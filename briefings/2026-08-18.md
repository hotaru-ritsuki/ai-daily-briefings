## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

This week's community motion is **skills as portable knowledge artifacts** — not just tool-wrappers but packaged domain expertise:

- **`book-to-skill`** ([virgiliojr94/book-to-skill](https://github.com/virgiliojr94/book-to-skill)) converts a technical-book PDF into a progressive-disclosure `SKILL.md` (keeping the body <500 lines and splitting overflow into referenced files, per Anthropic's own skill guidance). For me this is the shortest path to give an agent a *grounded* reference for RxJS operator semantics or Kafka delivery guarantees instead of hoping the base model remembers them.
- **`n8n-skills` + `n8n-mcp`** ([czlonkowski/n8n-skills](https://github.com/czlonkowski/n8n-skills), [czlonkowski/n8n-mcp](https://github.com/czlonkowski/n8n-mcp), ~22.7k★) are a paired take: a curated SKILL set that teaches Claude Code to author correct n8n workflows, plus an MCP server that lets CC/Cursor/Windsurf build those workflows live. Even off my primary stack, the *structure* — skill for know-how, MCP for the live surface — is the pattern to copy for a bespoke internal-tooling MCP.
- **Skill hygiene is now the differentiator**, not skill count: the mega-catalogs (3,000+ plugins) are breadth plays; the signal is small, audited libraries that follow the <500-line/progressive-disclosure rule. For a compliance-sensitive repo, a knowledge skill I can diff in a PR beats a firehose marketplace.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Zed's Anant Goel on evals, agent context, and the limits of git](https://workos.com/blog/zed-anant-goel-evals-agent-context-aie-2026)** (WorkOS) — First-hand from Zed: they re-run evals on *every* model release to keep behavior stable as models churn, and argue git is the wrong substrate for agent context. *~10 min. The strongest practitioner account this week on treating model swaps as a regression surface — directly relevant to unattended migration runs.*
- **[AI Coding Agent Evals on Real Repos (2026)](https://explainx.ai/blog/ai-coding-agent-evals-real-repos-2026)** — Argues you must compare agents *under the workflow you'll deploy* ("budget travels with the score"): retries, effort, and time budget change the ranking more than the base model does. *~8 min. A useful corrective before I trust any leaderboard for my migration agent.*
- **[Claude Code subagents: the 2026 production playbook](https://www.totalum.app/blog/claude-code-subagents-totalum)** — Feature subagents do the work, reviewer subagents catch issues, and every subagent gets an *explicit* model line so it doesn't silently inherit the parent's. *~9 min. Concrete on the feature/reviewer split I want for the Angular migration; medium-signal source but the model-line detail is real.*
- **[Beyond One-Shot Prompts: 5 Claude Code Workflow Patterns](https://www.mindstudio.ai/blog/claude-code-agentic-workflow-patterns)** — Sequential single-agent, parallel-via-worktrees, orchestrator/subagent, and event-triggered — with a decision rule for which fits independent vs. internally-parallelisable vs. event-driven work. *~7 min. A clean taxonomy to classify my own CC + IntelliJ ACP loops.*

### 6b. General AI engineering reading

- **[After Automation](https://every.to/context-window/after-after-automation)** (Dan Shipper, Every) — The 8,000-word case that automation *raises* demand for human work: cheap competence floods every field with "close but not quite right" output, and the value migrates to humans who supply framing, judgment, and review — "every agent needs a human." *~25 min. Published in May but resurfacing via Every's Agent-Mode kit (§5); the sharpest articulation of why my role shifts to framer/reviewer, not typist.*
