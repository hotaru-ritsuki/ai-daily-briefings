## 4. 🛠️ Claude Code & MCP ecosystem

- **MCP spec 2026 hit release candidate; final lands Jul 28** ([AAIF](https://aaif.io/blog/mcp-is-growing-up/), [WorkOS](https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)). Headline changes: a **stateless core**, **first-class extensions**, tightened **authorization**, **formal deprecation rules**, and **full JSON Schema for tool definitions**. The JSON-Schema and deprecation-rules parts are the practical ones — they're what let hosts validate tool args and version servers without silent breakage. If you maintain internal MCP servers, this is the spec to read before Jul 28, not after.
- **`ast-grep/ast-grep-mcp`** ([repo](https://github.com/ast-grep/ast-grep-mcp)) — an MCP server exposing tree-sitter AST queries + ast-grep rule authoring to the agent, with an Angular/TypeScript rule catalog. Lets Claude Code write and run structural codemods (e.g. AngularJS→Angular lifecycle/decorator rewrites) instead of regex-guessing across files. Distinct from the `codemod` CLI covered earlier — this is the in-agent AST layer.
- **`jeremylongshore/claude-code-plugins-plus-skills`** ([repo](https://github.com/jeremylongshore/claude-code-plugins-plus-skills)) — a plugin/skill marketplace shipping a **`ccpi` CLI package manager** for installing Claude Code plugins from the terminal. The package-manager framing (vs. copy-paste configs) is the interesting bit; worth a look even if you don't adopt the catalog wholesale. Quality is uneven — treat it as a source to cherry-pick, not install blindly.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns
- **[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)** — Anthropic Engineering. The "just-in-time" context argument: fetch context at tool-call time instead of front-loading it, and treat the context window as a budget to curate, not fill. The most useful primary-source framing of why long-running agents degrade. *~12 min.*
- **[Context Engineering: A Practical Guide](https://sourcegraph.com/blog/context-engineering)** — Sourcegraph. Code-retrieval-specific: how to scope what an agent sees in a large repo so it doesn't drown. Directly relevant to running agents over a big migration codebase. *~10 min.*
- **[The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)** — Armin Ronacher *(re-surfaced; the skeptic's counterweight)*. Separates the model's tool-result cycle from the external harness that restarts/redirects it, and names "comprehension debt" — code that's easier for machines to change than for humans to understand. Read alongside the loop-engineering hype, not instead of it. *~9 min.*
- **[Agent Design Is Still Hard](https://lucumr.pocoo.org/2025/11/21/agents-are-hard/)** — Ronacher. Older but the reference text on why execution control (path safety, allowlists, timeouts) must live in your harness, not the model. Worth a re-read given the new "writes" approval mode in Codex. *~11 min.*

## 8. 🎯 One thing to try today (≤30 min)

**Wire `ast-grep-mcp` into Claude Code and have it write one migration codemod.** This is the highest-leverage thing for my AngularJS→Angular work — it moves the agent from regex-guessing to structural AST rewrites.

```bash
claude mcp add ast-grep -- npx -y @ast-grep/mcp
# then, in Claude Code:
# "Using the ast-grep MCP, find all AngularJS .controller() registrations
#  in src/ and draft an ast-grep rule that flags each for Angular component migration."
```

Verify it can enumerate matches structurally before you trust it on a rewrite. If the timeout fix from v2.1.206 landed cleanly, the AST scan over a large `src/` should no longer die at 60s. ([repo](https://github.com/ast-grep/ast-grep-mcp))
