## 1. 🔥 Top 3 things I shouldn't miss today

- **⚡ [Claude Code 2.1.326](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) (Nov 16) is a large hardening release.** It tightens the Bash and Code Mode permission checks and the sandbox, warns at startup when an `--allowedTools`/`--disallowedTools` entry isn't a complete rule, and shows hook failures in red with the reason. It also fixes MCP tools whose schema has a root `anyOf`/`oneOf`, which previously showed Claude only the first branch.   - Claude Code runs in containers on the firm's own infrastructure, kept away from employee credentials.
  - Each new model has to pass the firm's own approval before use.
  - A pipeline gate gives a hard pass or halt, so Claude can't approve its own work.
  - The post gives no headcount or productivity numbers.
- **The [Claude Code Projects](https://alphasignal.ai/news/anthropic-upgrades-claude-code-projects-to-run-parallel-ai-workers-hands-free) coordinator now posts thread status on its own initiative**, and the update adds reminders, read-only thread links and `/btw` and `/fork` (reported Nov 13–14). ## 3. 📋 AI coding tool changelogs (since the 2026-11-16 briefing)

**Claude Code 2.1.326** (Nov 16, on both the [docs changelog](https://code.claude.com/docs/en/changelog) and [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md); ~370 entries, so only what matters is listed here):

- ⭐ 🔧 **Permissions and sandbox:**
  - Some Bash commands now ask first, or are refused where nobody can answer the prompt.
  - Code Mode checks are tighter, and sandboxed commands can write to fewer folders.
  - Delete/overwrite commands such as `find -delete` and `cat a > b` are no longer summarized in the transcript as "read" or "search".
  - **Why:** fewer surprises in auto mode. Expect a few more prompts in your existing flows.
- ⭐ 🆕 **Startup warning for incomplete `--allowedTools`/`--disallowedTools`/`--tools` rules.**
  - **Why:** headless runs with a typo'd rule used to fail silently.
- ⭐ 🐛 **MCP fixes:**
  - Root `anyOf`/`oneOf` schemas now show Claude every branch.
  - `/mcp` shows why a stdio server failed to start.
  - `claude mcp add-json` errors now say what to fix.
  - A failed `headersHelper` no longer stops that server loading in other sessions.
  - **Why:** these are the problems that make a custom MCP server look flaky.
- ⭐ 🔧 **Hooks:**
  - Failures are shown in red, blocks in yellow, each with the reason.
  - A crashed Node or Python hook now shows its full stack trace (Ctrl+O for up to 10k characters).
  - A PreToolUse hook that exits 127 now gets a warning that its check may not have run.
  - `updatedInput` is kept in more cases when several hooks answer the same call.
  - **Why:** debugging a guard hook no longer means guessing.
- 🆕 **Code Mode now works with agent teams turned on.** Subagents preloading a skill with an inline `!` command no longer fail in Code Mode.
- 🆕 **New visibility aids:** a `/status` row saying when an env var such as `DISABLE_TELEMETRY` turns features off, Ctrl+O for hidden startup notices, a warning when a `/permissions` rule couldn't actually be saved, and `OTEL_RESOURCE_INCLUDE_HOST`.
- 🐛 **Fixes:**
  - `/rewind` now says "Code changes unknown" instead of "No code changes" after shell edits it can't restore.
  - Resumed sessions no longer lose history after a crash.
  - Subagent status rows now say what an agent is waiting on.
  - Remote Control replies now stream to your phone.
  - In VS Code, a `claudeCode.promptSuggestions` setting turns prompt suggestions off.

**OpenAI Codex:** no new stable release; [0.169.0](https://github.com/openai/codex/releases) (Nov 13) is still the latest. Since yesterday there are five more pre-releases without notes: 0.171.0-alpha.8 to alpha.11 and an odd 0.170.0-alpha.4.1. Nothing to act on.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[VirusTotal MCP plugin](https://github.com/VirusTotal/virustotal-mcp)** (Apache-2.0, v0.9.9):
  - Looks up file, URL, domain and IP reports and submits samples. Sign-in is OAuth through `/mcp`, with no API key to paste.
  - Install: `claude plugin marketplace add VirusTotal/virustotal-mcp && claude plugin install virustotal@virustotal`. It needs Claude Code 2.1.283 or later, and the plugin has no hooks.
  - A clean example of a vendor shipping MCP and a skill as a single plugin. It's also handy for checking a suspicious dependency tarball before an agent installs it.
- **A three-stage review pipeline as plain prompts** ([vaibhav-space/my-ai-coding-workflow](https://github.com/vaibhav-space/my-ai-coding-workflow), 227 ★):
  1. **Plan:** map the work to acceptance criteria, then stop for approval.
  2. **Critical review:** an adversarial review in a fresh context or subagent, with a "YAGNI brake" that separates real failure modes from hypothetical ones.
  3. **Production-readiness audit:** check `git diff`, `git diff --cached` and untracked files against the approved plan.
  - The author is candid that these gates are only instructions. Real enforcement still needs permissions or hooks, which is exactly where 2.1.326's hook visibility helps.
- **Hook-based repo attacks are still the main threat model.** Write-ups keep landing on the same issue: a cloned repo's `.claude/settings.json` declares a `SessionStart` hook (see [Check Point](https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files/) and [Pillar's ChainDrop](https://www.pillar.security/blog/chaindrop-when-opening-a-repository-becomes-execution)). An [Adversa roundup](https://adversa.ai/blog/top-ai-coding-agent-security-resources-november-2026/) adds a report that a child session started inside a malicious repo ran such a hook without the parent's confirmation, and that Anthropic closed it as "Informative". I couldn't open the roundup, so treat that report as unverified.

## 8. 🎯 One thing to try today (≤30 min)

**Turn the plan → critical review → diff audit pipeline into three project slash commands, and make the audit run in a fresh-context subagent.**

```bash
claude update && claude --version   # expect 2.1.326; watch startup for new --allowedTools warnings
git clone --depth 1 https://github.com/vaibhav-space/my-ai-coding-workflow /tmp/mycw
mkdir -p .claude/commands && cp /tmp/mycw/prompts/{planning,critical-plan-review,production-readiness-review}.md .claude/commands/
```

1. **Adapt the commands (~10 min):**
   - Add `allowed-tools: Read, Grep, Glob, Bash(git diff:*), Bash(git status:*)` to the frontmatter of `production-readiness-review.md`, so the audit can read but not edit.
   - In `critical-plan-review.md`, add: "Run this as a subagent with no prior conversation context."
2. **Run it on today's real Angular or Spring ticket:** `/planning` → approve → `/critical-plan-review` → implement → `/production-readiness-review`.
3. **Score it:** note which issues the audit caught that you'd have missed. If it catches nothing in three tickets, delete it; a gate that never fires only costs context.
