## 4. 🛠️ Claude Code & MCP ecosystem (deep dive)

- **`Workflow` is the community's new orchestration substrate.** The pattern: a small JS program spawns subagents, routes outputs, runs `parallel()`/`pipeline()`, and branches with ordinary loops — *deterministic control flow, model-powered leaves*. alexop's ["I rebuilt Cloudflare's AI code review in a 250-line workflow"](https://alexop.dev/posts/ultracode-review-workflow-cloudflare/) is the most copyable artifact: dimensions → find → adversarially verify each finding before it comments. This is the disciplined alternative to letting an orchestrator improvise subagent calls turn-by-turn (§6a).
- **[Skill_Seekers](https://github.com/yusufkaraaslan/Skill_Seekers) (~14.7k★, updated Aug 6)** converts docs sites, GitHub repos, and PDFs into Claude Skills with **automatic conflict detection** — it diffs documented APIs against actual code and flags mismatches, then merges rule-based or AI-resolved. *Why it matters:* I could generate `angular-18`, `primeng`, and `spring-boot` skills straight from official docs instead of hand-writing them, with the conflict-check catching stale doc/code drift (§5, §8).
- **AWS CloudWatch "Coding Agent Insights"** (GA'd late July) ingests OpenTelemetry from Claude Code / Codex / Copilot — token spend, per-turn latency, tool calls, approvals — segmented by team/cost-center, queryable via PromQL ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/07/cloudwatch-coding-agent-insights/), [AWS blog](https://aws.amazon.com/blogs/mt/analyzing-claude-code-usage-with-cloudwatch-and-opentelemetry/)). *Why it matters:* if we already ship to CloudWatch, this is agent cost/latency observability with no extra instrumentation — the enterprise complement to v2.1.225's spend-limit warning.

## 8. 🎯 One thing to try today (≤30 min)

**Generate a stack skill from real docs with Skill_Seekers and conflict-check it.** Fastest way to see whether auto-generated skills beat my hand-written ones:

```bash
pipx install skill-seekers   # or: pip install skill-seekers
skill-seekers scrape https://primeng.org/ --name primeng --detect-conflicts
cp -r ./out/primeng ~/.claude/skills/primeng
```

Then in Claude Code on a real screen: `use the primeng skill to migrate src/app/dashboard's p-table usage to the current API`. If the conflict-detection flags stale doc/code drift on even one component, it earns a slot in the migration toolchain; if it only produces a doc dump, you've spent 20 minutes learning that hand-written skills still win here.
