## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

**The live thread this cycle is durable execution, crystallized by Pi.** [Pi 1.0](https://github.com/earendil-works/pi) (~114k★, "AI agent toolkit: unified LLM API, agent loop, TUI, coding agent CLI") ships `@earendil-works/pi-durable` — a "durable conversation, task, and document runtime." The mechanism is plain: **every agent step is a checkpoint**, so process death, machine sleep or container restart resumes at the last completed step, and the harness can fork a conversation at any point to run variants in parallel (~15k LOC, runs on Bun and Cloudflare Durable Objects). Mario Zechner's framing — summarized in [implicator.ai's "harness rebellion" piece](https://www.implicator.ai/pi-is-not-a-claude-code-rival-it-is-a-harness-rebellion/) — is that Pi's strength is what it *doesn't* build: a minimal loop you can reason about, with durability as a first-class primitive rather than a bolt-on. (Secondary reports also say Pi made MCP first-party on Sep 29 — unverified against a primary source.)

**Why this sits next to CC's official news:** CC 2.1.296's `autoCompactWindow` and the 2.1.290 fix for *scheduled tasks losing persistence after compaction* patch the same problem Pi Durable designs around. Pi isn't a CC replacement — but the *pattern* is liftable: treat long scheduled/cloud runs (like this briefing job) as checkpointed workflows where each tool call is a durable step, so a mid-run crash costs one step, not the whole run.

**MCP:** no brand-new high-signal dev-tooling server in the window (`mcp-server-git` cut a maintenance release Oct 11); the [PulseMCP directory](https://www.pulsemcp.com/servers) now lists ~21.7k servers — directional, not a release.

### 6a. AI workflows & patterns

- **[The durable execution stack for agents](https://greenabstracts.substack.com/p/the-durable-execution-stack-for-agents)** — maps the pattern and names the sharp gotcha: **an LLM call made *outside* a recorded step gets re-billed when the workflow resumes** — durability is only as good as your step boundaries. **Takeaway:** before wrapping an agent in any durability layer, wrap the *model calls* as steps, or resume just doubles your token bill. ~10 min.
- **[Durable execution for AI agents: LangGraph, DBOS, Inngest and Temporal compared](https://hackernoon.com/durable-execution-for-ai-agents-langgraph-dbos-inngest-and-temporal-compared)** — practical head-to-head: DBOS = Postgres-library, Temporal = replay engine (no clocks/RNG/direct HTTP in workflow code), Inngest/Restate in between. **Takeaway:** pick by how much infra you want to run, not by feature lists — all of them resume from the last completed step. ~12 min.
- **[Building Pi, and what makes self-modifying software so fascinating](https://newsletter.pragmaticengineer.com/p/building-pi-and-what-makes-self-modifying)** (Gergely Orosz) — first-hand on Pi's design and why a small, inspectable harness beats a feature-maximal one. **Takeaway:** the companion read to §4 — harness minimalism as a reliability strategy. ~15 min. *(snippet-sourced — host unreachable)*
- **[Pi is not a Claude Code rival, it is a harness rebellion](https://www.implicator.ai/pi-is-not-a-claude-code-rival-it-is-a-harness-rebellion/)** — opinionated but useful: Pi's bet is that *the loop you can read* plus durability beats a thick harness. **Takeaway:** a clean articulation of the "Agent = Model + Harness" argument applied to a real shipping tool. ~8 min.

## 8. 🎯 One thing to try today (≤30 min)

**Prove durable execution to yourself with Pi.** Install the Pi coding agent from [pi.dev](https://pi.dev), start a long-running task (a multi-file refactor, or a scripted multi-step job), then **`kill -9` the process mid-run** and restart it:

```bash
# from pi.dev quickstart — then, mid-task, in another shell:
pkill -9 -f pi   # or just close the laptop lid
# restart Pi on the same conversation and watch it resume at the last checkpoint
```

If it picks up at the last completed step instead of restarting, you've seen the primitive your scheduled/cloud CC runs are missing — and you'll know whether the pattern is worth porting (wrap each tool/LLM call as a durable step).

**Bonus (5 min, time-boxed):** if you have *any* eval history in OpenAI's hosted Evals, export it before the **Oct 31 read-only** cutoff using OpenAI's own [Promptfoo migration cookbook](https://developers.openai.com/cookbook/examples/evaluation/moving-from-openai-evals-to-promptfoo) — don't wait for Nov 30.
