## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

Two threads matured in parallel this cycle: **skills-as-methodology** and **tool-output sandboxing via MCP**.

**Skills frameworks graduated from libraries to opinionated processes.** [obra/superpowers](https://github.com/obra/superpowers) (MIT, ~295k★ per repo page — extraordinary, verify live) is the clearest example: where `addyosmani/agent-skills` and `mattpocock/skills` are *collections* you cherry-pick, Superpowers ships a *workflow that refuses to let the agent skip steps* — brainstorming, `writing-plans`, `subagent-driven-development`, `executing-plans`, `test-driven-development`, `systematic-debugging`, plus a `writing-skills` meta-skill — bootstrapped by a `SessionStart` hook so it's always on. It's worth reading *next to* CC 2.1.296's `autoCompactWindow`/`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`: a `subagent-driven-development` skill is only as cheap as your ability to pin the fan-out to Haiku and self-compact noisy workers. Adjacent and lighter: [forrestchang/andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills) — a single `CLAUDE.md` distilling Karpathy's "LLMs make wrong assumptions, overcomplicate, and edit what they don't understand" into four rules (think-before-coding, simplicity-first, surgical-changes, goal-driven). That's a 5-minute drop-in for any repo, stack-agnostic.

**Context/tool-output sandboxing is the other live wire.** [mksglu/context-mode](https://github.com/mksglu/context-mode) (ELv2, TS, ~26k★, 17 platforms) is an MCP server with 11 tools: `ctx_execute` runs code in a subprocess and surfaces only stdout; `ctx_index`/`ctx_search` push raw payloads into SQLite FTS5 (BM25) so the agent retrieves snippets instead of dumping logs; and it restores session state *across compaction* via tracked events. This is the same "stop flooding the orchestrator" goal as last week's `headroom` and `jevgrep`, but implemented as a routing MCP server enforced by hooks — the cleanest fit yet for your fan-out.

**Multi-agent orchestration, grounded.** [mvschwarz/openrig](https://github.com/mvschwarz/openrig) (Apache-2.0, TS, ~6.8k★) runs **Claude Code + Codex + Pi as one persistent team** — define roles in YAML, `rig up`, talk to a lead agent that coordinates specialists; built on tmux + SQLite + an MCP server, with snapshot/restore and "rig bundles." Note its own README warning: setup writes provider config, trust settings and executable hooks to your machine — back up first. Useful as a concrete reference even if you don't adopt it.

### 6a. AI workflows & patterns

- **[Harness Engineering for Coding Agent Users](https://martinfowler.com/articles/exploring-gen-ai/)** (Birgitta Böckeler / Thoughtworks, ~Apr 2026) — the canonical statement of **Agent = Model + Harness**: the harness (tools, hooks, prompts, context policy) is where reliability is won, and it's an engineering surface you own. **Takeaway:** stop tuning prompts in isolation; treat your whole `.claude/` as one testable system. ~12 min. *(snippet-sourced)*
- **[The State of AI Harness Engineering 2026](https://marmelab.com/blog/2026/09/24/the-state-of-ai-harness-engineering-2026.html)** (Marmelab, Sep 2026) — a survey of ~246 open-source harness repos + ~57 papers; the cited headline findings are that **~60% of harnesses ship with no tests or evals** and that **chains of >4 agent-to-agent handoffs almost always fail**. **Takeaway:** the honest counterweight to openrig-style fan-out — keep handoff depth shallow and *put evals on the harness itself*. ~10 min. *(figures unverified — snippet-sourced)*
- **[How Evals Are Central to Harness Engineering](https://hugobowne.substack.com/p/how-evals-are-central-to-harness)** (Antaripa Saha, via Hugo Bowne-Anderson, Sep 2026) — first-hand from production-eval work at Quotient AI: you can't improve a harness you can't measure, so evals are the primary artifact, not an afterthought. **Takeaway:** build an eval set for your own CC workflow before adding the next skill or subagent. ~9 min.
- **Geoffrey Huntley's "Ralph" / back-pressure loop** (summarized in [ml4trading's coding-agent reading list](https://insights.ml4trading.io/p/a-coding-agent-reading-list-behind)) — run the agent in a loop until an *oracle that cannot lie* (test, linter, type checker) passes; the deterministic gate is the control system. **Takeaway:** your Playwright/typecheck suite is the back-pressure — wire it as the loop's exit condition, not a post-hoc check. ~8 min.

### 6b. General AI engineering reading

- **[The Devil Is in the Interface: Evaluating How Tool Architecture Shapes Coding Agent Behavior](https://arxiv.org/pdf/2608.11386)** (arXiv) — empirical study showing the *shape* of a tool's interface (granularity, output format, error surfaces) measurably changes agent behavior, independent of the model. **Takeaway:** the strongest argument for why context-mode/MCP design (§4) is real leverage, not plumbing. ~15 min.
