## 4. 🛠️ Claude Code & MCP ecosystem (community deep-dive)

The interesting movement this week is on the **community/packaging** side, not official releases.

- **Skills as a cross-agent format.** [NVIDIA/skills](https://github.com/NVIDIA/skills) ships Agent Skills for NVIDIA products designed to "install into Claude Code, Codex, and other coding agents." Combined with the awesome-list proliferation below, the direction is clear: a Skill (an `SKILL.md` + scripts + one-level-deep references) is turning into a portable unit you author once and run across harnesses. Practical upside for you — the `.claude/` work you already do becomes less CC-locked.
- **The skill-design rules worth internalizing.** Current Anthropic skill guidance (summarized widely this week) converges on: skill bodies ≈≤500 lines; each skill fits cleanly into **one** of ~nine functional categories rather than straddling several; push anything deterministic into scripts so the model follows a procedure instead of improvising; keep reference files **one level deep** from `SKILL.md` (nested chains get only partially read); and re-test each skill per model, because the same skill behaves differently across models and newer reasoning models often get *worse* when over-prescribed. The anti-pattern: a skill that restates what Claude already does by default — it only adds context, not value.
- **Large real-world subagent fan-out.** [claude-seo](https://github.com/AgricIDaniel/claude-seo) runs 26 sub-skills + 19 specialist subagents in parallel for a single domain. Even if SEO isn't your world, it's a concrete, readable example of orchestrator→many-specialist fan-out with per-subagent context/tool budgets — worth skimming before you design your next multi-subagent flow.
- **Curated toolkits as menus.** [awesome-claude-code-toolkit](https://github.com/rohitg00/awesome-claude-code-toolkit) catalogs agents, skills, commands, plugins, hooks, and MCP configs in one place — a parts bin for your own `.claude/`, not something to install wholesale.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[The importance of Agent Harness in 2026](https://www.philschmid.de/agent-harness-2026)** (Philipp Schmid) — argues agent reliability now depends as much on the surrounding harness (tool interfaces, state, failure recovery, permissions, verification) as on the model. The clearest practitioner statement of the "harness > model" thesis. ~8 min.
- **[Spec-Driven Development: What Our Agents Ignored](https://heym.run/blog/spec-driven-development)** — a first-hand postmortem of which parts of written specs coding agents actually honored vs. silently skipped. Useful corrective to the "just write a good spec" narrative. ~7 min.
- **[Prompt, Context, Harness, Loop: The Four Layers of AI Agent Engineering](https://futureagi.com/blog/loop-engineering/prompt-context-harness-loop-layers/)** — a tidy mental model separating the four layers you can tune independently; handy vocabulary when debugging *where* an agent flow is failing. ~6 min.
- **[Claude Code Subagents: How They Work (2026)](https://www.mintmcp.com/blog/claude-code-subagents)** — mechanics of subagent context isolation: separate context window, own system prompt/tools/permissions/skills/MCP, result-only handback to the orchestrator. Good refresher before you scope a subagent's tool budget. ~6 min.

### 6b. General AI engineering reading

- **[Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems](https://arxiv.org/html/2604.14228v1)** — a research paper mapping CC's architecture against the broader design space of agent systems. Drier than a blog, but a rare systematic look at *why* the orchestrator-worker + reactive-loop shape won. ~20 min skim.

## 8. 🎯 One thing to try today (≤30 min)

**Test the "skills are portable across harnesses" thesis for yourself.** Clone a vendor skill pack and run the *same* Skill under both Claude Code and Codex:

```bash
git clone https://github.com/NVIDIA/skills && cd skills
# read one SKILL.md to see the structure (body + scripts + one-level-deep refs),
# then install it into Claude Code and invoke it, and separately into Codex.
```

Then apply the lesson to your own repo: take one ad-hoc prompt you keep re-pasting (e.g. your Handlebars-PDF scaffolding or a Spring-test generator), convert it into a single-category `SKILL.md` ≤500 lines with the deterministic bits in a script, and confirm progressive-disclosure triggers it. You end the session with one reusable, cross-tool skill instead of a copy-pasted prompt.
