## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

The ecosystem story this week isn't a feature — it's that **the discovery layer everyone's been celebrating (registries, marketplaces, `ccpi`-style package managers from 07-25/07-26) is now an attack surface**, and the response is a maturing class of MCP/skill security scanners.

- **How the bait works.** An agent asked to "find an MCP server for X" searches GitHub/registries, ranks a malicious repo on a plausible README + star-padded profile, and surfaces its `npx`/`pip` install line as legitimate documentation. The human approves what looks like the agent's own recommendation. Path-traversal and injection risk in *legitimate* servers compounds it: an audit of 100 MCP packages gave **71% an F grade, zero an A**, and a 2,614-server survey found 82% with path-traversal-vulnerable file ops ([appsecsanta](https://appsecsanta.com/research/mcp-server-security-audit-2026)). So even non-malicious servers are shaky.
- **The scanner options, concretely.** [`snyk/agent-scan`](https://github.com/snyk/agent-scan) covers 15+ risks across MCP servers *and* skills (prompt injection, tool poisoning, tool shadowing, toxic flows); [`eSentire-Labs/mcp-scanner`](https://github.com/eSentire-Labs/mcp-scanner) scans tools/prompts/resources with an LLM-judge layer; [`apisec-inc/mcp-audit`](https://github.com/apisec-inc/mcp-audit) maps what your agents can *access* and generates an **AI-BOM** for compliance; Invariant's `mcp-scan` and MCPSafe's 5-LLM-jury add cross-model consensus. *Caveat that matters:* YARA/keyword scanners can't tell adversarial prompt injection from normal MCP instructions — prefer the semantic + LLM-judge tools, and none of them replace SHA-pinning and reading the code.
- **Governance layer for a regulated team.** [`microsoft/agent-governance-toolkit`](https://github.com/microsoft/agent-governance-toolkit) (~4.9k★) puts deterministic, application-layer policy + tamper-evident audit + sandboxing *around* whatever servers survive the scan — the internal-control answer to the US "SR 26-2 leaves agentic AI out of scope" governance vacuum the trio flagged (07-25 §7).

## 8. 🎯 One thing to try today (≤30 min)

**Scan every MCP server and skill already in your `.claude/` config — before adding one more.** Given §1, treat this as a routine security gate, not a one-off.

1. List what you've got: `claude mcp list` (v2.1.219+ now shows HTTP status/errors) and inspect `.claude/` for installed skills/plugins.
2. Run a scanner over them — e.g. clone and point [`snyk/agent-scan`](https://github.com/snyk/agent-scan) or [`eSentire-Labs/mcp-scanner`](https://github.com/eSentire-Labs/mcp-scanner) at each server config:
   ```bash
   git clone https://github.com/eSentire-Labs/mcp-scanner && cd mcp-scanner
   # follow the README to scan a server URL / config entry
   ```
3. Triage: any flagged tool-poisoning or injection in a server you *didn't* write is a stop-ship. SHA-pin the ones that pass, and drop unpinned third-party skills you can't read.
4. If it's useful, wrap it as a `pre-install` check or CI step so the team can't add an unscanned server.

First command: `claude mcp list`. Payoff: you turn §1 from a headline into a repeatable control — and generate the start of an AI-BOM (§5.3) for the compliance conversation.
