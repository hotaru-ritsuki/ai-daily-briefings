## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

**The standout is [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)** — and it's the clearest "skills as a portable lifecycle" library to appear yet. It organizes 24 lifecycle skills + 1 meta-skill into phases that mirror how you'd actually run a change: **Define** (`interview-me`, `idea-refine`, `spec-driven-development`, `constraint-driven-development`) → **Plan** (`planning-and-task-breakdown`) → **Build** (`incremental-implementation`, `test-driven-development`, `context-engineering`, `source-driven-development`, `frontend-ui-engineering`, `api-and-interface-design`) → **Verify** (`browser-testing-with-devtools`, `debugging-and-error-recovery`) → **Review** (`code-review-and-quality`, `code-simplification`, `security-and-hardening`, `performance-optimization`) → **Ship** (`git-workflow-and-versioning`, `ci-cd-and-automation`, `deprecation-and-migration`, `documentation-and-adrs`, `observability-and-instrumentation`). It's pure Markdown, multi-harness (CC/Cursor/Codex/Gemini/Copilot), and pairs a `SKILL.md` with reference checklists and agent personas. Next to last week's `mattpocock/skills` (TS-focused) and Anthropic's `knowledge-work-plugins` (role-based), this one is organized by **software-lifecycle phase** — the most directly liftable into your front-end `.claude/` setup. The `browser-testing-with-devtools` and `frontend-ui-engineering` skills are the ones to diff first given your Playwright/Angular work.

**Where it plugs into official news:** CC 2.1.296's `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` + `autoCompactWindow` are the runtime knobs this kind of multi-skill, multi-subagent library actually needs — a `context-engineering` skill is only as good as your ability to keep the fan-out cheap and self-compacting. Worth wiring the two together rather than reading them as separate news.

The most-cited recent server remains **Chrome DevTools MCP**, whose Oct-2026 update ([Chrome blog](https://developer.chrome.com/blog/new-in-devtools-october-2026)) adds heap-snapshot querying, PWA automation, lazy source-map loading and optional console stack traces — relevant if you let an agent drive DevTools alongside Playwright. ### 6a. AI workflows & patterns

- **[Context Engineering Lessons from Building the Azure SRE Agent](https://techcommunity.microsoft.com/blog/appsonazureblog/context-engineering-lessons-from-building-azure-sre-agent/4481200)** (Microsoft eng) — first-hand production report: they went from **100+ tools and 50+ specialized agents down to a much smaller set and the agent got *more* reliable**. **Takeaway:** the honest counterweight to "add another subagent" — tool/agent sprawl is a reliability tax, not a capability. ~10 min.
- **[Context management in agent harnesses: memory, files, and subagents](https://arize.com/blog/context-management-in-agent-harnesses/)** (Arize) — frames the three places a harness can put state (working set, files, subagent responses as an isolated layer) and when each wins. **Takeaway:** a clean mental model for *where* context should live before you reach for memory tooling. ~9 min. (Recent, exact date uncertain.)
- **[Context Engineering for AI Agents in Production: Architecture, Failure Modes, and Metrics](https://galileo.ai/blog/context-engineering-for-agents)** (Galileo) — names the concrete failure modes (poisoning, distraction, clash) and the metrics to watch; notes context isolation often improves performance *despite* higher total token spend. **Takeaway:** the economics line is the same one your fan-out lives on — pay more tokens to buy a cleaner orchestrator. ~8 min.
- **[Everyone is Building AI Subagents — But Most Devs Still Don't Understand Context Engineering](https://dev.to/dhruvjoshi9/everyone-is-building-ai-subagents-but-most-devs-still-dont-understand-context-engineering-3ldj)** (DEV) — practitioner rules of thumb: one narrow responsibility per subagent, summarize long history before handoff. **Takeaway:** a short checklist to sanity-check your subagent definitions against. ~6 min.

### 6b. General AI engineering reading

- **Cognition's "don't build multi-agent systems" stance** (summarized in [Vellum's context-engineering piece](https://www.vellum.ai/blog/context-is-king-why-context-engineering-is-the-new-frontier-for-ai-agents)) — the Devin team argues a single agent with careful context control beats multi-agent designs that "burn tokens at an alarming rate." **Takeaway:** read it directly against §6a's isolation argument — the real decision is *read-only parallel work* (fan-out wins) vs. *shared-state building* (single agent wins). ~7 min.

## 8. 🎯 One thing to try today (≤30 min)

**Wire CC 2.1.296's new subagent knobs into one real fan-out task.** Point your workflow subagents at Haiku 5.5 and let a noisy worker self-compact, keeping the planner on Opus:

```bash
claude update
export CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=claude-haiku-5-5
```

Then add `autoCompactWindow` to one explore/grep subagent's frontmatter so it compacts before it floods the orchestrator:

```yaml
---
name: explore
description: Read-only repo exploration
autoCompactWindow: 0.5   # compact at ~50% of its window, ahead of the main session
---
```

Run a task that normally makes the fan-out thrash, and compare `/cost` against a baseline run (now that `/cost` prices Sonnet cache reads correctly, the number is trustworthy). If the cost drops without a quality hit, it's a permanent setting. Bonus 5 min: `git clone https://github.com/addyosmani/agent-skills` and drop its `context-engineering` and `test-driven-development` `SKILL.md` files into `.claude/skills/`.
