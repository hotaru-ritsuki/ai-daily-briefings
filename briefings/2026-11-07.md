## 3. 📋 AI coding tool changelogs (since 2026-11-06 briefing)
### Claude Code — [2.1.319](https://code.claude.com/docs/en/changelog) (Nov 6)
- 🆕 ⭐ **MCP tasks in the terminal:** when a server runs a tool call as an MCP task, Claude Code moves it to the background right away and reports the result to Claude when it finishes. This now works without feature flags too, so it covers Bedrock, Vertex and gateways. It matters for slow MCP tools, such as a DB migration or a full Playwright run: you can keep working while they run. To opt out, set `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`, or `CLAUDE_CODE_DISABLE_MCP_TASKS=1` to turn tasks off entirely.
- 🆕 ⭐ **`permissions.denyInsteadOfPrompting`:** any tool call that would wait on a permission prompt is denied instead, and the turn continues. This applies to terminal sessions, subagents and teammates. It's the missing piece for headless runs: the allowlist defines the boundary, and anything outside it fails instead of stalling.
- 🆕 ⭐ **"Earlier in this session" row in `/tasks`:** lets you reopen and message a finished subagent, even after a restart. Useful when a review subagent's findings need a follow-up question.
- 🆕 **`/claude-api latency-optimize`:** finds the slow spots in your Claude API code and tests faster settings against your eval. Also new: `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`.
- ⚠️ ⭐ **Self-paced `/loop` now ends** when a turn finishes without rescheduling. Set `CLAUDE_CODE_LOOP_KEEPALIVE=1` to get the old behaviour.
- ⚠️ **`claude -p` exits 1** (text and JSON output) when auto mode refused actions because no safety check was available. Previously it exited 0.
- ⚠️ **Auto mode with telemetry or feature flags off, or behind an LLM gateway:** calls the server can't check are now asked about or denied, with no fallback to the built-in classifier. `CLAUDE_CODE_AUTO_MODE_SERVER=0` restores the fallback.
- 🔧 **Stricter permissions:**
  - A session's exact ask rule loses to a broader deny rule.
  - `which` with unusual flags now prompts.
  - Plugin marketplaces from `--add-dir` directories register only after that directory's trust dialog is accepted.
  - With the sandbox on, nested `.claude/skills` folders load only from the folder you started in or `/cd` into.
- 🐛 ⭐ **Security fixes:** a sandbox escape during worktree creation, Bash deny/ask rules missing commands with quoted words, a crafted environment prefix hiding part of a command, and a `sed` command skipping the permission check in accept-edits and auto mode.
- 🐛 **Other fixes:** MCP servers on the older handshake failing to connect; slash commands typed after a leading space being sent as plain text; `/diff` breaking on a file named `HEAD`; `/context` re-sending its grid every turn; plugin updates not installing new dependencies.
- 🔧 **Smaller improvements:** `/model` groups older models under "More models", and `/context` shows each list's top 10 rows. About 90 fixes in total.

## 6. 📰 Articles & essays
### 6a. AI workflows & patterns
- **["The components of agent memory"](https://www.anthropic.com/research/components-of-agent-memory)** (Anthropic Engineering, Nov 6, ~15 min). It's evaluated on CL-Bench, Pokémon Red and a company document corpus. The key findings:
  - **Tell the model what memory is *for*, not which rules to follow.** "Record only failures" rules *hurt* stronger models.
  - **Store what the environment won't show again**, such as strategy and verified rules, not state the agent can re-read.
  - **Keep injected context to a short index** that points to deeper material.
  - **Give each entity its own page.** Concurrent writes to shared pages lost facts: 41 of 57 retained, versus 57 of 57 with per-entity pages.

  The article also states that Claude Code's auto memory loads only the first 200 lines or 25 KB of `MEMORY.md`.
- **["Context Engineering for AI Agents and Where Memory Lives"](https://aerospike.com/blog/context-engineering-ai-agents/)** (Aerospike, ~2 days old, ~10 min). It maps context components to where they're stored: local files and checkpoints for coding agents, and a durable store with expiry for customer-facing agents. **Caveat:** it's a vendor post and I've read only the search summary.

## 8. 🎯 One thing to try today (≤30 min)
**Make an unattended Playwright-test generation run fail fast instead of hanging, using 2.1.319's `denyInsteadOfPrompting`.**
1. Run `claude update && claude --version`. You need 2.1.319 or later.
2. In a scratch branch of your Angular repo, add the following to `.claude/settings.local.json`:
   ```json
   {"permissions":{"denyInsteadOfPrompting":true,
     "allow":["Read","Edit(e2e/**)","Bash(npx playwright test:*)"]}}
   ```
3. Run:
   ```
   claude -p "Write one Playwright spec in e2e/ for the <feature> happy path using existing page objects. Run it with npx playwright test <file>. Do not edit src/." --output-format json > run.json; echo "exit=$?"
   ```
4. Check `run.json` for denied calls. Every denial is a permission you either forgot to allow or deliberately want blocked, such as an `npm install` or an edit under `src/`. Tighten or widen the allowlist and run again.
5. Optional, 5 minutes: run `/context` in an interactive session and count the lines in your CLAUDE.md. If it's over about 200, move sections into `docs/agent/*.md` and leave pointers, per the memory post.

**Success criteria:** the run finishes in either case (exit 0 or a clean failure), never stalls at a prompt, and you have an allowlist you could drop into CI.
