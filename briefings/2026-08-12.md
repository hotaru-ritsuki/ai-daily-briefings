## 3. 📋 AI coding tool changelogs

**Claude Code — v2.1.227 (Aug 10) & v2.1.228 (Aug 11)** ([changelog](https://code.claude.com/docs/en/changelog)). v2.1.226 covered 08-08; these are the net-new diff:

- ⭐ 🔧 **Hardened claude.ai-synced skills (v2.1.228):** they no longer shadow local commands or MCP prompts, their descriptions are sanitized and labeled, and on your machine their bodies don't run `!` shell commands or expand `@` file references. *Why it matters:* as skills sync across claude.ai/Cursor/Codex, this is the harness closing an obvious supply-chain hole — directly relevant to trusting shared skills on a regulated repo.
- ⭐ ⚠️ **Write tool behavior change (v2.1.228):** newer models can now overwrite an existing file they haven't read this session (matching Edit's rules); older models still require the read first. *Why it matters:* my migration agents can clobber a file without a prior read — tighten hooks/permissions if that's not what I want unattended.
- 🐛 **Self-hosted runner robustness (v2.1.228):** a failed `checkout` hook on a repo the session doesn't push to now skips that repo with a warning instead of failing every session; sessions no longer end in the gap between a background task finishing and the follow-up turn.
- 🐛 **Data-safety fixes (v2.1.228):** session cleanup no longer deletes contents inside a project's memory folder; a settings-merge bug where a higher-precedence marketplace entry could inherit another tier's custom headers is fixed (entries now merge whole).
- 🔧 Cross-session messages now display sender + body inline (with your Remote Control session name as sender); Vertex AI now fails fast on expired/missing GCP creds instead of retrying for minutes; the deferred-tools reminder is no longer sent twice after a skill invocation.
- 🐛 **v2.1.227:** an expired login token no longer evaluates feature flags without your tier (which wrongly prompted Max users to enable Fable credits); `claude-code-action` Bash commands no longer fail under `allowed_non_write_users` on GitHub-hosted runners — relevant if I run CC in CI.

## 8. 🎯 One thing to try today (≤30 min)

**Scaffold Mastra and build a tiny LLM-as-judge eval for one migration diff.** It's the fastest way to test eval-driven dev in *your own* language instead of a Python notebook:

```bash
npm create mastra@latest my-eval-lab
# choose the Agents + Evals template, then in the project:
# add an eval that scores "does this migrated component preserve the AngularJS behavior?" over 3-5 real diffs
npm run dev   # opens the local playground to inspect scores/traces
```

If a 20-line LLM-as-judge over a handful of real migration diffs gives you a repeatable "did the behavior survive?" score, that's a CI gate you can wire into the migration — the objective verifier the loop-engineering thread keeps calling for. If it's noisy on your diffs, you've learned that cheaply before betting a pipeline on it.
