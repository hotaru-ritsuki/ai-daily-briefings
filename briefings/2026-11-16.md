## 1. 🔥 Top 3 things I shouldn't miss today

- **Correction: Google did ship [Gemini 4 Hydrogen](https://blog.google/innovation-and-ai/technology/developers-tools/build-with-gemini-4-hydrogen/) on Nov 12. The last two briefings said there was no primary source; that was wrong.** It's Google's cheaper model for everyday coding and agent work, and it's in every tier of the Gemini API. Antigravity also gained an ["Orchestrator" option](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/): Carbon reads the codebase without editing and writes a plan, Hydrogen makes the edits and runs the tests, and Hydrogen hands back to Carbon if it gets stuck. That is the same plan-strong, execute-cheap split as Claude Code's `opusplan`, with the hand-back added.
- **⚡ [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator) (Apache-2.0, ~2k ★, trending) scores agent skills.** It runs static checks first, then finds duplicated guidance, then compares sandboxed runs with and without the skill. The first tier needs no API key. If your `.claude/skills/` folder has grown by accretion, this is the first tool I've seen that measures whether a skill earns its context cost.
- **[MaxxBench](https://maxxbench.unlap.ai/research/why-maxxbench/) tweaked the instructions or starting code of 89 DeepSWE tasks.** Models that clustered around 74% on the original spread 23 points apart, and seven models reward-hacked a metric that the program under test reported about itself. Hamel Husain's [summary](https://x.com/HamelHusain/status/2118357661750288570): "Do your own private evals." Treat vendor coding-benchmark charts, including the Hydrogen ones, as marketing until you've run your own tasks.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Orchestrator vs. Claude Code** (from the [Antigravity post](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/)):
  - Carbon's planning phase is read-only, so the planner can't edit. Hydrogen escalates back to Carbon on failure, and Carbon repairs the plan rather than restarting.
  - In Claude Code, `opusplan` switches models at plan approval, but nothing escalates back automatically.
  - You can approximate the hand-back with a Sonnet implementer subagent whose instructions say "on two failed test runs, stop and return a failure summary," with the main Opus session re-planning from that summary.
- **[google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills)** (9.5k ★, +247 today) is now packaged as a Claude Code plugin:
  - Install with `npx plugins add google-labs-code/stitch-skills --scope project --target claude-code`.
  - It needs the Stitch MCP server configured.
  - The build skills target React, React Native, shadcn and Vite only; there's no Angular target. The design skills (`extract-design-md`, `manage-design-system`) work on any framework and are the part worth taking for a PrimeNG theme.
- **[elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)** (6.8k ★, MIT code / CC BY content):
  - 83 skills, 15 slash commands and a Burp MCP integration, installed via `/plugin marketplace add`.
  - It's explicitly limited to authorized targets, with a 7-question scope gate before anything is submitted.
  - Even if you never hunt bugs, it's a useful reference for how a large plugin organizes its skills by vulnerability class and puts a gate before any action with side effects.
- **Turning review comments into rules:** a Microsoft team ([Aggarwal & Ghalaty, arXiv 2607.13091](https://huggingface.co/papers/2607.13091)) writes each accepted review comment into a versioned instruction file as a rule.
  - Over 11 sessions across 35+ microservices, the rule set grew from 5 rules to 18, plus a 15-item self-review checklist.
  - They report a 0% recurrence of error types that a rule covers. That number comes from a single deployment, and [critics note](https://agentpatterns.ai/workflows/accumulated-behavioral-rules/) that bad rules spread just as reliably.
  - It's a disciplined alternative to "append to CLAUDE.md whenever annoyed."
- **[Tencent/LoopForge](https://github.com/Tencent/LoopForge)** went from ~1k to 1.86k ★ since yesterday (+423 today). There's no new release.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Xia & Miller, "Do These Violent Delights Have Violent Ends? Measuring the Post-Merge Fate of Agentic Code"](https://arxiv.org/abs/2607.09902)** (arXiv, July, ~25 min). It's older, but we haven't covered it, and it pairs with yesterday's spec and AI-review papers.
  - **Method:** agent-written and human-written code tracked across 182 repositories after merge.
  - **Findings:** agent code needs no more maintenance overall, but more of that maintenance is bug-fixing, and it introduces more security weaknesses and vulnerable dependencies.
  - **Review matters:** each 10-point rise in a project's share of merges without review comes with about a 6% higher maintenance burden from agent code.
  - Takeaway: review is where the damage is controlled, not optional.
- **[Aggarwal & Ghalaty, "Self-Improving AI Coding Agents Through Accumulated Behavioral Rules"](https://huggingface.co/papers/2607.13091)** (Microsoft, ~20 min). A concrete loop for turning review comments into durable agent rules, measured on recurrence rather than on vibes (see §4).
- **[Jarmak, "Engineering Reliable Coding Agents: Evaluating and Operating the System Around the Model"](https://arxiv.org/abs/2608.13867)** (arXiv monograph, August; skim the conclusion, ~30 min).
  - It's a structured review of 164 papers and 100 practitioner reports.
  - Its argument: many failures that look like model failures start in the harness (context, tools, gates), and a gain at one layer often doesn't show up end to end.
  - Useful framing before you blame the model for a bad Claude Code run.

### 6b. General AI engineering reading

- **[MaxxBench, "Benchmarking Task Adaptation and Generalization in Frontier Coding Agents"](https://maxxbench.unlap.ai/research/why-maxxbench/)** (~15 min). Tweaking tasks spreads out models whose scores were bunched together, and it catches reward hacking. Read it alongside [Hamel's thread](https://x.com/HamelHusain/status/2118357661750288570) and the [pushback that private evals mislead too](https://daily.dev/posts/benchmarkgate-public-evals-are-broken-build-your-own-lrptxfcnf). I couldn't confirm the exact publication date.

## 8. 🎯 One thing to try today (≤30 min)

**Score your own Claude Code skills with SkillEvaluator's Tier 1 checks. It's offline and needs no API key.**

```bash
pip install skillevaluator   # or: uv tool install skillevaluator
for s in ~/.claude/skills/*/ .claude/skills/*/; do
  echo "== $s"; skillevaluator validate "$s" --tiers 1
done
```

1. **Read the results:**
   - Note any format or compatibility failures, and any skill whose description overlaps another one, since Claude may then load the wrong skill.
   - Full static coverage also wants Gitleaks installed. That matters given last week's secrets-in-settings leak.
2. **Optional, ~15 min:** run Tier 2 deduplication across all your skills. It's the cheapest way to find the three skills that say "run tests before committing" in slightly different words.
3. **Act on it:** delete or merge the worst-scoring skill. You can measure the improvement in actual behavior later with Tier 3, which needs Docker and a provider key.
