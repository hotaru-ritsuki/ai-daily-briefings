## 1. 🔥 Top 3 things I shouldn't miss today

- **⚡ [Claude Code 2.1.323](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) fixes yesterday's secrets-in-`settings.local.json` problem.** "Don't ask again" now keeps a rule for this session only, without saving it, when the rule looks like it contains a secret or would be written to a git-tracked `settings.local.json`. The release also closes a long list of permission and sandbox holes. Update today, because several of those holes were cases where an allow rule skipped a prompt it shouldn't have.

One community author's [measurements](https://github.com/darjss/claude-code-codemode) of the same idea show it **costs more tokens** on ordinary coding tasks and only pays off for long chains of reads or large outputs. Don't switch it on everywhere.

Setting `features.multi_agent` now prints a warning: use `agents.enabled` instead.

## 3. 📋 AI coding tool changelogs (since the 2026-11-12 briefing)

### Claude Code — 2.1.323 (Nov 12)

This is a very large release. Here's what matters for daily use:

- ⭐🔧 **"Don't ask again" no longer saves secrets.** A rule that looks like it contains a credential, or that would land in a tracked `settings.local.json`, now applies to this session only. A separate fix makes `settings.local.json` gitignored globally even when a folder becomes a repo later. Together these close the leak path from §1 of yesterday's briefing.
- ⭐🐛 **Permission and sandbox holes closed:**
  - `Bash(ls*)`-style rules with a wildcard attached directly to the command skipped prompts in some cases. A rule that names a variable, like `Bash(NODE_ENV*)`, now asks.
  - Write and Edit could bypass `Read` deny rules.
  - The sandbox could switch off mid-session.
  - `excludedCommands` let commands it didn't name escape the sandbox.
  - `defaultMode: auto` could start in a looser mode when auto mode wasn't available.
  - There's a new startup warning for `*` inside a variable value, such as `Bash(PORT=* npm run dev)`.
- ⭐🆕 **Code Mode (experimental, opt-in):** Claude writes JavaScript that calls its tools. Organizations can turn it off. The docs page isn't live yet.
- ⭐🔧 **MCP changes:**
  - Approvals for `.mcp.json` servers now have to match the server name exactly.
  - The MCP sign-in tool asks you to confirm even in bypass and auto mode.
  - `TOKEN_EXPIRED` now prompts you to sign in again instead of failing.
  - `/mcp` shows how many of a server's tools were dropped because the API would reject their input schemas. This is useful when a homegrown server "loses" tools.
  - ⚠️ The v1 MCP client has been removed. `MCP_SDK_GENERATION=v1` now runs v2 in a compatibility mode.
- 🆕 **Plugins:** `engines["claude-code"]` in `plugin.json` pins a plugin to a range of Claude Code versions. `claude plugin validate` now type-checks TypeScript hook modules.
- ⚠️ **Unrecognised model IDs** are now assumed to have a 1M context window, not 200K. If you point Claude Code at other vendors' models through a gateway, set `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`.
- 🔧 **Worktrees and agents:**
  - The sandbox now blocks `git worktree add/move/remove`.
  - Finished subagents release their memory sooner.
  - `CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1` cuts the extra requests made to summarise subagent progress.
- 🐛 **Fixes:** running `/compact` again could summarise away a message Claude hadn't answered yet, and resumed sessions could merge your next message with an old interrupted one.
- 🚫 **Deprecated or removed:** `subagentStatusLine` is removed, and a plugin's `agent` setting is deprecated.
- 🔧 **JetBrains/VS Code:** there's a trust prompt before the first session in a folder you haven't trusted, and Bash output now streams live into the chat.

### OpenAI Codex

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Community "code mode" plugins came before the official feature, and one has data.** [darjss/claude-code-codemode](https://github.com/darjss/claude-code-codemode) adds a single `run` tool in which Bash, Read, Edit and MCP tools are async functions. Its nested calls still go through your hooks and permission prompts.
  - The author's two-week log found 177 turns of chained single reads and 152 tool outputs over 10K characters. Those are the cases where scripting helps.
  - Forcing every call through `run` cost more:
    - **Research task:** 3.45M tokens with Code Mode vs 2.62M with direct tools.
    - **Small coding task:** 0.80–0.89M vs 0.66–0.69M.
  - Treat this as single-user data, but it's the best evidence available for when to enable Anthropic's version. [gabe4coding/claude-code-mode](https://github.com/gabe4coding/claude-code-mode) applies the same idea to MCP tools only.
- **Pin your plugins now that `engines` exists.** A [community write-up](https://dev.to/piekwerk/claude-code-21323-pins-plugins-to-version-ranges-what-the-engines-field-enforces-and-6-things-to-13bc) covers what the new `engines` field enforces. If you share team plugins or `.claude/` configs, add `"engines": {"claude-code": ">=2.1.323"}` so old clients don't silently load hooks they can't run. I only saw a search summary of the post, because dev.to is blocked.
- **SAP's ABAP MCP server [major update](https://community.sap.com/t5/technology-blog-posts-by-sap/abap-development-tools-mcp-server-major-update-available/ba-p/14496064)** adds its own tools for search, where-used lookups and traces, so it no longer depends on VS Code's read and edit tools and works with Claude Code and Codex. It's not in your stack, but it shows a pattern: vendor MCP servers are dropping their IDE dependency, and the JetBrains MCP could follow.
- **Planner/implementer subagents instead of agent teams.** One [practitioner's setup](https://dev.to/krolmic/claude-code-subagents-vs-agent-teams-a-better-default-for-sequential-workflows-10of) uses `planner.md`, `implementer.md` and a `/task` command, and runs it in a GitHub Action. The argument: for sequential work, teams add coordination overhead with no parallel gain. Again, I only saw a summary.

## 8. 🎯 One thing to try today (≤30 min)

**Have `agent-skills` write a spec, then implement one small Angular change from it.**

1. **Install.** Update with `claude update` and confirm the version is ≥ 2.1.323. Then, in a scratch branch of your Angular repo, run:
   ```
   /plugin marketplace add addyosmani/agent-skills
   /plugin install agent-skills@addy-agent-skills
   ```
2. **Write the spec.** Ask Claude to *"use spec-driven-development to spec: add a loading/error state to `<one NgRx-backed PrimeNG table>`."* Stop after the spec, then edit it by hand. Check that it names the selectors, the effect, and a Playwright assertion.
3. **Implement and verify.** Ask Claude to implement the spec with `incremental-implementation`, then verify with `browser-testing-with-devtools`, or point it at `npx playwright test <spec>`.
4. **Judge it.** Did the spec catch an edge case you'd have missed, such as a retry or an empty state? Did the implementation stay inside what the spec covered?

**Success criteria:** a passing test, plus a spec you'd reuse. If both, copy the spec into `.claude/commands/spec.md` as a team template.

*Side task (5 min):* after updating, read the startup warnings. 2.1.323 now flags allow rules like `Bash(PORT=* …)`. Then look for rules with a wildcard attached directly to the command, such as `Bash(ls*)`, which can match more than you meant:
```
grep -rhE 'Bash\([A-Za-z_]+\*' ~/.claude/settings.json .claude/settings*.json
```
