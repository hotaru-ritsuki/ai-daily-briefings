## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **Evals are becoming a *skill*, not a separate tool.** Husain/Shankar's [`evals-skills`](https://github.com/hamelsmu/evals-skills) plugin is the sharpest example of the pattern: rather than bolt on a framework, you give the coding agent a procedure — `evals-start` routes by situation, `eval-audit` inspects an existing pipeline, and `error-discovery` (the load-bearing one) turns a file of traces into a sampled review app and clusters your notes into failure modes. This is the eval-driven-prompt-development discipline packaged as SKILL.md, harness-portable, and it slots straight into the `--plugin-dir` folder support that landed in v2.1.265 today. Closest thing to "TDD for prompts" I've seen shipped as an installable.
- **The MCP SSE-fallback fix (v2.1.266) is a quiet reliability win worth re-testing your servers against.** If you'd written off an HTTP MCP server as flaky, it may have been a transport mismatch, not the server — reconnect and check. Pair with the reminder from the DSEWiki/sandbox-escape week (covered 09-06): re-verify each server's write + egress scope while you're in the config.
- **Harness engineering is the framing the community has converged on this week.** OpenAI's [*Harness Engineering*](https://openai.com/index/harness-engineering/) post (the environment around the agent — rules, feedback loops, docs structure, dependency order — mattering more than the model) is drawing a wave of practitioner writeups ([Ken Huang](https://kenhuangus.substack.com/p/from-software-engineering-to-harness), [AlphaSignal](https://alphasignalai.substack.com/p/a-closer-look-at-harness-engineering)). The actionable read for you: your `.claude/` config, skills, and CI checks *are* your harness — invest there before you chase a bigger model.

## 8. 🎯 One thing to try today (≤30 min)

**Install the `evals-skills` plugin and run `error-discovery` on one of your own failing skill/prompt traces** (§1, §4). In Claude Code:

```
/plugin marketplace add hamelsmu/evals-skills
/plugin install evals-skills@hamelsmu-evals-skills
```

Restart CC, then invoke `/evals-skills:evals-start`, point it at a directory of outputs/traces from a skill that's been misbehaving, and let `error-discovery` sample and cluster them into named failure modes. Even if you don't adopt the whole methodology, you'll get a concrete list of *how* your prompt fails — which is exactly what you'd otherwise stare at logs for an hour to find. Bonus: after v2.1.265, you can keep this and other plugins in one folder and point CC at it with `--plugin-dir`.
