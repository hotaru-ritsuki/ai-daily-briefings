## 4. 🛠️ Claude Code & MCP ecosystem (community side, deep dive)

**Thariq's 9-category skill taxonomy is the missing structure under `.claude/skills/` auto-load.** The 06-03 [Anthropic post](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills) reads as authoritative because the numbers are concrete: a **47% reduction in tokens-per-task on document-heavy ops** vs. inline prompts, and **verification is named as the single highest-impact category** by measured output quality. Concrete mapping for the AngularJS → Angular 18 migration:

- **Library/API reference** → the `SignalMigration.md` substrate (validator mapping, import paths).
- **Product verification** → Playwright Healer against the ported component (the *single most important* skill per Thariq).
- **Code scaffolding** → component shell generation from the AngularJS `directive` definition.
- **Code quality/review** → `ng lint`, `tsc --noEmit`, OnPush-purity check.
- **CI/CD** → the wrapper around the overnight `claude -p` migration cron.
- **Runbooks** → "feature `<X>` test suite regressed by N% — diagnose."
- **Infra ops** — out of scope unless I extend the skill to manage worktrees.

The 9-category framework slots cleanly above 06-07's VILA-Lab "Dive into Claude Code" thesis: VILA-Lab argues *the harness > the model* (1.6% AI logic vs 98.4% deterministic infrastructure); Thariq argues *the harness has nine well-defined types*. Together they're the strongest "what good `.claude/skills/` looks like" reference we've had — read VILA-Lab for the architecture, then Thariq for the taxonomy.

**FastMCP 3.4.0–3.4.2 (June 3–6) ships `fastmcp-remote` — a standalone bridge for stdio-only MCP hosts** ([updates page](https://gofastmcp.com/updates), [PrefectHQ/fastmcp releases](https://github.com/PrefectHQ/fastmcp/releases)). When a host expects to launch a local command, `fastmcp-remote` runs locally, connects to a remote MCP server over Streamable HTTP or SSE, and exposes it back over stdio — OAuth on automatically for HTTPS, with **out-of-the-box support for WorkOS/AuthKit, GitHub, Google, Azure (Entra ID), AWS Cognito, Auth0, Descope, Scalekit, JWTs, and RFC 7662 token introspection**. This is the missing layer for Claude Code's stdio MCP client (which v2.1.163 just hardened with `CLAUDE_CODE_SESSION_ID`) talking to remote enterprise MCP servers behind SSO. Pair with v2.1.166's `fallbackModel` and the regulated-perimeter story for headless runs starts to make sense without bespoke proxy code. Pairs especially well with the 06-07 Spring AI 1.0.8/M7 Streamable-HTTP default — the stdio↔Streamable-HTTP bridge is the missing link between Claude Code's stdio assumption and the new Spring-side default.

**Anthropic Kotlin and C# client SDKs are now ~300 stars each, updated June 7–8** ([anthropic-sdk-java](https://github.com/anthropics/anthropic-sdk-java) reads as Kotlin per its repo metadata, [anthropic-sdk-csharp](https://github.com/anthropics/anthropic-sdk-csharp)). Both are **client SDKs**, not Agent SDKs (Agent SDK is still Python + TypeScript only per [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)) — but they are the first-class path to call Opus 4.8 from Spring Boot or .NET-side risk tooling without going through Python. Worth a Spring Boot bake-off against whatever OpenAI-Java client the platform team has standardised on; if the Kotlin SDK becomes the default, the Spring AI MCP server starter (06-07) is the matching server-side piece.

## 8. 🎯 One thing to try today (≤30 min)

**Audit your current `.claude/skills/` against Thariq's 9-category framework — and if you don't have any skills yet, scaffold a single "product verification" one for your migration loop.** Verification is the named highest-impact category; it pays back faster than any of the others. (Also: Agent-SDK credit-claim email lands today — see 06-07 §8 for the audit checklist around that.)

```bash
# 1. Pull the latest spec + the AAIF-standard frontmatter convention:
git clone https://github.com/anthropics/skills .ref/anthropics-skills
git clone https://github.com/anthropics/knowledge-work-plugins .ref/anthropics-kwp

# 2. Scaffold one Verification skill for a single ported feature:
mkdir -p .claude/skills/verify-feature-migration
cat > .claude/skills/verify-feature-migration/SKILL.md <<'EOF'
---
name: verify-feature-migration
description: |
  TRIGGER — run after porting any AngularJS feature module to Angular 18.
  Runs the Playwright e2e suite for the feature, then the Healer agent
  if any test fails; if Healer can repair without changing assertions,
  surface the diff as additionalContext (no auto-commit).
disallowed-tools: [Write]
---
# What this skill does
Calls scripts/verify.sh, which runs:
  - ng test --watch=false --browsers=ChromeHeadless --include="src/app/features/<X>/**"
  - npx playwright test e2e/features/<X> --reporter=line
  - npx playwright test --healer --report=json (if step 2 fails)
Reports back a structured pass/fail with the diff Healer produced (if any),
via Stop/SubagentStop hookSpecificOutput.additionalContext.
EOF
mkdir -p .claude/skills/verify-feature-migration/scripts
# (fill scripts/verify.sh with the three commands above + JSON munging)

# 3. Verify the skill loads (auto-load is v2.1.157+):
claude /reload-skills
claude /plugin list --enabled | grep verify-feature-migration

# 4. Dry-run against an already-ported feature:
claude -p "Run the verify-feature-migration skill on src/app/features/portfolio."
```

If the SKILL.md auto-loads and the Stop hook's `additionalContext` lands without aborting (the v2.1.163 fix), the loop is wired correctly. **Why today, not next week**: Thariq's framework is now the canonical "what good looks like" inside Anthropic — writing skills against it is materially easier than retrofitting structure later when the team has ten skills with overlapping responsibilities.
