## 1. 🔥 Top 3 things I shouldn't miss today

- **⚡ [Angular Anything](https://github.com/erkamyaman/angular-anything) (MIT, npm `0.1.1`, created Nov 27) records a React, Vue or AngularJS app in Chromium, then fails your agent's Angular port on any difference it finds.** It compares the accessibility tree, DOM, computed styles, data-changing requests, `localStorage`, URL, focus and dialogs. **Why:** it's the "prove the migration behaves the same" gate that agent-led migrations have been missing, in my framework. - **[actions-speedup](https://github.com/yuwen-cool/actions-speedup) publishes blind evals in which its own skill *loses* to a plain 10-point prompt, 25 to 23.5 out of 44 across 13 repositories.** **Why:** it's a rare honest skill-vs-prompt comparison, and it's a read-only CI audit I can point at our slow Angular + Spring pipelines today (§6a, §8, §9).
- **⚡ [mcp-sentinel](https://github.com/Jokudneh/mcp-sentinel) (MIT, zero dependencies) wraps any stdio MCP server as a policy proxy.** It blocks `rm -rf`, path escapes, `.env` reads and injection-shaped tool results, and writes every `tools/call` to a JSONL flight recorder. **Why:** an audit-only rollout of my local MCP servers takes about 10 minutes, and it complements the static `.mcp.json` scan from safe-anything (§4, §5).

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Runtime guard for MCP, not just a config scan.** [mcp-sentinel](https://github.com/Jokudneh/mcp-sentinel#mcp-client-integrations) sits between the client and the server's stdio and leaves the JSON-RPC stream untouched:
  - **Blocked calls never reach the server.** The agent gets a JSON-RPC error (`-32001`) with the rule ID, so it sees *why* and the session stays alive.
  - **Recommended rollout:** run `--mode audit` with `--trace` first, then build `--allow-tool` and `--allow-root` lists from `inspect` output before you switch to `enforce`.
  - **Limits:** detection is rule- and regex-based, so it won't catch a cleverly worded injection. One author, created yesterday, 13★. Treat it as a tripwire and audit log, not a sandbox.
- **Ticket sets → reviewed commits, with one human decision per turn.** [orchestrate-skills](https://github.com/orkhanfarmanli/orchestrate-skills#why-these-exist) builds on [mattpocock/skills](https://github.com/mattpocock/skills) and is the ticket-runner half of the pattern:
  - `/orchestrate` gives each ticket a fresh subagent, in dependency order, and checks its commits before the next one starts.
  - Every ticket gets a spec review *and* Claude Code's built-in `code-review` at `xhigh`, because code can match the spec and still be wrong.
  - `/flagman` walks `flags.md` one entry per turn (fix or ignore), and `/fixer` applies only the agreed fixes. Deciding and fixing are separate steps.
  - It never pushes or opens a PR, and it refuses to start on a dirty tree.
- **Parallel chats on one repo without collisions.** [mestrecs/skills](https://github.com/mestrecs/skills) gives each chat its own worktree and a shared test queue that runs N suites at a time. Changes to critical paths get a review from a different model. A single-file merge lock re-tests on the new base before each merge. It also includes a `codex-gemini-subagents-for-claude-code` skill that sends subagent work to Codex or Gemini CLI, chosen per chat.
- **MCP Apps in Angular.** [ngx-mcp-apps](https://github.com/umb0o/ngx-mcp-apps) (npm `0.4.0`) exposes the host connection, tool-call data, theme and display mode as **signals**. `ng add ngx-mcp-apps-builder` makes `ng build` output the single HTML file that MCP hosts expect. It's tested on claude.ai and Claude for Android only.

## 5. 📦 Useful repos

1. **[erkamyaman/angular-anything](https://github.com/erkamyaman/angular-anything)** (MIT, 9★). Behaviour gate for agent-written ports to Angular 22: `record` runs each case twice on the original and locks the result, and `gate` replays every case against the port. Recorded `fetch`/XHR responses are replayed, so no backend is needed. **Why I'd care:** an objective "done" signal for AngularJS → Angular work. **Limits:** early software, macOS-only testing, and loading/pending UI is never compared.
2. **[Jokudneh/mcp-sentinel](https://github.com/Jokudneh/mcp-sentinel)** (MIT, 13★). A stdio firewall, secret redactor and JSONL recorder for any MCP server. **Why I'd care:** it gives me a log of every tool call my agents make through local servers.
3. **[yuwen-cool/actions-speedup](https://github.com/yuwen-cool/actions-speedup)** (MIT, 28★). A Claude Code/Codex skill: a 16-item checklist plus Python scripts that profile run history, logs and per-test times. It's read-only until you agree to a change. **Why I'd care:** CI time is the main limit on how fast agent PRs get through.
4. **[orkhanfarmanli/orchestrate-skills](https://github.com/orkhanfarmanli/orchestrate-skills)** (MIT, 7★). `/orchestrate`, `/flagman` and `/fixer`. **Why I'd care:** a ready-made spec → tickets → reviewed commits loop with a short, auditable list of decisions for me.
5. **[mestrecs/skills](https://github.com/mestrecs/skills)** (MIT, 5★). A worktree per chat, a test queue, cross-model review and a merge queue. **Why I'd care:** the plumbing for running Claude and Codex at the same time on one monorepo.
6. **[umb0o/ngx-mcp-apps](https://github.com/umb0o/ngx-mcp-apps)** (MIT, new). An Angular 18–22 library and builder for MCP Apps, about 5 KB gzipped. **Why I'd care:** I can ship in-chat UIs, such as a PDF-preview or approval widget, with Angular skills I already have.
7. **[yfggg/spring-mcp-settlement-guard](https://github.com/yfggg/spring-mcp-settlement-guard)** (MIT, new). A Spring Boot + Spring AI MCP server where refunds are idempotent, velocity caps lock the row, and anything above a limit becomes an HMAC-signed `PENDING_APPROVAL` hold for a human. **Why I'd care:** a readable Java template for "money math and approvals stay in the backend, not in the LLM" (see §7).
8. **[FVitor7/streamsage](https://github.com/FVitor7/streamsage)** (MIT, new). A read-only Kafka MCP server for topics, consumer lag, messages and DLQs. Unknown lag is reported as `null`, never `0`, and payloads are off by default. **Why I'd care:** a safer first Kafka MCP than one that can write to topics.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[actions-speedup: Evaluation record](https://github.com/yuwen-cool/actions-speedup/blob/main/evals/results.md)** (~10 min). A good template for evaluating any skill you publish:
  - **Ground truth:** maintainer-merged CI speedup PRs. The agent sees only the base commit and the CI runs from before the PR.
  - **Discipline:** the rubric was written before any output was read, versions were frozen before each round's answers were seen, repos were never reused, and a second grader (Codex) scored blind.
  - **Result:** the 10-point prompt slightly wins overall. The skill is strongest on causes buried in test helpers and build scripts, and it hands changes that lower assurance (dropping matrix legs) to the human. One run can swing a repo by two points.
- **[Angular Anything: How it works + llms.txt](https://github.com/erkamyaman/angular-anything/blob/main/llms.txt)** (~8 min). A migration contract written *for the agent*: the tool never writes the port, only judges it. Its practical notes are worth reading even without the tool. Angular strips whitespace the original rendered (`preserveWhitespaces: true`), and emulated encapsulation's `_ngcontent-*` attributes break DOM equality, so use `ViewEncapsulation.None` or global styles.
- **[orchestrate-skills: "Why these exist"](https://github.com/orkhanfarmanli/orchestrate-skills#why-these-exist)** (~5 min). A first-hand account of what was still manual around a spec/ticket flow. The lesson: early runs dumped every review finding on the human. Fix rounds now settle findings that have one obvious fix, and a corrected spec line keeps its old text as `[was: ...]`, which keeps the history of the spec.
- **[spring-mcp-settlement-guard README](https://github.com/yfggg/spring-mcp-settlement-guard#how-it-works)** (~10 min). A concrete failure model for agents that move money: tool retries cause double payouts, the LLM gets decimal arithmetic wrong, and injected callers split one claim into many under per-call limits. The fixes: `BigDecimal` diffs on the server, idempotency keys claimed under `SELECT … FOR UPDATE`, gateway calls made outside the DB transaction, and a four-eyes `PAYOUT_UNKNOWN` state on timeout.

## 8. 🎯 One thing to try today (≤30 min)

**Race actions-speedup against a plain prompt on your own slowest CI workflow.**

1. Install it and check prerequisites (authenticated `gh`, Python 3.9+):
   ```bash
   npx skills add yuwen-cool/actions-speedup
   gh auth status
   ```
2. In the Angular or Spring repo with the slowest pipeline, start Claude Code in **plan mode** (`claude --permission-mode plan`) and ask: *"Our CI is slow, find out why. Use the actions-speedup skill. Report leads with evidence and expected savings; change nothing."* It makes about 60–100 API calls and takes about a minute.
3. In a fresh session *without* the skill, ask the same thing using a 10-point checklist: queue/setup/work split, cancelling superseded PR runs, cache keys, dependency install, Docker layer order, test sharding, Playwright container vs apt installs, per-test timings, duplicate builds, and jobs that could run in parallel.
4. Compare the two lists. Note which findings are hygiene (caching, sharding) and which are code causes (a slow Spring context, Playwright `waitForTimeout`, a Karma/Jest config).

**Pass criteria:** at least one lead with log evidence that you'd actually merge, plus a before/after table that keeps the same list of tests and the same required checks. If both sessions find the same things, use the cheaper prompt. The skill's own evals say that happens.
