## 2. 🤖 Frontier model & platform news

**Opus 4.8 beyond §1**: defaults to **high** effort, new `/effort xhigh`; fast mode **2× rate / 2.5× speed** (sharp drop from 4.7); accepts `role: "system"` after a user turn so you can append instructions mid-conversation without restating the prompt; min cacheable prompt now 1,024 tokens — down from 4.7 — so smaller skill/subagent prompts can hit the cache ([Simon Willison](https://simonwillison.net/2026/May/28/claude-opus-4-8/)). Honesty/calibration is the headline behavior change ([The New Stack](https://thenewstack.io/claude-opus-48-release/)).

**Working with Opus 4.8 — practical adjustments:**
- **Drop the "be thorough / don't make assumptions" preludes from CLAUDE.md and skills.** The 4× fewer silent flaws come from training, not prompting — extra hedging now over-fires and makes the model ask for confirmation it doesn't need. Trim before the next long migration run.
- **Default to `/effort high` (now the model default); reserve `/effort xhigh` for whole-module ports and architectural plans.** xhigh costs proportionally more thinking tokens, so reach for it on the workflow plan, not every subagent.
- **Re-baseline your cost projections.** Fast mode is now meaningfully cheaper relative to 4.7; long agentic sessions that you previously left on slow Opus may pencil out on fast Opus 4.8 ([benchmark + pricing recap](https://artificialanalysis.ai/models/claude-opus-4-8)).
- **The `role: "system"`-after-`user` capability** lets a Routine or workflow inject a refreshed system block mid-run when context changes (e.g., switching from "porting" to "fixing the failing tests"). Worth wiring into the next workflow you author.
- **API model ID**: `claude-opus-4-8`; live on Claude API, Bedrock, Vertex AI, and Microsoft Foundry from day one.

**OpenAI / Google / others** — no flagship in the 24–72h window.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

**Dynamic workflows are an architectural change, not a feature.** Until now every orchestration pattern (skills, subagents, Routines, `/goal`) had Claude in the loop turn-by-turn — context grew with every result. A *workflow* is a JS script Claude writes once and a separate runtime executes; subagent results stay in the script's memory, only the rolled-up answer reaches Claude. Same shape as LangGraph's "graph-as-program" but generated on demand. For the migration: the Bun port's three-stage shape (map lifetimes → port files in parallel → fix-loop the build) transposes directly to "map AngularJS components → port to standalone signal-based Angular → fix-loop ng build + Playwright" ([case study](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)). Caveats: 1,000-subagent cap per workflow, Pro tier excluded, `/usage` gets a new "workflows" bucket ([MarkTechPost](https://www.marktechpost.com/2026/05/28/anthropic-ships-claude-opus-4-8-alongside-dynamic-workflows-and-cheaper-fast-mode-with-workflows-capped-at-1000-subagents/)).

**Security Guidance plugin + Opus 4.8 calibration.** Covered in 05-28; today's follow-up is that Opus 4.8 self-flags uncertainty more honestly, so the plugin's instruction-injection pattern (deterministic regex match → text block back into the model) lands cleaner — the model rewrites instead of arguing with the warning. Install via `/plugins` → `security-guidance` (free, ~157K installs); pair it with Opus 4.8 on the next migrated component for a working baseline ([source](https://github.com/anthropics/claude-code/tree/main/plugins/security-guidance)).

**Quarkus Agent MCP** ([InfoQ](https://www.infoq.com/news/2026/05/java-news-roundup-may04-2026/)) — standalone MCP (not in-process) for managing Quarkus apps. Closest published precedent if the Spring Boot side ever wants an MCP for project ops.

```bash

```
