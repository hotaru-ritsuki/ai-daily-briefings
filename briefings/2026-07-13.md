## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

The community theme neither 07-11 (MCP migration) nor 07-15 (GitHub agent-security) touched is **cross-harness packaging** — tooling that treats your agent config as one portable, versioned loadout instead of per-tool silos. This is the natural next layer once you run Claude Code *and* Codex *and* Cursor *and* JetBrains against the same repo:

- **[skillet](https://github.com/Brattlof/skillet)** (Go) — a package manager for MCP servers, Agent Skills (`SKILL.md`), and Claude Code commands/hooks/subagents/output-styles that installs into **Claude Code, Cursor, Codex, Gemini CLI, Copilot and Cline**. The "npm for agent config" idea done concretely — the fix for hand-syncing skills across IntelliJ ACP + Claude Code + Cursor.
- **[agent-plugin-sdk](https://github.com/jnsahaj/agent-plugin-sdk)** (TypeScript) — define a plugin *once* (skills, commands, subagents, hooks, MCP, shared tools) and ship it to Claude Code, Codex, Pi and OpenCode. Same problem as skillet, solved at the authoring layer rather than install.
- **[Local-Loadout-Smithery](https://github.com/robester0403/Local-Loadout-Smithery)** (TypeScript) — shows the **token/context cost of every skill, command, subagent and MCP** in your loadout. A concrete, measurable answer to context-rot: know what each MCP server costs before it silently eats your window — the same instinct behind 07-15's "7× faster tool rounds at high tool counts" fix, but on the config side.
- **[scholar-megasearch](https://github.com/TaewoooPark/scholar-megasearch)** (Python, 20★) — one Claude Code skill that **fans out subagents across 20+ scholarly databases**, dedupes and ranks. Worth reading purely as a clean, real subagent-fan-out implementation you can retarget at internal sources (Confluence, Jira, internal wikis).

Nothing net-new on the official-skills front beyond 07-15's `anthropics/skills` (`mcp-builder`, `webapp-testing`) note.

## 8. 🎯 One thing to try today (≤30 min)

**Audit what your agent loadout actually costs in context, then version-control it across harnesses.** Two steps:

```bash
# 1. Measure the token cost of every skill/command/subagent/MCP in your loadout
git clone https://github.com/robester0403/Local-Loadout-Smithery && cd Local-Loadout-Smithery
# follow the README to point it at ~/.claude and your repo's .claude/ dir

# 2. Then install skillet and pull your MCP/skills as versioned packages
#    (works across Claude Code, Cursor, Codex, JetBrains-via-Gemini-CLI)
#    https://github.com/Brattlof/skillet
```

Why this over 07-15's PR-security drill (do that too): you're deep in a long migration with many MCP servers wired in (JetBrains, DB, GitHub, Atlassian). Each eats context you'd rather spend on the AngularJS→Angular diff. Measuring the cost, then version-controlling the loadout, is a 20-minute investment that pays back every session — and complements the 07-15 v2.1.208 perf work from the config side rather than the runtime side.
