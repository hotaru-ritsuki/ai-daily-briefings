## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **GitHub MCP skills ([README § MCP Skills](https://github.com/github/github-mcp-server#mcp-skills)).** The catalogue covers `pull-request-code-review`, `pull-request-review-feedback`, `workflow-failure-triage`, `security-alert-triage`, `release-preparation`, `issue-backlog-triage`, `copilot-task-delegation` and 12 more.
  - **Design worth copying:** every description pairs `USE FOR:` with `NOT FOR:` and names the neighbouring skill to use instead (review someone else's PR vs. respond to feedback on yours). That's how you stop look-alike skills from being picked for the wrong job.
  - **Filtering:** a restricted toolset only exposes the skills it can run. A read-only setup won't advertise skills that write.
  - Also in v2.2.0: optional secret hiding in secret-scanning alert tools. Repository tools now return typed `structuredContent` when the client negotiates MCP `2026-07-28` or later.
- **[autologin-mcp](https://github.com/olgaysezgin/autologin-mcp).** The agent calls `login({url})` and gets back a one-time script with no secret in it. The page then pulls the credentials from an origin-checked `127.0.0.1` bridge, or through CDP if the app's CSP blocks the bridge. Tool results are redacted, and a guard hook blocks Claude from reading the credentials file. It only handles username + password today; SSO, multi-step logins and TOTP are on the roadmap. It's a 5-★, one-day-old repo. CI enforces 98% coverage and there are E2E tests against headless Chrome, but use throwaway test accounts only.
- **[groundhog](https://github.com/Shiroe-95/groundhog)** (MIT, 0 deps, no network). A `PostToolUseFailure` hook normalises each error into a signature (paths → `<path>`, numbers → `<n>`, hashes → `<hex>`, with secrets masked first) and counts repeats per tool. On the 2nd hit it adds a note asking for a hypothesis and a prediction. On the 3rd it says stop: find the root cause, start a fresh subagent, or ask the user. A `PostToolUse` hook on Edit spots A→B→A reverts by hashing old and new text. More test passes than last time reset the count. It never blocks, so it's safe to try. The design is the useful part: "same wall, different command" is exactly the loop that wastes long sessions.
- **[trust-pyramid](https://github.com/Tim-rppl/trust-pyramid)** (MIT). A follow-up to Lauren Tan's "Code is memory" talk ([covered Nov 19](2026-11-19.md)), packaged as a Claude Code plugin and Codex skill. Run it once per repo and it sets up project-specific lint rules whose errors explain the fix, a Stop hook gate, and CI that uses the **base branch's** rules. Its AI reviewer only counts a finding when it comes with a test that fails before the fix and passes after. Install with `/plugin marketplace add Tim-rppl/trust-pyramid`. It's very new (5 ★), and the demo GIF is a scripted replay, as the README says.

## 8. 🎯 One thing to try today (≤30 min)

**Let Claude Code run a logged-in Playwright check on a local Angular app, then prove the password never reached the transcript.**

```bash
npx autologin-mcp install          # registers MCP server + skill + guard hook
npx autologin-mcp add              # run in a normal terminal, NOT in Claude
#   Profile: local   Root URL: localhost:4200   Username/Password: a throwaway test user
```

1. Make sure Playwright MCP is registered (`claude mcp list`). If not: `claude mcp add playwright -- npx @playwright/mcp@latest`.
2. `npx ng serve`, then restart Claude Code and prompt: *"Using Playwright MCP, open http://localhost:4200/orders. If you hit a login form or a 401, use autologin. Then check the orders table renders and the PrimeNG paginator works."*
3. **Pass criteria:** the agent calls `login`, gets `success` and carries on, and `grep -rF '<the test password>' ~/.claude/projects/ | wc -l` prints `0`. Also ask Claude to "read the autologin credentials file". The guard hook should block it.
4. If the app's CSP blocks the bridge, the README's fallback is CDP mode (Chrome remote debugging). Note it if you need it, because staging CSPs will probably hit the same problem.
5. If it passes, add one line to the repo's `CLAUDE.md`: "For authenticated UI checks, use the autologin `local` profile; never ask the user for credentials."

## 9. 📣 Shareable angle

**Hook:** "If your agent's E2E test needs your password in the chat, your test setup is the leak."
