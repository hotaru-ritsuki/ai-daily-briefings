## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Audit your MCP configs against the reference-server archival.** Anthropic now maintains only **7 reference servers** — Everything, Fetch, Filesystem, Git, Memory, Sequential Thinking, Time — and has handed the rest (GitHub, Postgres/DB, Slack, etc.) to **vendor-maintained** servers under the Linux Foundation's AAIF governance ([techsy](https://techsy.io/en/blog/best-mcp-servers-2026), [Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)). The practical rule: for DB access use the vendor server (Supabase's official Postgres MCP, or googleapis `genai-toolbox` for a Spring Boot backend), not an archived reference one.
- **Durable-state control planes are the concrete form the "meta-harness" theme is taking.** [`huangruiteng/loopx`](https://github.com/huangruiteng/loopx) (~1.7k★, v0.4.1) externalizes objective, approval gates, todo ownership, evidence, and quota into a `.loopx/` state dir **on disk, independent of any single agent session** — so a long job survives session restarts and hand-offs across Codex/Claude Code/Cursor. Each turn becomes a bounded slice: check quota → claim a todo → work → write evidence → hand off. That's a cleaner shape for my scheduled/unattended runs than cramming state into context ([explainx overview](https://explainx.ai/blog/loopx-agent-control-plane-loop-engineering-august-2026)).
- **Cross-harness *control surfaces* are maturing too.** [`pingdotgg/t3code`](https://github.com/pingdotgg/t3code) drives whichever agents are already set up on your machine (Claude Code, Codex, Cursor, Grok, OpenCode) from a mobile/web/desktop UI, with git-worktree integration, a one-click PR workflow, and a per-turn diff viewer ([Better Stack guide](https://betterstack.com/community/guides/ai/t3-code/)). Matches my multi-harness setup; worth it just for the per-turn diff review on the phone.
- **Playwright-as-skill over Playwright-MCP** keeps gaining as the token-efficient default — the CLI saves accessibility snapshots to disk as compact YAML instead of streaming a verbose tree into context ([QASkills setup](https://qaskills.sh/blog/playwright-mcp-claude-code-setup-2026)). Incremental on the 08-15 CLI-vs-MCP note, but the direction is now clear for my Playwright suites: expose the CLI as a skill, don't wire the MCP tool schema.

### 6a. AI workflows & patterns
- **[Harness Engineering: Making AI Coding Agents Work in 2026](https://www.faros.ai/blog/harness-engineering)** (Faros AI, ~last week) — frames a production harness as five explicit layers (tool orchestration, verification loops, context/memory, guardrails, observability); useful as a checklist to name the gaps in my own setup. *~9 min.*
- **[Harness Engineering for AI Coding Agents: Constraints That Ship Reliable Code](https://www.augmentcode.com/guides/harness-engineering-ai-coding-agents)** (Augment Code) — the "constraints beat instructions" argument made concrete: mechanical guardrails the agent can't talk its way past. Pairs with Simon Willison's validation-mechanism thesis. *~10 min.*
- **[Agentic Engineering Patterns](https://simonw.substack.com/p/agentic-engineering-patterns)** (Simon Willison) — the repeatable-workflow patterns behind agents that actually take multi-step actions autonomously; the throughline is that an agent needs a *validation mechanism it can run itself* (tests, a spun-up server) rather than trust. *~12 min. (search-confirmed — see Run notes.)*

## 8. 🎯 One thing to try today (≤30 min)

**Audit your MCP configs against the reference-server archival** — cheap, concrete, and it closes a real "this'll break silently later" risk (§1, §4).

1. `claude mcp list` — Claude Code now shows disabled servers as `⊘ Disabled` without health-checking them, so the list is fast and honest.
2. For each stdio server, check whether it's one of the **archived reference servers** (anything that *isn't* Everything/Fetch/Filesystem/Git/Memory/Sequential-Thinking/Time and came from the old `modelcontextprotocol/servers` repo — GitHub, Postgres, Slack, etc.).
3. Swap any archived one for its **vendor-maintained** replacement (e.g. `googleapis/genai-toolbox` for DB access) and commit the updated `.mcp.json` so every machine picks it up.

**Bonus (10 min):** clone [`huangruiteng/loopx`](https://github.com/huangruiteng/loopx) and read its `.loopx/` state model — it's the cleanest published answer to "how do I keep a scheduled agent job's goal + evidence durable across restarts," which is exactly the shape this daily briefing run wants.
