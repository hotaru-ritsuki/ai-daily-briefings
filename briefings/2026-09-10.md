## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **"Worktree isolation" is converging into a first-class primitive across harnesses.** Codex 0.154.0 adds `/worktree`; Claude Code already forks background workers into worktrees (and v2.1.267 fixes the cache bug that created); community orchestrators like **Sandcastle** (covered 09-08) and **orca** wrap the same idea. The practical pattern for you: stop letting parallel agents stomp one working tree — give each a branch-scoped checkout and merge back, which also makes a bad run trivially discardable. This is the cheap, correct substrate for the multi-agent fan-outs you already run.
- **The prompt-cache story is now a *correctness* story, not a perf nicety.** v2.1.267's fixes share one root cause — **anything that rewrites the tool list or system-prompt prefix after turn one invalidates the cache and drops extended thinking** — which is exactly why mid-session MCP reconnects and `/model` switches were quietly expensive. Actionable: treat MCP server churn and mid-session model swaps as cache-hostile, and on long sessions prefer a stable toolset. If you maintain an HTTP MCP server, the 09-09 SSE-fallback fix plus today's deferred-definition change mean it's worth re-checking how your server announces tools on reconnect.
- **`--system-prompt-snapshot off` is a small gift for skill authors.** When you're iterating a `.claude/skills/*` SKILL.md or a custom command's system prompt, the recorded-prompt reuse used to mask edits until you started a fresh session; the new flag re-renders every request so you see prompt changes immediately. Pairs naturally with yesterday's `evals-skills` `error-discovery` loop — edit prompt, re-run traces, cluster failures, repeat.

## 8. 🎯 One thing to try today (≤30 min)

**Use Codex 0.154.0's new worktree isolation for a throwaway refactor you wouldn't risk on your main tree.** After upgrading:

```bash
codex upgrade          # lands you on 0.154.0 stable
# then, inside a session:
/worktree              # spins an isolated git checkout for this session
#   or launch directly:  codex --worktree
```

Point it at a risky, self-contained change — e.g. "migrate this NgRx feature from the old `createReducer` pattern to the new one, run the unit tests, report the diff." Because the session runs in its own checkout, a bad run never touches your working tree; you review the branch and merge or discard. This is the cheapest way to feel out the parallel-agent / isolated-checkout pattern (§4) before wiring it into a script with Sandcastle or orca. **Before you upgrade, grep any tooling for `codex mcp-server`** — that entry point is gone in 0.154.0 (§3).
