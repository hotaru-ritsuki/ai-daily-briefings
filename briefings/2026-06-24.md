## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **`aislop` as a CI quality gate for AI-written code** ([scanaislop/aislop](https://github.com/scanaislop/aislop)). A deterministic, no-LLM linter that flags the patterns coding agents leave behind — narrative comments, swallowed exceptions, `as any` casts, dead branches, oversized functions — across 8 languages incl. TypeScript, emitting a 0–100 score you can fail a PR on. This is the missing guardrail for agent-generated diffs that type-checks-but-smells; pair it with `/review`.
- **`claude-flow`** ([ruvnet/claude-flow](https://github.com/ruvnet/claude-flow)) — a community orchestration layer that runs swarms of Claude Code subagents with shared memory and a coordinator role. Heavier than `.claude/agents/` markdown subagents; useful if you're prototyping the multi-agent migration patterns this series keeps circling.
- **MCP spec RC on your radar** ([modelcontextprotocol blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), *published May 21 — not breaking news*). The `2026-07-28` release candidate drops the `initialize` handshake and `Mcp-Session-Id` (stateless core behind a plain load balancer), adds the **MCP Apps** (server-rendered UI in sandboxed iframes) and **Tasks** extensions, hardens OAuth, and deprecates Roots/Sampling/Logging on 12-month windows. Final spec lands Jul 28 — read it before you author any new MCP server, but nothing breaks today.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)** — Armin Ronacher (Jun 23). The harness-level loop (the loop *outside* the agent loop) now dominates agentic discourse, but Armin reports it hasn't worked for code he deeply cares about: taste and the need to understand what ships cap how far you can delegate. The sober counterpoint to loop-maximalism. *~8 min.*
- **[Agentic Engineering Patterns](https://simonw.substack.com/p/agentic-engineering-patterns)** — Simon Willison. Most-useful nugget restated this week: pointing an agent at *another codebase as reference* is a high-bandwidth shortcut for communicating complex intent — directly applicable to "migrate this AngularJS module the way that already-migrated one was done." *~6 min.*
- **[Configuring Agentic AI Coding Tools: An Exploratory Study](https://arxiv.org/html/2602.14690v1)** — Empirical look at real repos: Context Files (`AGENTS.md`/`CLAUDE.md`) dominate and are often the *only* mechanism; Skills and Subagents are shallowly adopted and mostly static instructions, not executable workflows. *Takeaway: the mechanisms you lean on are underused by most teams — you're ahead, but verify yours actually execute. ~15 min skim.*
- **[Building Effective AI Coding Agents for the Terminal](https://arxiv.org/pdf/2603.05344)** — Scaffolding, harness design, and context-engineering lessons from building a terminal coding agent; useful vocabulary for evaluating why Claude Code/Codex behave differently under load. *~15 min.*

## 8. 🎯 One thing to try today (≤30 min)

Run the AI-slop linter against your migration repo to see what your AI-assisted commits actually leave behind:

```
npx aislop@latest scan
```

Zero-config, deterministic, no LLM at runtime — it returns a 0–100 score and flags narrative comments, swallowed exceptions, `as any` casts, and dead branches in your TypeScript. If the score is ugly, it's a ready-made CI gate; if it's clean, it's a cheap signal to cite when someone claims "AI code is sloppy." Repo: [scanaislop/aislop](https://github.com/scanaislop/aislop). *(~10 min.)* Bonus: once on v2.1.187, set `sandbox.credentials` and an org model restriction in `.claude/settings.json`.
