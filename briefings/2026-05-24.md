## 4. 🛠️ Claude Code & MCP ecosystem (community)

**The facade-tool pattern is becoming the standard answer to "big API, small context."** Salesforce's new **[Data 360 MCP Server](https://developer.salesforce.com/blogs/2026/05/introducing-the-data-360-mcp-server-developer-preview)** (developer preview) exposes ~200 API operations through a handful of facade tools so the agent never sees the full surface area. If you're wrapping internal fintech APIs as MCP, this is the design to copy — don't map one tool per endpoint; expose a small typed facade and let the agent compose.

**Code-knowledge-graph MCPs are maturing past "semantic search."** The newer entrants add structural reasoning, not just retrieval: **[sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp)** builds an AST graph (Tree-sitter, 16 languages) with call-graph traversal, **HTTP route tracing, and impact analysis** — the route-tracing + impact-analysis angle is genuinely useful for a Spring Boot + Angular system where you need "what breaks if I change this endpoint." (This is the differentiator vs. the Codegraph server covered 05-18.) **[GitNexus](https://www.marktechpost.com/2026/04/24/meet-gitnexus-an-open-source-mcp-native-knowledge-graph-engine-that-gives-claude-code-and-cursor-full-codebase-structural-awareness/)** maps imports/inheritance/interface-implementation as a graph behind MCP.

**Mega-aggregator skill repos keep ballooning** — `claude-code-plugins-plus-skills` now advertises 2,810 skills, `claude-skills` 329. Treat these as discovery surfaces, not vetted libraries: at that volume the signal-to-noise is poor and you're trusting unknown authors' prompts. Pull individual skills, read them, then adopt — don't install the marketplace wholesale.

## 5. 📦 Useful repos

1. **[sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp)** — AST knowledge-graph MCP: call-graph traversal, HTTP route tracing, impact analysis, 16 languages via Tree-sitter, hybrid BM25+vector search. *Best fit today for navigating a large AngularJS→Angular + Spring Boot codebase without fanning out across grep/Read.*
2. **[googleapis/mcp-toolbox](https://github.com/googleapis/mcp-toolbox)** — open-source MCP server for databases (connection pooling, auth, observability built in). *If you want agents querying your data layer safely, this is the maintained baseline rather than a hand-rolled DB MCP.*
3. **[Salesforce Data 360 MCP Server](https://developer.salesforce.com/blogs/2026/05/introducing-the-data-360-mcp-server-developer-preview)** — developer preview; reference implementation of the facade-tool pattern over ~200 operations. *Worth reading even if you don't use Salesforce — it's the cleanest example of MCP design over a huge API.*
4. **[levnikolaevich/claude-code-skills](https://github.com/levnikolaevich/claude-code-skills)** — plugin suite with bundled MCP servers: hex-line (hash-verified editing), hex-graph (code knowledge graph), hex-ssh, plus a multi-model AI-review Agile pipeline. *The hash-verified-edit MCP is a clever guardrail against agents clobbering files they didn't actually read.*
5. **[Lum1104/Understand-Anything](https://github.com/Lum1104/Understand-Anything)** — Claude Code plugin that runs a multi-agent pipeline to build a browsable knowledge graph (files/functions/classes/deps) with an interactive dashboard. *Onboarding aid for the legacy AngularJS side nobody fully remembers.*
6. **[rohitg00/awesome-claude-code-toolkit](https://github.com/rohitg00/awesome-claude-code-toolkit)** — curated index of agents, skills, commands, hooks, MCP configs. *A vetted-ish discovery hub; better starting point than the 2,800-skill mega-dumps.*
7. **[push-based/angular-toolkit-mcp](https://github.com/push-based/angular-toolkit-mcp)** *(repeat, still under-starred)* — semantic Angular project analysis for deprecated patterns and component contracts; handles AngularJS-flavored legacy the official Angular MCP ignores. *One of your two in-stack picks.*

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

A working Angular/.NET engineer arguing against over-engineering your agent setup: a tight spec + small loop beats elaborate multi-agent topologies for most real tasks. Closest first-hand account to your stack. ~9 min.

Use this to gate migrated-component PRs. ~12 min.

The four-phase loop (specify → plan → task → implement) with concrete prompts; frames migration as spec-mediated rather than syntax transform. ~10 min.

Maps sequential / operator / split-and-merge / agent-teams structures and when each pays off — a decision framework for how to wire subagents on the migration rather than defaulting to one big agent. ~8 min.

## 8. 🎯 One thing to try today

**Run the new per-category `/usage` breakdown in Claude Code v2.1.149 right after a normal migration session** — it's the fastest read on where your quota goes before June 15 pricing lands.

```bash
claude update      # get to v2.1.149+
claude             # run a typical session: a subagent or two, your usual MCP servers
# then, in the session:
/usage
```

Read the split across **skills / subagents / plugins / MCP servers**. If one MCP server (e.g. a heavyweight code-graph or DB server) dominates, decide whether it earns its keep or should be loaded only on demand. Five minutes of looking now can save real money after the credit change.

Bigger experiment if you have 30 min: clone **[sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp)**, index one Angular feature module + its Spring Boot endpoints, and ask Claude "what breaks if I change this controller's response shape?" — see if impact-analysis-over-MCP beats your current grep-and-read loop.
