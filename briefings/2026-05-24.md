## 4. 🛠️ Claude Code & MCP ecosystem (community)

**The facade-tool pattern is becoming the standard answer to "big API, small context."** Salesforce's new **[Data 360 MCP Server](https://developer.salesforce.com/blogs/2026/05/introducing-the-data-360-mcp-server-developer-preview)** (developer preview) exposes ~200 API operations through a handful of facade tools so the agent never sees the full surface area. If you're wrapping internal fintech APIs as MCP, copy this: don't map one tool per endpoint; expose a small typed facade and let the agent compose calls behind it. (Note this is also the spirit of the MCP 2026-07-28 RC's stateless core, covered yesterday.)

**Code-knowledge-graph MCPs are adding structural reasoning, not just retrieval.** [sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp) builds an AST graph (Tree-sitter, 16 languages) with call-graph traversal, **HTTP route tracing, and impact analysis**; [GitNexus](https://www.marktechpost.com/2026/04/24/meet-gitnexus-an-open-source-mcp-native-knowledge-graph-engine-that-gives-claude-code-and-cursor-full-codebase-structural-awareness/) maps imports/inheritance/interface-implementation behind MCP. The route-tracing + impact-analysis angle is the differentiator versus the retrieval-focused Codegraph and claude-context servers covered earlier this week — it's "trace the blast radius," not "find similar code."

**Mega-aggregator skill repos keep ballooning** — `claude-code-plugins-plus-skills` now advertises 2,810 skills, `claude-skills` 329. Treat these as discovery surfaces, not vetted libraries: at that volume signal-to-noise is poor and you're trusting unknown authors' prompts. Pull individual skills, read them, then adopt — don't install the marketplace wholesale.

## 5. 📦 Useful repos

1. **[sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp)** — AST knowledge-graph MCP: call-graph traversal, HTTP route tracing, impact analysis, 16 languages via Tree-sitter, hybrid BM25+vector search. *Best fit today for tracing change blast-radius across AngularJS→Angular + Spring Boot without grep fan-out.*
2. **[GitNexus](https://www.marktechpost.com/2026/04/24/meet-gitnexus-an-open-source-mcp-native-knowledge-graph-engine-that-gives-claude-code-and-cursor-full-codebase-structural-awareness/)** — MCP-native knowledge-graph engine mapping function calls, imports, class inheritance, and interface implementations; ships MCP tools + skills + context-enrichment hooks. *Structural awareness for Claude Code on a large legacy repo; complements the AST server above.*
3. **[googleapis/mcp-toolbox](https://github.com/googleapis/mcp-toolbox)** — open-source MCP server for databases with connection pooling, auth, and observability built in. *The maintained baseline if you want agents querying your data layer safely rather than a hand-rolled DB MCP.*
4. **[Salesforce Data 360 MCP Server](https://developer.salesforce.com/blogs/2026/05/introducing-the-data-360-mcp-server-developer-preview)** — developer preview; reference implementation of the facade-tool pattern over ~200 operations. *Read it even if you don't use Salesforce — cleanest public example of MCP design over a huge API.*
5. **[levnikolaevich/claude-code-skills](https://github.com/levnikolaevich/claude-code-skills)** — plugin suite with bundled MCP servers: hex-line (hash-verified editing), hex-graph (code knowledge graph), hex-ssh, plus a multi-model AI-review Agile pipeline. *The hash-verified-edit MCP is a clever guardrail against agents clobbering files they didn't actually read.*
6. **[Lum1104/Understand-Anything](https://github.com/Lum1104/Understand-Anything)** — Claude Code plugin running a multi-agent pipeline to build a browsable knowledge graph (files/functions/classes/deps) with an interactive dashboard. *Onboarding aid for the legacy AngularJS side nobody fully remembers.*
7. **[rohitg00/awesome-claude-code-toolkit](https://github.com/rohitg00/awesome-claude-code-toolkit)** — curated index of agents, skills, commands, hooks, MCP configs. *A vetted-ish discovery hub; better starting point than the 2,800-skill mega-dumps.*

## 8. 🎯 One thing to try today

**Clone [sdsrss/code-graph-mcp](https://github.com/sdsrss/code-graph-mcp), index one Angular feature module plus its Spring Boot endpoints, and ask Claude an impact-analysis question** — see if graph-over-MCP beats your current grep-and-read loop on the migration.

```bash
git clone https://github.com/sdsrss/code-graph-mcp && cd code-graph-mcp
# Follow the repo's setup, then point it at a scoped path of your monorepo
# and register it in .mcp.json, e.g.:
# {
#   "mcpServers": {
#     "code-graph": {
#       "command": "code-graph-mcp",
#       "args": ["--root", "/path/to/your/feature-module"]
#     }
#   }
# }
```

Then in Claude Code: *"Use the code-graph tools to trace every caller of `OrderController.getSummary` and every Angular component/service that consumes that endpoint. List what would break if I change its response shape from a flat array to a paginated envelope."* The value is the blast-radius map you'd otherwise assemble by hand — and a read on whether to keep this MCP loaded by default or only via `/mcp connect` for refactors.
