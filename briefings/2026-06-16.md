## 3. 📋 AI coding tool changelogs

### Claude Code ([changelog](https://code.claude.com/docs/en/changelog))

**v2.1.178 — June 15** (substantive)
- 🆕 ⭐ **`Tool(param:value)` permission-rule syntax** with `*` wildcard. `Agent(model:opus)` blocks Opus subagents; the pattern generalizes to any tool input parameter. ⭐ The first-class primitive for the param-level allowlist patterns the platform team has been writing by hand against `PreToolUse` hooks since the 05-30 deny-rule degradation CVE.
- 🆕 ⭐ **Nested `.claude/skills` directories load when working on files there**; on a name clash, the nested skill appears as `<dir>:<name>` so both stay available. ⭐ Direct fit for a monorepo migration — feature-module-scoped skills instead of project-root-only.
- 🆕 ⭐ **Auto-mode classifier now evaluates subagent spawns *before* launch.** Closes the gap where a subagent could request a blocked action without classifier review. ⭐ The natural pairing to v2.1.172's 5-level subagent depth (06-11) — depth without classifier coverage was the obvious bypass class.
- 🆕 Nested `.claude/` directories: closest agent/workflow/output-style wins on collision; project-scope workflow saves now target the closest existing `.claude/workflows/`.
- 🔧 Workflow keyword now triggers only on explicit phrases ("run a workflow" or "workflow:"), not any mention of the word — fewer false-positive dynamic-workflow generations.
- 🔧 `/doctor` cleaner: flat tree layout, clearer section status icons, highlighted command names.
- 🐛 ⭐ **Compaction now honors `--fallback-model`** on overload or model-availability errors. ⭐ With v2.1.166's fallback chain pinned, compaction now degrades gracefully instead of failing the whole turn.
- 🐛 ⭐ **MCP server-level specs (`mcp__server`, `mcp__server__*`, `mcp__*`) in subagent `disallowedTools` being silently ignored** — fixed. Real allowlist-bypass class for any subagent that was supposed to be MCP-isolated; audit subagent configs.
- 🐛 Subagent transcripts now show tool results + live progress; messages sent while subagent finishes turn no longer dropped; ctrl+b on running subagent no longer restarts from scratch.
- 🐛 `claude agents` workers failing with `401 Invalid bearer token` when daemon started from shell with custom `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` — fixed.
- 🐛 OOM crash when CLI inherits stale websocket/OAuth FD env var from parent process — fixed.
- 🐛 `/bug` requires a description before submitting; no longer uses model-refusal text as GitHub issue title.
- 🐛 `claude` in Chrome silently failing to connect when OAuth token belongs to a different account than the Claude Code login — fixed.

## 4. 🛠️ Claude Code & MCP ecosystem (community side)

**The bake-off the platform team has been deferring just became un-deferrable — and it's no longer symmetric.** Pre-June-12, the Claude vs Codex case was about *capability*. Post-June-15, capability is roughly a tie on what's actually available to most teams (Fable still suspended; Opus 4.8 vs GPT-5.5/Codex), and the deltas that matter are **(a) `/import` from Claude Code on the Codex side (no Anthropic equivalent), and (b) `Tool(param:value)` + classifier-before-spawn on the Claude side (no Codex equivalent)**. Both vendors shipped material primitives on the same day. The right move this week is to run the bake-off, not put it off another month.

**[ching-kuo/claude-codex](https://github.com/ching-kuo/claude-codex)** *(NEW here)* — Claude Code workflow that wires **Codex as an MCP server** inside Claude Code, with smart routing between Claude and Codex per call. Plan-implement-review loops with per-step routing decisions. This is the cleanest reference for **multi-vendor agentic workflows** — you stop choosing a vendor and start letting the orchestrator route. Worth a sandbox install today as the counterpoint to the unilateral migration `/import` implies. The repo's premise gets stronger this week, not weaker — both vendors' headline features are different enough that you'd genuinely want both inside the same loop.

**Codex's `/import` puts quiet pressure on the AAIF SKILL.md interop story.** The folder-instructions + skills transfer cleanly; MCP servers don't. For any skill being authored fresh this week, the practical move is **dual-target the SKILL.md frontmatter** (`runtime: [claude-code, codex, ...]`) so it survives a future `/import` and any vendor pivot for free. The 06-13 sweep-for-`claude-fable-5`-pins advisory has the same shape — model pins are vendor-coupling surfaces, runtime IDs are vendor-portability surfaces.

**v2.1.178's nested `.claude/skills` directories change the right shape for a migration's skill tree.** Pre-178, all skills lived under `.claude/skills/` at the project root and a feature-module-scoped skill couldn't co-exist with a project-wide one without name collision. Post-178, `src/app/features/portfolio/.claude/skills/migrate.md` and `.claude/skills/migrate.md` both load, with the nested one showing up as `portfolio:migrate`. For the AngularJS→Angular 18 work this matches the existing module hierarchy 1:1.

**JetBrains MCP server** still at v262.7132.31 (June 5). No movement since.
