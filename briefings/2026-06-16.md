### Claude Code ([changelog](https://code.claude.com/docs/en/changelog))

**v2.1.178 — Jun 15**
- 🆕 ⭐ **`Tool(param:value)` permission-rule syntax** with `*` wildcards. `Agent(model:opus)`; the pattern generalizes to any tool input parameter. ⭐ The first-class param-level primitive the platform team has been hand-rolling with `PreToolUse` hooks.
- 🆕 ⭐ **Nested `.claude/skills` directories** load contextually when working on files in those subdirs; name clashes surface as `<dir>:<name>`. ⭐ Direct fit for feature-module-scoped skills in a monorepo migration.
- 🆕 ⭐ **Auto-mode classifier evaluates subagent spawns *before* launch.** Closes the gap where a child could request a blocked action without classifier review.
- 🆕 Nested `.claude/` agents/workflows/output-styles: closest-to-cwd wins on collision.
- 🔧 Workflow keyword now triggers only on explicit phrases (`"run a workflow"`, `"workflow:"`) — fewer false fires.
- 🐛 ⭐ **Compaction now honors `--fallback-model`** on overload. ⭐ Pairs with v2.1.166's fallback chain — compaction degrades gracefully now.
- 🐛 ⭐ **MCP server-level specs (`mcp__server`, `mcp__*`) in subagent `disallowedTools` were silently ignored** — fixed. Real allowlist-bypass class; audit subagent configs.
- 🐛 Subagent transcripts now show tool results + live progress; `ctrl+b` on running subagent no longer restarts from scratch; `claude agents` workers `401` on custom `ANTHROPIC_BASE_URL` fixed; OOM from stale websocket/OAuth FD env vars fixed; `/bug` requires description, no longer uses model-refusal text as the GH issue title.

## 4. 🛠️ Claude Code & MCP ecosystem (community side)

**The bake-off the platform team has been deferring just stopped being symmetric.** Codex now has `/import` from Claude Code (no Anthropic equivalent); Claude Code has `Tool(param:value)` + classifier-before-spawn (no Codex equivalent). Both vendors shipped material primitives the same day. The deltas are now in *different* directions — which is exactly the shape that makes a multi-vendor harness setup more defensible than a vendor-selection one.

**The Codex-as-MCP-inside-Claude-Code pattern is gaining real implementations.** [`tuannvm/codex-mcp-server`](https://github.com/tuannvm/codex-mcp-server) and [`cexll/codex-mcp-server`](https://glama.ai/mcp/servers/cexll/codex-mcp-server) wrap Codex CLI as an MCP server callable from Claude Code (one-line install: `claude mcp add codex-cli -- npx -y @cexll/codex-mcp-server`); [`clptvn/claude-codex-dialog`](https://lobehub.com/mcp/clptvn-claude-codex-dialog) goes further with back-and-forth dialog between the two agents. **The most interesting development**: [openai/codex Discussion #15374](https://github.com/openai/codex/discussions/15374) — bidirectional Claude Code Channels (MCP) ↔ Codex App Server in the same live session. The cross-vendor routing pattern is now first-party-ish, not just a community hack.

**Codex's `/import` puts quiet pressure on the SKILL.md interop story.** Folder-instructions + skills transfer cleanly; MCP servers don't. For any skill authored fresh this week, **dual-target the SKILL.md frontmatter** (`runtime: [claude-code, codex, ...]`) so it survives a future `/import` for free. The 06-13 sweep-for-`claude-fable-5`-pins advisory has the same shape: model pins are vendor-coupling surfaces, runtime IDs are vendor-portability surfaces.

**v2.1.178's nested `.claude/skills` is the right shape for a feature-module migration.** Pre-178, a feature-module skill couldn't co-exist with a project-wide one without name collision. Post-178, `src/app/features/portfolio/.claude/skills/migrate.md` loads as `portfolio:migrate` alongside the root one. The hierarchy maps 1:1 onto Angular's module structure.

**JetBrains MCP server** still at v262.7132.31 (Jun 5). No movement.
