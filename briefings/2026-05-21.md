### Claude Code

**v2.1.146 — May 21, 2026**
- `/simplify` renamed to `/code-review` with optional effort level — 🆕 ⭐ This replaces a command I use; the effort parameter (`/code-review high`) lets you control review depth without prompt engineering.
- Auto mode no longer suppresses `AskUserQuestion` when a skill depends on it — 🐛
- MCP `resources/list`, `resources/templates/list`, `prompts/list` fix: items past page 1 on paginating servers were dropped — 🐛 ⭐ If you use MCP servers with many resources, this was silently losing data.
- `CLAUDE_CODE_SUBAGENT_MODEL` now forwarded to child processes in multi-agent sessions — 🐛 ⭐ Fixes model override propagation in agent chains.
- Windows: PowerShell tool fix for `pwsh` via winget/MS Store (regression from v2.1.124) — 🐛
- Background sessions: `/background` no longer refuses sessions whose only input was a skill/slash command; backgrounded sessions stop re-prompting for already-granted permissions — 🐛
- Windows worktree cleanup no longer follows NTFS junctions into the main repo — 🐛
- Auto-updater retries transient network failures instead of failing immediately — 🔧
- Diff rendering performance improved for large file edits — 🔧

**v2.1.145 — May 19, 2026**
- `claude agents --json` for scripting (tmux-resurrect, status bars, session pickers) — 🆕 ⭐ Pipe live agent state into your terminal tooling.
- `agent_id`/`parent_agent_id` in OTEL spans + fixed trace parenting for background subagents — 🆕
- Status line JSON now includes GitHub repo and PR info — 🔧
- `/plugin` Discover/Browse shows commands, agents, skills, hooks, MCP/LSP servers before install — 🔧
- `claude agents` tab title shows awaiting-input count — 🔧
- Permission-prompt bypass fix: bare variable assignments to non-allowlisted env vars were auto-approved — 🐛 ⚠️ Security fix.
- Slash command and @-mention suggestions support mouse hover/click in fullscreen — 🔧

## 8. 🎯 One thing to try today

**Try the new `/code-review` command on your migration code.** Claude Code 2.1.146 renamed `/simplify` to `/code-review` and added an effort parameter. Run it against one of your AngularJS-to-Angular 18 migrated components:

```bash
# Update Claude Code first
claude update
# Then in a session, navigate to a recently migrated component and run:
/code-review high
```

This will give you a thorough review of the migrated code. Compare results between `/code-review` (default effort) and `/code-review high` on the same file to calibrate how you want to use it going forward. Takes ~10 minutes.
