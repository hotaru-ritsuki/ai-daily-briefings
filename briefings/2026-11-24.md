## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[safe-anything](https://github.com/erkamyaman/safe-anything)** is from the author of rust-anything ([covered Nov 18](2026-11-18.md)). Its agent rules ([docs/agent-setups.md](https://github.com/erkamyaman/safe-anything/blob/main/docs/agent-setups.md)) cover:
  - `bypassPermissions` or `--dangerously-skip-permissions`, and `"allow": ["Bash"]`
  - **unpinned `npx -y` MCP servers**, plaintext tokens in `.mcp.json` `env`, and `http://` MCP URLs
  - `curl | sh` in hooks or skills, and skills that read `~/.ssh` or `~/.aws`
  - prompt-injection phrases and hidden Unicode tag characters
  It runs as a CLI, an MCP server (`claude mcp add safe-anything -- safe-anything mcp`) or a plugin, and it exits 1 on high or critical findings, so it can gate CI. The README's suggested habit is worth adopting: clone someone's skills repo to `/tmp`, scan it, then install.
- **[joggernaut](https://github.com/usejog/joggernaut)** (MIT, ~26 ★, Nov 22) is a set of CI-speed skills (`/jog:ci-diagnose`, `ci-flaky-tests`, `ci-cache`, `ci-measure`, `ci-guard`) built from about 85 team write-ups that include before/after numbers. The design is the interesting part:
  - **One fix per PR**, and estimated savings are never added together.
  - `ci-measure` needs at least 5 CI runs on each side and uses a Hodges-Lehmann interval, so one fast run doesn't count as a win.
  - **"Keep every test" is a hard rule**, and the hook bans every way of skipping it. That rule exists because one team's agents skipped the pre-push hook on 118 of 411 pushes, a self-reported figure cited in the README.
- **[agent-postmortem](https://github.com/zeyusuntt/agent-postmortem)** (MIT, alpha) reads `~/.claude/projects` transcripts and reports which subagents or Workflow agents were killed and quietly restarted, which never returned, and which said "done" when their own results showed failure. Its plugin also tracks `claude --bg` workers and wakes the parent session when one is stuck on a permission prompt. The author's own scan found 13 of 166 workflow runs re-launched an agent's task. It has no LLM, needs no network, and is read-only: `uvx agent-postmortem scan`.
- **[questionnaire](https://github.com/fazxes/questionnaire)** (MIT, ~34 ★) makes the agent answer a typed intake before work starts (debug, build, design, repro or review, then follow-up questions). A script rejects skipped, invented or vague answers. The output is `skills.md` plus `rules.md`, which includes a "Done when" line the agent re-reads after compaction. It's a deterministic version of "pick the skills for this task".
- **Browser-auth for agent testing.** Following autologin-mcp ([covered Nov 23](2026-11-23.md)), two more tools take different approaches. [SessionForge](https://github.com/Hamzasohail123/sessionforge) (Apache-2.0) is an Electron browser with one isolated session per role (Admin, Customer, Guest) and a localhost MCP bridge that is off by default, with production sessions read-only. [sessfork](https://github.com/wasabihu/sessfork) (MIT) copies Chrome cookies and localStorage into a Playwright `storageState` file. sessfork copies real logins out of your browser, so keep it away from production accounts.

## 8. 🎯 One thing to try today (≤30 min)

**Audit my own agent setup and one community skill with safe-anything, then pin whatever it flags.**

```bash
npx safe-anything ~/projects/<angular-repo> --severity medium   # repo incl. .claude/, .mcp.json, CLAUDE.md
npx safe-anything ~/.claude --offline                           # user-level skills, hooks, settings
```

1. Look at `agent.*` findings first. `agent.mcp-unpinned` will almost certainly fire on `npx -y @playwright/mcp@latest` and similar entries. Pin them to exact versions (for example `@playwright/mcp@0.0.86`).
2. Move any token found by `agent.mcp-plaintext-secret` into an env var. Re-add the server with `claude mcp add-json <name> -` from stdin (2.1.327) so the token stays off the command line.
3. Before installing the next community skill: `git clone --depth 1 <repo> /tmp/x && npx safe-anything /tmp/x`.
4. **Pass criteria:** zero high or critical agent findings. If it's clean, add `npx safe-anything . --fail-on high --offline` as a pre-push or CI step.
5. While you're in managed settings: if your team uses `extraKnownMarketplaces`, decide now whether each entry needs `"autoUpdate": false` before the Nov 30 default change.
