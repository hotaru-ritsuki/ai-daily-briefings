## 4. 🛠️ Claude Code & MCP ecosystem (community)

- ⭐ **The "Karpathy" 10-rule CLAUDE.md is the config story of the week.** Four edit-time rules + six runtime rules; the high-value additions for unattended loops are *no fix is "done" until a test passes*, *per-step/per-pipeline/per-day token budgets that halt and surface on overrun*, and the named-failure-mode vocabulary ([CLAUDE.md](https://github.com/multica-ai/andrej-karpathy-skills/blob/main/CLAUDE.md), [TechTimes write-up](https://www.techtimes.com/articles/319214/20260628/karpathy-claudemd-grows-ten-rules-new-self-check-protocol-ai-coding-loops.htm)). Use it as a menu, not a wholesale template.
- **Anthropic's official "Steering Claude Code" guide** lays out all seven instruction mechanisms (CLAUDE.md, rules, skills, subagents, hooks, output styles, system-prompt append) with a decision tree for each ([claude.com/blog](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)). The useful split: **skills** run in the main thread so you steer each step; **subagents** isolate side tasks whose intermediate output you don't want in context.
- **MCP testing tooling worth wiring into CI:** [`modelcontextprotocol/inspector`](https://github.com/modelcontextprotocol/inspector) (interactive UI + proxy to debug a server over stdio/SSE/streamable-http) and [`modelcontextprotocol/conformance`](https://github.com/modelcontextprotocol/conformance) (standardized scenario tests, e.g. `server-initialize`) — the pair to reach for before shipping a custom MCP server wrapping our JetBrains/Spring tooling.
- **DESIGN.md is spawning an ecosystem:** [`VoltAgent/awesome-design-md`](https://github.com/voltagent/awesome-design-md) ships ready-made DESIGN.md files reverse-engineered from real brand systems; pairs with the tool-agnostic [`agents.md`](https://github.com/agentsmd/agents.md) behavioral format as the design-side counterpart.

## 7. 🎯 One thing to try today (≤30 min)

**Give Claude Code a DESIGN.md and watch it stop guessing at your UI.** Capture a slice of our design language (colors, spacing, typography, a couple of component rules) as tokens-plus-prose, drop it at repo root, then ask Claude Code to build one small PrimeNG or Highcharts component to spec.

```bash
git clone https://github.com/google-labs-code/design.md
# read docs/spec.md, create a DESIGN.md in your project root, then in Claude Code:
#   "Build a Highcharts donut card that conforms to ./DESIGN.md"
```

Even a 30-line DESIGN.md typically beats pasting screenshots or hex codes, and the validator (broken token refs, WCAG contrast) doubles as a lint pass on the design system itself. *Bonus:* paste the relevant rules from the §1 Karpathy CLAUDE.md into your config and re-run the same task to compare discipline.
