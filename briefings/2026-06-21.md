## 4. 🛠️ Claude Code & MCP ecosystem (community side, deep dive)

The week's most useful ecosystem story is **stack-native**, not generic. `angular/skills` (§1, §5) is the structural counterpart to last week's "one governed source, many harnesses" thread: instead of you hand-authoring a `SKILL.md` that encodes Angular 18 conventions, the framework owner now ships and maintains it, and it compiles into Claude Code as an auto-loading skill. Pair it with the **Angular MCP server's** preview modernization tools (v20.2+) and you get the migration loop the 06-17 subagent-driven-worktree pattern was missing a leaf for: orchestrator → feature-module subagent → `angular/skills`-guided component rewrite → Playwright spec as the review gate. The caveat from practitioners is consistent and worth internalizing (§6a): "migration completed" ≠ "behavior preserved" — a 77% first-run pass on a real Reactive→Signal Forms migration still hid validation-semantics regressions ([HeroDevs](https://www.herodevs.com/blog-posts/the-slog-is-real-possibilities-and-limitations-of-ai-assisted-angularjs-migrations)). The skill makes the agent *write modern Angular*; it does not make the diff *correct*. Keep the test gate non-negotiable.

On the **AI-code-review** side, the community model consolidated: **PR-Agent** — the original open-source PR reviewer — is now fully community-owned under Apache 2.0 after Qodo transferred it to [The-PR-Agent org](https://github.com/The-PR-Agent/pr-agent), with the managed Qodo service moving to a parallel multi-agent architecture (four specialists — bug/security/quality/test-coverage — in parallel). For a regulated review gate this matters: an OSS, self-hostable reviewer you can run inside the perimeter is a more defensible MRM artifact than a SaaS dependency. Newer entrant **[Nikita-Filonov/ai-review](https://github.com/Nikita-Filonov/ai-review)** adds a ReAct-style agent mode (the model explores the repo with shell commands before reviewing) and — usefully for a Spring-Boot shop on enterprise infra — supports Bitbucket Server and Azure DevOps, not just GitHub.

*(The MCP `2026-07-28` spec release candidate was covered 06-18 — note for accuracy: the RC actually froze May 21, final lands Jul 28; nothing new there today.)*

## 8. 🎯 One thing to try today (≤30 min)

**Wire Angular's official skills into one component migration and let the test gate catch what the skill can't.**

```bash
# 1. Update (picks up Claude Code v2.1.185):
npm update -g @anthropic-ai/claude-code   # expect 2.1.185

# 2. Add Angular's official Agent Skills to your migration repo:
git clone https://github.com/angular/skills ~/src/angular-skills
#    Reference its SKILL.md files from your .claude/ (or copy the relevant
#    skill into .claude/skills/) so Claude Code auto-loads modern-Angular
#    conventions when editing component files.

# 3. In an orchestrator session, prompt:
#    "Using the angular/skills modern-Angular skill, migrate
#     src/app/features/portfolio/portfolio-list.component from AngularJS
#     to a standalone Angular 18 component with signals + OnPush. Run the
#     existing Playwright spec as the gate; do not commit on red. Then
#     diff validation/behavior against the old component and report any
#     semantic differences you cannot prove are preserved."

# 4. The point of step 3's last sentence: the HeroDevs/Leonhardt lesson is
#    that "it compiles + tests pass" hides validation-semantics regressions.
#    Force the agent to argue behavior-preservation explicitly.
```

The payoff: a single migrated component done with first-party conventions instead of stale ones, plus a concrete read on whether the skill changes your per-component velocity enough to standardize on it.
