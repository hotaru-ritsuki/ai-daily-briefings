**Catch-up item: `/ship` and `/steward`** shipped in earlier builds (≥ 2.1.330, improved in 2.1.331) and haven't been covered here. They're documented [here](https://code.claude.com/docs/en/ship-command).
- 🆕⭐ **`/ship`** commits uncommitted work, pushes, opens the PR, runs `/code-review` (default effort `high`), and then starts a *watch*. A watch fixes failing checks, merges the base branch in, answers and resolves review threads, and re-requests review, all in auto mode without asking. **`/steward`** skips the review and starts the watch on a PR that's already open. **Why:** it closes the loop from finished change to green PR inside my local session. Requirements and limits:
  - It needs `gh` ≥ 2.63 and git ≥ 2.38.
  - No watch starts in `bypassPermissions` mode, on native Windows, or in background sessions.
  - A watch ends after 7 days, on merge or close, on `Esc`, on `/clear`, or if I change branches.
- ⚠️⭐ **Trust model:**
  - While Claude acts on its own, merge, approve, auto-merge and force-push commands are blocked.
  - Watch-time git commands run as `git -c core.hooksPath=/dev/null …` and outside the sandbox, so **my git hooks and `PreToolUse` hooks don't apply to them**.
  - An `ask` rule on `Bash(git push *)` doesn't match those commands. Only `Bash(git *)` does.
  - Code merged from the base branch, and anything in `.claude/skills/steward/SKILL.md`, runs with my credentials.
  - To turn the commands off: set `skillOverrides: {"ship-local":"off","steward":"off"}` or `CLAUDE_CODE_DISABLE_SHIP=1`.

**OpenAI Codex:** no new stable release since **0.172.0** (Nov 24, covered). Pre-releases 0.174.0-alpha.6 (Nov 25) and alpha.7 (Nov 26) came out [with no notes](https://github.com/openai/codex/releases).

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Claude Approvals policy as code.** The [policy reference](https://code.claude.com/docs/en/approvals-policy) is worth reading even if I never enable the hosted agent, because it's a careful design for "when may an agent approve":
  - Rules match `paths` and set a `verdict` of `{claude: approves|comments|blocks, seats: N}`.
  - An `override` can lower the requirement while a condition such as `"claude/code_review = pass"` holds.
  - The strictest applicable verdict wins.
  - Edits to protected files (the policy itself, `.claude/classifiers/`, `REVIEW.md`, `CODEOWNERS`) always need a person.
  - The docs say plainly that `CLAUDE.md`, `AGENTS.md`, `.mcp.json` and `.github/` are **not** protected by default, so write a rule for them.
  - Start with `mode: observe`, which is still billed.
- **Watch for this:** once `.claude/approvals.yml` is on the default branch, Code Review's automatic reviews **stop** on paths where no rule mentions `claude/code_review` ([Claude Ship docs](https://code.claude.com/docs/en/claude-ship)). Adding the policy can quietly reduce review coverage.
- **A2UI over MCP in Angular.** Manfred Steyer's [a2ui-over-mcp-demo](https://github.com/manfredsteyer/a2ui-over-mcp-demo) has an MCP server that ships a declarative A2UI template as a resource. An AG-UI middleware then renders the tool result as a native `@a2ui/angular` surface inside a CopilotKit chat. There's no iframe and no UI generated by the LLM. It's an alternative to HTML-based MCP Apps for Angular front ends.
- **Agent verification is moving toward "explore once, replay deterministically."** [Explore-Compile-Replay](https://github.com/pierridotite/explore-compile-replay) and [Journeys First](https://github.com/santorilabs/journeysfirst) both appeared this week (§5). Together with ui-diff and autologin-mcp from earlier in the week, they show where agent test verification is heading: agents explore, and plain tests replay what they found without a model.

## 5. 📦 Useful repos

1. **[santorilabs/journeysfirst](https://github.com/santorilabs/journeysfirst)** (MIT, new). It defines user journeys in plain YAML sentences (`users: [agent, teammate]`, `check:` steps) and runs them with a Playwright replay or an agent-driven runner that can also cover MCP journeys. Each run keeps a `run.json` with proof for every check. **Why I'd care:** it checks a change from every affected user's login, not just the one in the task. The authors report 3–4× higher build cost.
2. **[pierridotite/explore-compile-replay](https://github.com/pierridotite/explore-compile-replay)** (Apache-2.0, opened Nov 24). An agent explores the app once, the trace compiles to a plain test file, and that file replays in CI with no model. A repair step can change how a step finds its target but never weaken a check. **Why I'd care:** it's the right shape for Playwright, but the only real adapter so far targets Maestro (mobile), so for now it's a pattern and spec ("seven laws") to borrow from, not a tool to adopt.
3. **[Alessandro-Incantalupo/angular-agent-kit](https://github.com/Alessandro-Incantalupo/angular-agent-kit)** (MIT, new). It bundles a signal-first `modern-angular` skill based on angular.dev, a `migrate-to-signals` playbook, an `angular-reviewer` agent and a design-tokens MCP server with a `check_contrast` tool. It installs as a Claude Code plugin, a Copilot plugin or via APM. **Why I'd care:** it's built for my stack. It's a one-person project with no stars yet, so compare it with the official [angular/skills](https://github.com/angular/skills) before adopting it.
4. **[manfredsteyer/a2ui-over-mcp-demo](https://github.com/manfredsteyer/a2ui-over-mcp-demo)**. A runnable Angular + CopilotKit + MCP demo of native generative UI. **Why I'd care:** it's the cleanest reference I've seen for rendering MCP tool results as Angular components.

A local-first desktop agent team built on the pi kernel, with group chats, a coordinator bot, MCP, routines and approval gates. **Why I'd care:** it's an open-source reference for multi-agent coordination with an approval step on every risky action. ## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Migrating our Messages API to Rust](https://www.anthropic.com/research/migrating-api-to-rust)** (Anthropic Engineering, Nov 25, ~20 min).
  - The ~700 ported integration tests reached a 98% pass rate while matching only ~24% of shadowed production inputs, and an audit found 100+ weakened assertions.
  - The fix was differential shadowing: the model ran once and its output was replayed into both stacks. Diffs logged positions and lengths, not text, and were grouped by fingerprint.
  - It ran three loops: a sandbox loop under a second, a production-shadow loop over hours or days, and a "memory" loop that turned corrections into rules and tests.
  - Results: 99.6% match rate, ~70% less CPU per request and ~20% faster median time to first token.
  - Its key line: "Verification, not generation, had become the bottleneck."
- **[/ship and /steward docs](https://code.claude.com/docs/en/ship-command)** (Claude Code docs, ~15 min). It's reference material, but the "Decide where to run a watch" section is a candid threat model for an agent working with my credentials. It lists what's blocked, what can still lead to a merge, and why hooks don't fire. Read it before running an unattended PR agent of any kind.
- **[Claude Approvals policy reference](https://code.claude.com/docs/en/approvals-policy)** (~15 min). It's a worked design for who has to approve what, including subtle traps:
  - an `ANY` vs `ALL` mistake that lets one author relax a rule for everyone
  - `reuse` letting two earlier authors fill `seats: 2`
  - classifiers that never return an answer
  It's a useful pattern for any policy that gates AI-written code.
- **[Journeys First: results](https://github.com/santorilabs/journeysfirst/blob/main/docs/results.md)** (~8 min). Measured on small samples (3 and 6 runs), agents given journeys verified as every user role 3/3 times versus 1/3 without, and without journeys 2 of 6 one-prompt apps shipped unclickable. It's a vendor's own numbers, so treat them as indicative only.

## 8. 🎯 One thing to try today (≤30 min)

**Run `/ship` on a throwaway branch with guardrails, and read its `terms` before trusting it.**

```bash
claude update && gh --version   # need Claude Code ≥ 2.1.331, gh ≥ 2.63, git ≥ 2.38
cd ~/scratch/angular-sandbox && git switch -c try-ship
```

1. Make a small, real change, such as converting one `@Input()` to `input()`, and leave it uncommitted. Run `git status` first, because `/ship` commits *everything* that isn't caught by its secret-filename filter.
2. Make sure GitHub auto-merge is **off** for the repo. Then start `claude` in auto mode and type `/ship terms` to see what a watch may do.
3. Run `/ship medium`. Within a few seconds, you'll see an "Esc to cancel" line before the commit and again before the push.
4. Push a deliberately failing lint commit from the shell with `git push origin try-ship`, and see whether the watch fixes it. Then leave one PR comment and check how it replies.
5. Run `/tasks` to see the `/steward --tend` watch, then `/ship stop`.

**Pass criteria:** the PR goes green without me touching it, and I can say in one line whether its `/code-review` findings justify the token cost compared with running `/code-review` alone. Don't try this on a work repo until you've decided on a `Bash(git *)` ask rule.
