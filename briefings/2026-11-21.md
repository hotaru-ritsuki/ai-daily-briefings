## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[cospan](https://github.com/keli-wen/cospan)** (MIT, 40 ★, Nov 15): one async delegation protocol across Claude Code, Codex, Antigravity and DeepSeek Harness.
  - The host starts a detached session, checks on it later, then collects or resumes it. The README's examples: fan a review out to Codex models, or have Codex drive live browser tests while Claude writes code.
  - Install: add the marketplace, install the `cospan` plugin, restart. Needs Node 20+ and the target CLIs installed and signed in.
  - Limits: local only for now (SSH delegation is on the roadmap); plugin upgrades need a restart in both Claude Code and Codex.
- **GitLab's Claude Code setup skill** ([config post, Nov 18](https://about.gitlab.com/blog/recommended-config-for-agentic-engineering/); [workflow post, Nov 19](https://about.gitlab.com/blog/coding-agents-with-gitlab/)): copy `gitlab-duo-setup` and `gitlab-mr-followup` into `~/.claude/skills/` and run `/gitlab-duo-setup`. It uses `glab` to set up group flows, per-project automation and the MCP connection, so every merge request from an agent gets Duo review and failed-pipeline repair. Security triage needs Ultimate. Based on search excerpts; I couldn't open the posts.
- **[agent-crop](https://github.com/oriliz/agent-crop)** (MIT, 177 ★): local hooks/MCP that log tool success, turn time, waits and rework signals (repeated edits, retries) to `~/.agentcrop/data`, and have the agent file a retrospective from a fixed list of nine causes. The author's example: adding one missing skill page cut a 10-minute task to 30 seconds. Claude Code steps are in `docs/INSTALL.md`; the README admits the thresholds aren't calibrated yet.

- **[The recommended GitLab configuration for agentic engineering](https://about.gitlab.com/blog/recommended-config-for-agentic-engineering/)** plus **[The best way to use your coding agents with GitLab](https://about.gitlab.com/blog/coding-agents-with-gitlab/)** (GitLab, Nov 18–19, ~15 min together). - **[Coding agents made us faster, but the software factory made us ship](https://superplane.com/blog/coding-agents-made-us-faster-software-factory-made-us-ship/)** (SuperPlane, Nov 17, ~8 min). More parallel agents didn't mean more merged PRs until they added clear task boundaries, a shared brief and a failure policy per agent. From search excerpts only.
- **["Rethinking Verification in Agent Harnesses"](https://arxiv.org/abs/2610.34577)** (arXiv, Oct, ~30 min; not covered here before). Splits verification into four layers: instructions, after-edit reminders, completion gates, and an independent critic in a fresh context that treats the agent's success claims as a hypothesis. It finds completion gates give the biggest gains at a significant cost. That's the mechanism behind the `verify`-skill idea from yesterday.
- **Background for §8:** [Nick Nisi (WorkOS), "How I deleted 95% of my agent skills"](https://ai.engineer/talks/pruning-agent-skills) (AI Engineer Europe, May; [written summary](https://paulund.co.uk/notebook/ai/measure-your-agent-skills-or-delete-them)). In an A/B eval, one auto-generated skill dropped accuracy from 97% to 77%. Swapping ~10k generated lines for 553 handwritten gotchas fixed it and cut eval time from 68 to 6 minutes. Older, but it's the method I'm using today.

## 8. 🎯 One thing to try today (≤30 min)

**A/B test one of your own skills: same prompt, with and without it, scored by a deterministic check.**

```bash
claude update && claude --version          # expect 2.1.330
npx @abiramcodes/angular-doctor@latest     # baseline score for the repo
git worktree add ../ab-with  -b ab-with
git worktree add ../ab-without -b ab-without
rm -rf ../ab-without/.claude/skills/<your-angular-skill>
```

```bash
PROMPT='Convert src/app/<feature>/<component> to signals and OnPush; keep tests green.'
for d in ../ab-with ../ab-without; do
  for i in 1 2 3; do
    (cd "$d" && git checkout -q . && claude -p "$PROMPT" --permission-mode acceptEdits >/dev/null \
      && npx -y @abiramcodes/angular-doctor@latest | tail -1 \
      && npx ng test --watch=false >/dev/null && echo "$d run $i: tests pass" || echo "$d run $i: FAIL")
  done
done
```

1. Pick a skill you wrote from docs, not one you wrote from your own mistakes. Those are the ones Nisi found hurting.
2. Compare doctor score and pass rate over 3 runs each. Three runs is noisy, so you're looking for a big gap, not a 1-point one.
3. **Delete or shrink the skill if "without" ties or wins.** If it wins, cut it down to the gotchas only and run again.
