## 3. 📋 AI coding tool changelogs (since the 2026-11-19 briefing)

**Claude Code 2.1.329** (Nov 19, [docs changelog](https://code.claude.com/docs/en/changelog) and [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). ~90 fixes; the ones that matter to me:

- ⭐ 🔧 **`/code-review` targets the right diff:** no-target reviews the full branch vs. default branch (multi-commit diffs were being lost); `<pr>` and PR URLs use `gh pr diff` and stop if it fails; it no longer stalls on a permission prompt looking for a missing `~/.claude/CLAUDE.md`. **Why:** I run it before every push.
- ⭐ ⚠️ **Code Mode PreToolUse hooks that error now let the call through**, matching non-Code-Mode behaviour. Any hook that must refuse needs `"onFailure": "block"`.
- ⭐ 🆕 **Trust dialog now says where a folder's hooks are declared.** **Why:** directly addresses the "cloned repo runs hooks" class of attack covered on Nov 17.
- ⭐ 🆕 **`/tasks` now lists scheduled tasks, `/loop` wakeups, the goal and forks**, and can stop them; header shows one combined background count.
- ⭐ ⚠️ **Saved scheduled tasks from earlier versions mostly need re-scheduling** in new sessions. Re-check anything you set up with `/loop` or the scheduler.
- ⭐ 🆕 **`/mcp` shows a remote server's JSON-RPC error message** when it refuses the connection; HTTP MCP servers on an older protocol reconnect themselves; MCP-served PDFs/images sent as `application/octet-stream` are no longer saved as `.bin`.
- 🐛 **`~/.claude.json` could be reset to defaults** after a network stall or file lock during save. Fixed.
- 🐛 **`/sandbox` on Linux** no longer claims `allowUnixSockets` entries are allowed (they aren't).
- 🐛 **Agent teams:** the Agent tool's `effort` parameter was ignored for named teammates.
- 🚫 **Removed 2.1.326's auto-retry on `max_tokens` errors**; behind a gateway, set `CLAUDE_CODE_MAX_OUTPUT_TOKENS`.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[harness-profiler](https://github.com/afurmanov/harness-profiler)** (MIT, Nov 15): records every skill, subagent and tool call via hooks and renders a sequence diagram where each bar is a *context*, with tokens spent per context.
  - Answers "did my `validator` subagent actually run, and what did it cost?" for skill/subagent pipelines.
  - Install: `/plugin marketplace add afurmanov/harness-profiler`; for cloud sessions, `npx -y github:afurmanov/harness-profiler init claude` commits the hook to `.claude/settings.json`.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)** (Addy Osmani, claude.dev, Nov 16, ~12 min). Per [triage notes](https://github.com/steveash/hitchhikers-guide-to-ai-native-engineering/issues/4824) and [Addy's thread](https://x.com/addyosmani/status/2122590683055993308): a `verify` skill per repo that runs the app; e2e, property and differential tests (old vs. new during migrations); three repair rounds then a human; flaky tests are fixed or deleted with a recorded reason; review rules come from `REVIEW.md` on the base branch; reviews are bound to a commit; a commit gate (starting in observe mode) blocks commits that skipped `/verify` or `/code-review`. I couldn't open the original (host blocked), so specifics come from secondary summaries that agree.
- **[Using a "chaos loop" to harden the Claude Docs launch](https://claude.dev/blog/chaos-loop-claude-docs-launch/)** (claude.dev, Nov 17, ~15 min). A coordinator ran ~11 (peak ~30) subagents for about two weeks against staging: pick a fault scenario, run load, read Datadog via MCP, ship a fix, repeat, checking two invariants every iteration. Irreversible changes (schema, storage layout) needed human approval. Reported: ~60 server errors across ~2B requests, ~$125k inference at list price ([notes](https://github.com/steveash/hitchhikers-guide-to-ai-native-engineering/issues/4825)). First-party and expensive, but the "invariants + telemetry + human gate on irreversible changes" structure is the takeaway.
- **[Build once, run on any agent: a practical guide to agent skills](https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/)** (GitHub Blog, Nov 12, ~10 min). Its review example runs a verifier in Actions that sees the request and the diff but *not* the coding agent's self-assessment, returning PASS/FAIL/PARTIAL. Same independence idea as the Claude Code post, from the Copilot side.

## 8. 🎯 One thing to try today (≤30 min)

**Write a project `verify` skill using the Claude Code team's rules, then profile it.**

```bash
claude update && claude --version     # expect 2.1.329
mkdir -p .claude/skills/verify && $EDITOR .claude/skills/verify/SKILL.md
```

```markdown
---
name: verify
description: Run before every commit. Boots the Angular app and backend, drives the changed flow in a real browser, and reports evidence.
---
1. Start the Spring Boot API and `ng serve` as background tasks; wait for health checks.
2. For the routes/components in the current diff, run the matching Playwright specs; if none exist, drive the flow with Playwright and take screenshots.
3. If a check fails, fix and re-run. After 3 failed rounds, STOP and report to me with the evidence.
4. Never skip a test, add waits/sleeps, or retry a flaky test until green. Find the root cause or report it.
5. Report: what ran, pass/fail, screenshot paths.
```

1. Run `/verify` on a branch with a real UI change; then run `/code-review` (now the whole branch) and compare what each caught.
2. Install the profiler (`/plugin marketplace add afurmanov/harness-profiler`, then `/plugin install harness-profiler@harness-profiler`) and run `/harness-profiler:show-profile` to see what `/verify` cost.
3. Optional: put review rules in a `REVIEW.md` on `main`, not in the feature branch.

**Keep it if** the skill catches one thing the unit tests didn't, at a token cost you'd pay on every commit.

## 9. 📣 Shareable angle

**Hook:** "If your AI code reviewer reads its rules from the PR branch, the PR can rewrite its own reviewer."

**Draft:** The Claude Code team reads review rules from the base branch, stops an agent after three failed fix rounds, and bans retrying flaky tests until green. None of that needs a better model; it's plain CI hygiene applied to agents, and I'm adding all three to my Angular repo this week.
