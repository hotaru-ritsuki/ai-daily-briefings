## 4. 🛠️ Claude Code & MCP ecosystem (community side)

- **[humanlayer/advanced-context-engineering-for-coding-agents](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents)** ([ace-fca.md](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)) is the standout: a written-down methodology for *frequent intentional compaction* — keep the working context lean by having the agent research, then write a durable plan/spec file, then implement against it, compacting aggressively between phases. It's the practitioner complement to the "your MCP output is eating your context" tooling (context-mode, codebase-memory-mcp) covered earlier.
- **[dvcrn/mcp-server-subagent](https://github.com/dvcrn/mcp-server-subagent)** — an MCP server letting a "planning" agent delegate scoped tasks to "executor" agents (Claude Code, Aider, Q) with *bi-directional* comms, so a subagent can ask its parent a clarifying question mid-run. A cleaner primitive than fan-out-and-forget if you hand-roll planner/executor splits.
- **[colbymchenry/codegraph](https://github.com/colbymchenry/codegraph)** — pre-indexed local code knowledge graph that cuts per-turn token use; same deterministic-retrieval family as graphify, worth a side-by-side on an Angular/Spring monorepo.
- **[bradagi/awesome-cli-coding-agents](https://github.com/bradagi/awesome-cli-coding-agents)** — a curated directory of terminal-native coding agents and the harnesses (parallel runners, autonomous loops) that orchestrate them; a good map when you're deciding what to put opposite CC in an openrig-style two-seat setup.

## 8. 🎯 One thing to try today (≤30 min)

Apply HumanLayer's **intentional compaction** loop to one real CC task instead of one long sprawling session:

```bash
git clone https://github.com/humanlayer/advanced-context-engineering-for-coding-agents
# read ace-fca.md, then on a real task:
# 1) ask CC to RESEARCH only and write findings to notes/research.md
# 2) /clear, feed research.md, ask it to write a PLAN to notes/plan.md
# 3) /clear, feed plan.md, let it IMPLEMENT against the plan
```

The point is the `/clear` between phases: each stage starts with a lean, purpose-built context (a file you reviewed) instead of a 120k-token transcript. Try it on a Playwright test + the fix it covers and compare token use / drift against your usual single-session run.
