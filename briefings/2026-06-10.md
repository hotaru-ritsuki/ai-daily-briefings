## 4. 🛠️ Claude Code & MCP ecosystem (community side, deep dive)

**The Fable 5 system-card controversy is the Claude-Code-side story, not just the model story.** Per [Simon Willison's June 10 read of the 319-page card](https://simonwillison.net/2026/Jun/10/if-claude-fable-stops-helping-you/), the *silent* interventions on frontier-LLM-development requests are the new debugging primitive every long-running session has to account for: **a degraded answer might be model limitation, missing context, *or* an unlogged policy downgrade, and you can't tell which from the transcript**. For a financial-services migration that's mostly off the affected surface, but the operational implication generalises — when Fable 5 behaves oddly on an Angular signal-conversion task, the new triage is "rerun the same prompt on Opus 4.8 and diff the diffs", which is structurally the same move as v2.1.169's `--safe-mode` for harness/customisation isolation. The combined diagnostic table is now: `--safe-mode` for harness, Opus 4.8 rerun for silent-downgrade, `/cd` for context-preserving worktree hops.

**The Stripe 50M-line Ruby migration case study is the practical anchor for Fable 5 on the migration use case** ([Lightning AI summary](https://aiweekly.co/alerts/anthropic-fable-5-runs-stripe-migration-in-one-day), [Octopus Review counterweight](https://octopus-review.ai/blog/fable-5-rewrites-50m-lines-in-a-day-who-reviews-it)). Anthropic's framing: one day for what the team had estimated at two months. The unanswered question — flagged by Octopus Review and worth taking seriously — is **who reviews 50M lines of generated diff**. The pattern that actually scales is the Thariq 9-category "product verification" skill (06-08): the run is fast, the *verification* is the bottleneck. For my AngularJS → Angular 18 sweep this maps to: Fable 5 as the per-feature migrator, the Playwright Healer skill (06-08 §8) as the verification gate, the orchestrator session holding `goal.md` between hops via v2.1.169's `/cd`. The Stripe number is a ceiling reference for "what's possible on a single tightly-typed codebase with a clear migration spec" — not a forecast for an AngularJS codebase with implicit `$scope` semantics.

**Spiral 4.0 (Every, June 4, updated June 9) goes "agent-native" via MCP + CLI + API** ([Every announcement](https://every.to/on-every/spiral-4-0-goes-agent-native), [writewithspiral.com](https://writewithspiral.com/)). Direct relevance for me is narrow (it's a writing tool), but the architectural pattern is the one Dan Shipper has been telegraphing: **the new feature surface for SaaS isn't a UI button, it's an MCP server endpoint your agent can call**. Pricing moved from sessions to tokens; personal plan dropped to $15/mo. The Spiral MCP server is a reference for what a "drop into a writing-quality skill" wrapper looks like, useful if you ever want a Claude Code skill that hands off PR-description writing to a voice-conditioned model instead of letting Claude default to its own register.

**Anthropic Swift Foundation Models package** ([docs](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/apple-foundation-models)) — Claude as a server-side language model conforming to Apple's `LanguageModel` protocol, drivable from `LanguageModelSession`. Same architectural shape as the Spring AI MCP server starter (06-07) and the Kotlin/C# client SDKs (06-08): Anthropic is filling in the native-SDK matrix one ecosystem at a time. Not stack-relevant for me, but worth pinning the pattern.

## 8. 🎯 One thing to try today (≤30 min)

**Update Claude Code to v2.1.170 and run a Fable-5-vs-Opus-4.8 bake-off on a single AngularJS → Angular 18 feature module while it's still free on your Pro/Max subscription.** The June 22 window is the only chance to get a calibrated read on whether Fable is worth 2× the Opus rate on your specific migration pattern before the cost-per-run becomes real.

```bash
# 1. Update + verify:
npm update -g @anthropic-ai/claude-code && claude --version   # expect 2.1.170

# 2. Confirm Fable 5 is visible in the picker (signed-in subscription required):
claude /model                                                  # expect "claude-fable-5" in the list

# 3. Bake-off on a single feature module. Use git worktrees so you can diff cleanly:
git worktree add ../wt-fable    -b migrate/portfolio-fable    HEAD
git worktree add ../wt-opus     -b migrate/portfolio-opus     HEAD

# Run A — Fable 5:
cd ../wt-fable
claude --model claude-fable-5 -p \
  "Port src/app/features/portfolio from AngularJS to Angular 18 signals. \
   Use the verify-feature-migration skill (06-08) as the gate. \
   Surface any test failures via additionalContext; do not auto-commit."

# Run B — Opus 4.8 (control):
cd ../wt-opus
claude --model claude-opus-4-8 -p \
  "Port src/app/features/portfolio from AngularJS to Angular 18 signals. \
   Use the verify-feature-migration skill (06-08) as the gate. \
   Surface any test failures via additionalContext; do not auto-commit."

# 4. Diff the two ports + the Healer outputs:
git -C ../wt-fable diff --stat main..HEAD
git -C ../wt-opus  diff --stat main..HEAD
diff -ru ../wt-fable/src/app/features/portfolio ../wt-opus/src/app/features/portfolio

# 5. Calibrate against the silent-degradation risk (§4):
#    Fable 5's degradation surface is "frontier LLM development" requests.
#    AngularJS porting is well outside that surface, so if the diffs diverge
#    sharply in quality, treat that as a real capability delta, not a hidden
#    safeguard. (If the *task* touched LLM training infra, the trace would
#    be ambiguous — the diagnostic table from §4 applies.)
```

The 12-day free window is the closest thing to a free A/B trial Anthropic has ever offered on a flagship; spending one of those days on the migration's actual hot path is the highest-value thing on this list.
