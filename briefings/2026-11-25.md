# AI Engineering Briefing — 2026-11-25

## 1. 🔥 Top 3 things I shouldn't miss today

- **⚡ [Skills over MCP is live in Claude and Claude Code](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more) (public beta, Nov 24), and Tasks and Elicitation are now GA.** An MCP server can now ship `SKILL.md` playbooks alongside its tools; they update when the server updates and load only when needed. **Why:** the GitHub MCP Server's 19 bundled skills ([covered Nov 23](2026-11-23.md)) now reach my Claude Code sessions directly. It also opens a new attack surface: a server can change its skills at any time (§2, §4, §8).
- **⚡ [Claude Code 2.1.332](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) (Nov 25) is the client side of that launch.** It adds MCP skills as `server:skill` commands and a `PreSkillShellCommand` hook that can refuse a skill's inline shell commands. It also fixes about 90 bugs, several of them MCP hangs. **Why:** the new hook and `Skill(mcp__<server>__*)` permission rules are how I control what a server's skills can run (§3).
- **[shrink-anything](https://github.com/EL4CTEO/shrink-anything) (MIT, ~216 ★, Nov 23) deletes dead code, files and dependencies, runs my own test command after every cut, and puts back any cut that breaks it.** It runs as a CLI, a Claude Code plugin or an MCP server. **Why:** agent-written Angular code builds up unused services and exports, and less code means fewer tokens the agent reads on the next task (§5).

## 3. 📋 AI coding tool changelogs (since the 2026-11-24 briefing)

**Claude Code 2.1.332** ([CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [docs changelog](https://code.claude.com/docs/en/changelog) dated Nov 25)
- 🆕⭐ **Skills from MCP servers (beta)** show up in `/` and `/skills` as `server:skill`. **Why:** typing `/github:pull-request-code-review` replaces copying GitHub's skill files into `~/.claude/skills`. The [docs](https://code.claude.com/docs/en/mcp#use-skills-from-mcp-servers) list several important limits:
  - They are not supported in `claude -p`, the Agent SDK, cloud sessions, GitHub Actions, on Bedrock, Vertex or Foundry, or behind a custom `ANTHROPIC_BASE_URL`.
  - **In auto mode, the classifier decides whether to load a skill without reading it.**
  - Skills from servers you add with `claude mcp add` are not scanned by Anthropic.
- 🆕⭐ **`PreSkillShellCommand` hook** can refuse a skill's or command's inline shell commands as it loads. **Why:** it's the enforcement point for skills I didn't write. Watch out: on 2.1.331 and older, a settings file that names this hook opens a dialog at startup.
- 🔧⭐ **Model alias changes:** `sonnet` now means Sonnet 5.5 on Google's Agent Platform and Foundry, and `opus` means Opus 5.5 on Foundry. The Foundry default is now Sonnet 5.5. `--model default` now falls back to an older model instead of erroring. **Why:** a shared `settings.json` used on Vertex now picks a different model.
- 🔧 The `/permissions` dialog now rejects rules that would be skipped at the next start. Memory use is lower at startup with large MCP tool lists. Recovery is better after 413 errors behind gateways.
- 🐛⭐ **MCP fixes:** SSE servers no longer hang after their stream drops. A local server flooding stdout no longer freezes the terminal. Task IDs up to 1,024 characters now work. CLAUDE.md is no longer sent twice after entering a `.claude/worktrees` worktree. Reading a `.env` named pipe now fails after 20 s instead of hanging. Code Mode subagents no longer stall on scripts longer than 10 minutes.
- ⚠️ The desktop Code tab's OTel `service.name` is now `claude-code-desktop`. `computer-use` is now a reserved skill name on Macs. Self-hosted runner OAuth tokens may now start with `oat02-`, so update any log scrubbers that match `oat01-`.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Which servers serve skills today.** The [implementations list](https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/implementations.md) is the practical directory:
  - **GitHub MCP Server** (opt-in `--features=skills`, filtered to your enabled toolsets)
  - Cloudflare (hosted, serves `cloudflare/skills`)
  - Hugging Face (HTTP only)
  - Langfuse (its `migrate-to-langfuse` skill)
  - Google MCP Toolbox v1.16.0
  - Context7 (merged, not yet released)
  - In progress: Next.js's `next-mcp`, Azure MCP and Mapbox.
  **Pattern worth copying:** Capgo also exposes the same skills as ordinary tools for clients that lack the extension.
- **Design notes for server authors** (from [the rationale](https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/rationale.md)):
  - Skills are Resources at `skill://<prefix>/<name>/SKILL.md`, not a new primitive, so supporting files keep their directory layout.
  - `skills/list` may be partial or empty, and clients must not take an empty list as proof that a server has no skills.
  - `skills/get` exists to return content digests, so a host can check a skill it reached by URI against what the server published.
- **Locking it down:** per [the docs](https://code.claude.com/docs/en/mcp#set-rules-for-a-servers-skills), `deny` or `ask` on `Skill(mcp__<server>__*)` blocks a server's skills or prompts on every load, and an `ask` rule applies **even in auto and bypass modes**. Also deny `ReadMcpResourceTool` to block reading supporting files.
- **[Lodestar](https://github.com/chipfighter/lodestar)** (MIT, ~36 ★) is a Claude Code plugin that asks at your first message which named skill set the session should load, then hides every other skill until the session ends. Subagents can get their own set. Choosing at the first message means the prompt cache stays intact. Install with `/plugin install skill-loadout --marketplace chipfighter/lodestar`. It matters more now that MCP servers add skills to the `/` menu without me installing anything.
- **[swarmy](https://github.com/koorchik/swarmy)** (~47 ★) is a read-only terminal dashboard for live Claude Code, Codex and Antigravity agents. It shows context fill, spend, weekly-limit burn per project, and a warning when two sessions edit the same worktree. `J` jumps to a pane that's waiting on a prompt.

## 8. 🎯 One thing to try today (≤30 min)

**Use the GitHub MCP Server's bundled skills as native Claude Code commands, with a guard on them first.**

```bash
claude update            # need ≥ 2.1.332 (MCP skills need ≥ 2.1.331)
claude mcp add github -e GITHUB_PERSONAL_ACCESS_TOKEN=$GH_PAT -- \
  docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server stdio --features=skills
```

1. Before starting, add `"ask": ["Skill(mcp__github__*)"]` to `~/.claude/settings.json`. Every load then prompts, even in auto mode, because this server's skills aren't scanned.
2. Start `claude` in an Angular repo with an open PR, type `/`, and check that `github:pull-request-code-review` and `github:pull-request-review-feedback` appear. Run `claude --debug=mcp` if they don't.
3. Run `/github:pull-request-code-review <PR#>` and compare its output with built-in `/code-review` on the same branch. Which one catches more real bugs, and which one batches line comments better?
4. Optional: add a `PreSkillShellCommand` hook that logs, and blocks, any `curl`/`wget` in skill-inlined shell.
5. **Pass criteria:** the skills show up, each load asks for approval, and you have a one-line verdict on whether GitHub's review skill is worth keeping next to `/code-review`.

This won't work in `claude -p`, the Agent SDK or cloud sessions, or with Bedrock or Vertex auth. Try it in a local terminal or the JetBrains terminal.
