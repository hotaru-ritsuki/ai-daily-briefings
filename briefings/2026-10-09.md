## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

The standout is **[anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins)** (Apache-2.0). It's Anthropic's open library of role-based plugins — reports vary between ~11 and 20+ (engineering, data, product, sales, support, legal, finance, HR, ops, design). Each plugin bundles three things worth copying into your own setup: **skills** (domain knowledge Claude auto-invokes), **slash commands** (e.g. `/data:write-query`, `/sales:call-prep`), and **connectors** (MCP integrations to CRM/analytics/PM tools). It's pure Markdown + JSON — no compiled code — so it doubles as a canonical example of plugin layout. Install via `claude plugin marketplace add anthropics/knowledge-work-plugins` then `claude plugin install engineering@knowledge-work-plugins` ([write-up](https://www.aibuilderclub.com/blog/claude-code-plugins-official-library-2026)).

On the **context/token side**, two threads are converging:
- **[headroom](https://github.com/headroomlabs-ai/headroom)** (Apache-2.0, Python/TS) compresses tool outputs, logs and RAG chunks reversibly before the model reads them — type-specific compressors (JSON/AST/prose) plus a `CacheAligner` that stabilises prefixes so provider KV caches still hit. Four deployment modes: library (`compress(messages)`), proxy (`headroom proxy`), agent wrapper (`headroom wrap <agent>`), and an **MCP server** exposing `headroom_compress`/`headroom_retrieve`/`headroom_stats`. Claimed savings are payload-dependent (big for repetitive JSON, ~15–20% for code) — verify on your own traces, not the README.
- **Agent memory** keeps trending: [mem0](https://github.com/mem0ai/mem0), [cognee](https://github.com/topoteretes/cognee), and last week's [claude-mem](https://github.com/thedotmack/claude-mem) all aim at the same "sessions forget everything" gap. Nothing architecturally new this week, but the cluster is clearly where community energy is.

Caveat: today's trending digest ([agents-radar #402](https://github.com/kouweizhu/agents-radar/issues/402)) reports star counts that are internally inconsistent and implausibly high (e.g. 275k for a new harness) — treat all star numbers below as directional only.

### 6a. AI workflows & patterns

- **[Advanced Context Engineering for Coding Agents](https://www.humanlayer.dev/blog/advanced-context-engineering)** (HumanLayer) — argues subagents are a *context-control* tool, not role-play; fresh-window search + summarization is the real win. **Takeaway:** stop anthropomorphizing agents; design for what the orchestrator *never* sees. ~10 min.
- **[Subagents Are Context Engineering](https://www.decodingai.com/p/subagents-are-context-engineering)** (Decoding AI) — a subagent = one scoped task returning a compressed ~1–2k-token report after spending tens of thousands exploring. **Takeaway:** the economics (big spend → tiny return) are the whole point of fan-out. ~8 min.
- **[How to write a good spec for AI agents](https://addyosmani.com/blog/good-spec/)** (Addy Osmani) — the spec drives implementation, tests and task breakdown; don't code until it's validated, and have the agent self-check against it. **Takeaway:** a reusable spec-template beats re-prompting. ~9 min.
- **[Rethinking Code Review in the Age of AI: Agentic Code Review](https://arxiv.org/pdf/2605.17548)** (arXiv, vision paper) — as agents raise code volume, review becomes the bottleneck; reviewers shift from inspectors to *supervisors of review agents*. **Takeaway:** sober framing for where your PR-review workflow is heading. ~15 min.

### 6b. General AI engineering reading

- **[The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)** (Armin Ronacher) — agent-driven code still needs human comprehension; the loop removes the shared-work friction team scaling relied on. Older (Jun) but the clearest statement of the comprehension-debt problem. ~12 min.
