- 🆕 ⭐ **`sandbox.credentials` setting** blocks sandboxed commands from reading credential files / secret env vars. The literal control you want documented for a fintech headless run — secrets stay out of agent-shell reach. (§8)
- 🆕 ⭐ **Org-configured model restrictions** enforced across the model picker, `--model`, `/model`, and `ANTHROPIC_MODEL`, with a "restricted by your organization's settings" message. Centralized model governance — pin the org to approved models instead of trusting per-dev config.

- 🐛 **Structured-output fix:** the model can no longer re-call `StructuredOutput` indefinitely after success, and `--resume` no longer fails with "No conversation found" when the original `-p` run produced no model turns — both matter for `-p`/`--json-schema` cron jobs (like this briefing).
- 🔧 **`/install-github-app`** now lets you install just the App and skip the Actions workflow/secret steps; subagent depth tracking fixed (resumed/forked subagents restore spawn depth and count toward the cap); leaked agent worktree registrations auto-cleaned.

## 4. 🛠️ Claude Code & MCP ecosystem

- **MCP 2026-07-28 Release Candidate is the big community-side story.** Beyond the headline stateless core, two pieces change how I'd build servers: **MCP Apps (SEP-1865)** ship interactive HTML in a sandboxed iframe with UI templates declared ahead of time so hosts prefetch/security-review them, and every UI action routes back through the same JSON-RPC consent/audit path as a tool call; the **Tasks extension** lets a server answer `tools/call` with a *task handle* driven by `tasks/get` / `tasks/update` / `tasks/cancel` ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), [MCP.Directory explainer](https://mcp.directory/blog/mcp-2026-07-28-release-candidate)). The Tasks model is the clean primitive for long-running migration jobs that currently fake async with polling. Tier-1 SDK support is expected within the ten-week window.
- **Claude Tag for Slack (Jun 23)** — Anthropic shipped a **multiplayer** `@Claude` that joins a Slack workspace as one shared teammate with its own identity, memory, and admin-scoped tool access; it decomposes tagged tasks, works asynchronously, and (if "ambient" is on) proactively flags stale threads ([Anthropic](https://www.anthropic.com/news/introducing-claude-tag), [TechCrunch](https://techcrunch.com/2026/06/23/anthropics-claude-tag-is-learning-your-company-one-slack-message-at-a-time/)). It **replaces the old Claude-in-Slack app** (admins have 30 days to opt in). Anthropic claims **65% of its product team's code is now created by an internal version**. Enterprise/Team beta — worth piloting against a triage channel, but note the memory-across-channels surface is a data-governance review item in a regulated shop.
- **Context-engineering tooling keeps maturing.** HumanLayer's [`advanced-context-engineering-for-coding-agents`](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents) (~1.7k★) packages **Frequent Intentional Compaction** — target 40–60% context utilization by structuring work into `research_codebase.md` → `create_plan.md` → `implement_plan.md` phases, each producing a compacted artifact a fresh context can reload (validated on 100k–300k LOC codebases). This is the discipline that makes a months-long migration survive context resets (§8).

## 8. 🎯 One thing to try today (≤30 min)

**Run the FIC research→plan loop on one un-migrated component** — context engineering made concrete, in a throwaway worktree:

```bash
git worktree add ../fic-test HEAD && cd ../fic-test
git clone --depth 1 https://github.com/humanlayer/advanced-context-engineering-for-coding-agents /tmp/ace
cp /tmp/ace/*.md .claude/commands/ 2>/dev/null || mkdir -p prompts && cp /tmp/ace/*.md prompts/
claude -p "Using research_codebase.md as the template, produce research.md for the next \
un-migrated AngularJS component in TODO.md — map its dependencies, services, and tests. \
Write ONLY research.md. Do not change any code." --permission-mode plan
```

Then start a **fresh** `claude` session and feed it `research.md` + `create_plan.md` to produce `plan.md`. The point: each phase writes a compacted artifact so the implementation context starts at ~40% utilization instead of 80%. Watch whether the plan stays coherent across the reset — that tells you if your component boundaries are clean enough for unattended migration. Bonus: add `sandbox.credentials` to `.claude/settings.json` (§3) so the run can't read repo secrets.
