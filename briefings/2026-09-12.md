## 3. 📋 AI coding tool changelogs

**Claude Code** ([changelog](https://code.claude.com/docs/en/changelog)) — **v2.1.269 (Sep 11)**, new since the last briefing (v2.1.268):

- **⭐ 🆕 `claude plugin eval`** — run a plugin's eval suite against Claude Code for scored, reproducible results (JSON + HTML report). *Why it matters:* this is skill/plugin hygiene with data behind it — regression-gate a skill in CI instead of noticing in a live session that it stopped firing. See §8.
- **🆕 `/output-style [name]`** — list and switch output styles, including over Remote Control and in cloud/headless sessions. Useful for my scheduled/headless runs.
- **⭐ 🔧 Bash-edit diff** — when the Bash tool makes file edits, the result now includes a diff of the changed files (`bashEditDiffEnabled`). *Why:* much better visibility when an agent mutates files via shell instead of the Edit tool.
- **🔧 `OTEL_METRICS_INCLUDE_REPOSITORY`** — tags OTel metrics/events with `vcs.*` repo attributes (commit events get `vcs.ref.head.*`). Per-repo cost/usage attribution for telemetry dashboards.
- **🆕 `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` (1–256)** — raise the Workflow tool's per-run concurrent-agent cap for inference-bound fan-outs. ⭐ if you run wide subagent orchestration.

## 4. 🛠️ Claude Code & MCP ecosystem (community side)

The week's center of gravity is the **community forming around plugin evals**, arriving the same day the feature shipped:

- The eval suite lives in `evals/` inside your plugin; each case is a subdirectory with a `prompt.md` and a `graders/` folder. There are **6 grader types** (regex over the reply, "was this tool called", LLM-as-judge rubric, etc.), a **no-plugin baseline** so you can prove the plugin actually changes behavior, and a `--threshold` for CI gating ([MarkTechPost](https://www.marktechpost.com/2026/09/11/anthropic-adds-plugin-evals-to-claude-code-6-grader-types-a-no-plugin-baseline-and-a-ci-gate-for-skills/), [docs](https://code.claude.com/docs/en/plugin-evals)).
- Authoring help is already appearing as skills — e.g. a [`plugin-eval-authoring-interview`](https://skills.rest/skill/plugin-eval-authoring-interview) skill that interviews you to generate a suite, and community `eval-harness` skills. Expect `evals/` folders to start showing up in shared plugin repos the way `README`s do.
- **Token-efficiency as a plugin:** [`ashlrai/ashlr-plugin`](https://github.com/ashlrai/ashlr-plugin) (MIT) replaces Read/Grep/Edit with compressed, head+tail-truncated, provider-budget-aware versions via [`ashlr-core-efficiency`](https://github.com/ashlrai/ashlr-core-efficiency). Self-reported −57% tokens; verify on your own repo before trusting the number.
- **Orchestration vocabulary worth having straight:** subagents (single session, report-only) vs. agent teams (separate sessions that debate via a shared task list) vs. Fleet mode (one orchestrator spawns tens–hundreds in parallel waves) — clean taxonomy in [The Prompt Shelf](https://thepromptshelf.dev/blog/claude-code-multi-agent-orchestration-patterns-2026/) and [explainx](https://explainx.ai/blog/claude-code-subagents-multi-agent-workflows-2026). Maps onto §3's new concurrency cap.

## 8. 🎯 One thing to try today (≤30 min)

**CI-gate one of your `.claude/` skills.** Update, then let Claude Code write the first eval suite for you:

```bash
claude update
cd your-plugin-or-skills-repo
claude plugin eval init        # interviews you, proposes cases + graders, writes evals/
claude plugin eval . --report ./eval-report.html --threshold 0.8 --runs 5
```

Open `eval-report.html`, and crucially check the **no-plugin baseline** row — if your skill scores the same with and without it, the skill isn't earning its context and should be cut. ([docs](https://code.claude.com/docs/en/plugin-evals))
