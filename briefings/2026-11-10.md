## 2. 🤖 Frontier model & platform news
- **Anthropic: Fable 5.2 and Mythos 5.2** ([announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2), [model docs](https://platform.claude.com/docs/en/models/fable-5-2/overview), [CNBC](https://www.cnbc.com/2026/11/09/anthropic-claude-fable-5-2-mythos-5-2.html)). Both are one underlying model. Fable 5.2 is the generally available version with cyber and bio safeguards, and Mythos 5.2 is gated behind the verification programs.
  - **Specs:** 1M context, 128K output, Jun 2026 knowledge cutoff, and $0.20/Mtok cache reads (2.5% of input). Fast mode costs $16/$80.
  - **Benchmarks (vendor-reported, mostly at highest effort):** FrontierCode 2.0 49.1% at Xhigh, OSWorld 2.1 89.3%. Anthropic says "Fable High ≈ Opus 5.5 Max at about half the cost per task." I couldn't find any independent evals yet.
  - **API breaking points** from the [migration guide](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide):
    - The preserved-thinking prefix check now applies to every account, so editing earlier turns returns a 400.
    - `computer_20251124` returns a 400 everywhere except Bedrock. Use `computer_toolset_20260801` instead.
    - An advisor tool paired with a Fable 5.2 executor must also be Fable 5.2 or Mythos 5.2.
    - 30-day data retention is required, so the model isn't available under ZDR.
  - **Early hands-on reports are mixed.** One creator test had Fable 5.2 finish a build in 1h57m for $81, against Opus 5.5's 3h11m for $46 ([BigGo summary of creator/Every-podcast tests](https://finance.biggo.com/news/c2056226ea22b68e)), and another reviewer said it struggled with rigid specs. These are single anecdotes.

## 3. 📋 AI coding tool changelogs (since 2026-11-09 briefing)
### Claude Code
- **2.1.321 (Nov 9)**
  - ⭐ 🆕 **Fable 5.2 (`claude-fable-5-2`) is now the default Fable model.** Saved Fable 5.1 picks move to `fable` (Pro/Max right away; Team/Enterprise once the org allows it). `/model claude-fable-5-1` switches back.
  - ⭐ 🐛 **Security fixes:**
    - MCP OAuth no longer sends refresh tokens to another host when a server redirects.
    - A read-only Bash command could run outside the sandbox with no prompt. Fixed.
    - Deny rules now apply to the target file of `cp`/`mv` into a directory. `/bin/cp` and `/bin/mv` get the same path checks.
  - ⭐ ⚠️ **Mods' own `$.tool.call`/`$.mcp.call` calls raise no permission prompt**, even under your ask rules. Deny rules and org policy still apply. Mods that Claude writes turn on without asking in auto and bypass modes. If you allow mods, audit your deny rules.
  - 🔧 Nested `.claude/skills` folders inside `~/.claude/plugins` no longer load. Headless sessions hot-reload mods in `.claude/skills` (`CLAUDE_CODE_PLUGIN_DIR_WATCH=0` turns it off).
  - ⭐ 🐛 **MCP reliability:**
    - A server could show as "connected" with no tools after a reconnect. Fixed.
    - `PreToolUse` `mcp_tool` hooks were skipped on answers over 16 MiB. The call is now refused instead.
    - A null stored MCP sign-in record left `claude mcp list` empty. Fixed.
  - 🐛 Fixed: project skills, commands and agents vanished after `git stash` or entering a worktree.
  - 🐛 Fixed: `claude agents` ignored `--model`, `--effort` and similar flags placed before the subcommand.
  - 🔧 Background command output over 1,000 characters is trimmed to its start and end, which saves context.
  - 🆕 `claude remote-control --settings <file>`.
  - Plus ~60 smaller fixes: Windows PATH, Remote Control, gateway, screen reader.
- **2.1.322 (Nov 10)** 🆕: Fast mode on Vertex (global, us and eu regions) is now available, falling back to standard speed when Vertex refuses it.

## 4. 🛠️ Claude Code & MCP ecosystem (community)
- **Your `.claude/` config is now the thing to tune.** The Fable 5.2 prompting guide says the model delegates "readily" in harnesses whose prompts invite it. It also says the model spawns review subagents of its own at xhigh and max. Any line in `.claude/agents/*.md` or CLAUDE.md that says "use subagents for X" is now a cost lever. Anthropic's tested fix is a subagent tool description that puts cost first. It reports about a third less delegation with the same task success.
- **MCP design worth copying: [homeassistant-ai/ha-mcp](https://github.com/homeassistant-ai/ha-mcp)** (6.2k★, MIT). Ignore the domain and look at the patterns:
  - Its 87 tools are split into read, write and delete proxies, so clients can auto-approve reads and confirm deletes.
  - A `/readonly` URL suffix restricts a connection to read-only tools with the same credential.
  - An optional BM25 "search catalog" mode shows small-context models only a few tools, while pinned tools stay visible.
  - Skills are served as `skill://` MCP resources.

  That's a good blueprint for an internal Spring Boot MCP server built on Spring AI RC2.
- **Memory as MCP: [garrytan/gbrain](https://github.com/garrytan/gbrain)** (32k★, MIT). It's a self-hosted agent memory backed by PGLite or Postgres+pgvector.
  - `gbrain setup claude-code` registers the MCP server and hooks and writes "brain-first" instructions.
  - It stores facts with their sources and supports corrections.
  - Compare it with claude-mem before adopting either. Also note the guide's warning that accumulated cautious notes make Fable 5.2 timid (§6a).
- **Official dynamic-workflow example.** [anthropics/claude-quickstarts](https://github.com/anthropics/claude-quickstarts/commits/main) (+551★ today) rebuilt its knowledge-wiki quickstart on a dynamic workflow (#534, Nov 6) and added a Sentry-autofix Managed Agents quickstart (#487). Both are reference code for orchestrating subagents with a script rather than turn by turn.

## 6. 📰 Articles & essays
### 6a. AI workflows & patterns
- **["Prompting Claude Fable 5.2"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2)** (Anthropic docs, Nov 9, ~15 min). Its key points are measured, not just claimed:
  - "Answer directly" lines no longer stop thinking, so use effort instead.
  - The sentence "This codebase is yours…" raised dedup-refactoring from under 10% of tries to about 50%, at 1.5× the tokens and with unrequested changes.
  - A "finish the whole task" block halved early stops.
  - Accumulated "never retry" notes measurably suppress retries.
- **["Fable 5.2 migration guide"](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide)** (Anthropic docs, ~10 min). Read the behaviour-changes section even if you never touch the API. A small `max_tokens` can now end a turn in thinking before any text arrives. If you build your own `messages` array, plan to keep the history append-only.
- **[Fable 5.2 announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2)** (Anthropic, ~8 min). The useful parts for workflow design are the engineering anecdotes: over 90% of merged changes in Anthropic's core codebase are written by Claude, a Python→Rust service migration, and an OS prototype built with more than 1,000 coordinated subagents. They describe how Anthropic itself runs agents, but treat them as marketing until reproduced.

## 8. 🎯 One thing to try today (≤30 min)
**Run an effort and ownership A/B of Fable 5.2 in Claude Code on one real Angular task.**
1. Update the CLI: `claude update`, then confirm `claude --version` shows ≥ 2.1.321.
2. In a clean worktree, run `claude --model claude-fable-5-2` and pick a task with some duplication, for example *"Add a status filter to `OrdersListComponent` (PrimeNG `p-table`), wire it through the NgRx selector, update the specs, run `npx ng test --watch=false`."*
3. Run it three ways and reset between runs with `git checkout . && git clean -fd`:
   - (a) `/effort medium`, prompt as-is.
   - (b) `/effort high`, prompt as-is.
   - (c) `/effort medium` with *"This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it."* prepended.
4. Record `/usage` cost, time, test result and `git diff --stat` for each. Check whether (c) merged duplicate selector or filter code, and whether it touched anything you didn't ask for.
5. While you wait, `grep -rn "subagent\|delegate" .claude/ CLAUDE.md` and flag any standing "always delegate" lines to trim.

**Success criteria:** a measured default effort for daily Angular work, and a decision on whether the ownership line belongs in your CLAUDE.md (it suits greenfield modules better than shared legacy code).
