## 3. 📋 AI coding tool changelogs (since the 2026-11-18 briefing)

**Claude Code 2.1.328** (Nov 19, on both the [docs changelog](https://code.claude.com/docs/en/changelog) and [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). The release has about 90 fixes; these are the ones relevant to my setup:

- ⭐ ⚠️ **`/code-review` reports only bugs** and CLAUDE.md violations, with severity tags and a suggested fix. `/simplify` covers cleanups. **Why:** two commands, two jobs. Run `/code-review` before pushing and `/simplify` when you want a refactor pass.
- ⭐ 🆕 **`mcp_tool` hooks accept `"onFailure": "block"`**, the same as command and HTTP hooks. **Why:** a policy check that runs through an MCP server, such as a Jira ticket gate, can now fail closed.
- ⭐ ⚠️ **Code Mode no longer runs UserPromptSubmit hooks on script output**, including managed ones. Redact with a PostToolUse hook and `updatedToolOutput` instead.
- ⭐ 🔧 **Code Mode got a lot of work:**
  - It's faster: a 0.75s pause after most scripts is gone.
  - Tool descriptions are shorter, so it uses fewer tokens.
  - It shows a script's command and output while the script runs.
  - It tells Claude where a failed edit came closest to matching.
  - Dev servers now start as background tasks that show up in `/tasks`.
  - About a dozen fixes for resumed sessions.
- ⭐ 🐛 **MCP:** tools whose schema starts with `anyOf`/`oneOf`/`allOf` no longer go missing when telemetry is off. A tool with an invalid schema is now left out, with the reason given, instead of failing the request.
- 🐛 **Scheduled tasks:** saving one can no longer wipe the project's other saved tasks, and a typo no longer deletes a task.
- 🐛 **zsh:** words starting with `=`, such as `echo ====` or `[ a == b ]`, no longer fail with "not found".
- 🐛 **Compaction:** automatic compaction now rebuilds the system prompt the way `/compact` does.
- 🔧 **Agent teams:** starting several in-process teammates at once now rarely fails with "Lock file is already being held".
- 🆕 **Auto mode** is now available for Opus 4.6 and Sonnet 4.6 on Bedrock, Agent Platform and Foundry. It doesn't matter to me unless I'm working through an enterprise gateway.
- 🔧 **Self-hosted runner:** about 25 changes, including `--repository-folder`, `--hook-label`, `--metadata` and new orchestrator metrics.

**OpenAI Codex** ([Releases](https://github.com/openai/codex/releases)): **no new stable release since 0.170.0** (covered yesterday). Only `0.171.0-alpha.13` and `0.172.0-alpha.1` are new, and neither has notes.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[pstack](https://github.com/cursor/plugins/tree/main/pstack)** (MIT), Lauren Tan's plugin:
  - **Contents:** about 30 skills and 24 principles. `/poteto-mode` routes each task to one of 22 playbooks (bug fix, perf, refactor, ship…). There's also `/interrogate` for finding flaws in a diff, `/arena` and `/swarm` for parallel attempts, `/tdd` and `/create-verification-skill`, plus two subagents, `poteto-agent` and `comment-sicko`, a read-only comment reviewer.
  - **Claude Code support:** an adapter renames the commands to `/pstack:*` and skips features that only exist in Cursor.
  - **Updates:** auto-update is off for third-party marketplaces, so update it by hand.
- **[pulsar](https://github.com/yocontra/pulsar)** (MIT, Nov 17): an MCP server that puts every local agent on one message bus: Claude Code, Codex, OpenCode, Cursor, Gemini CLI and pi.
  - **Tags:** agents tag themselves automatically with harness, model, branch, worktree and PR, and you can address them by selector (`pr=1402 role=reviewer`).
  - **Waking agents:** a message can wake an idle agent.
  - **Install:** one line, `npx pulsar setup`, but that writes into each harness's config, so diff your `.claude/` and `~/.codex` afterwards.
- **[cache-maxxing](https://github.com/5m0k3/cache-maxxing)** (MIT, v0.4.0): a Claude Code plugin that shows a prompt-cache countdown and what your next message will cost, before you send it.
  - `/cmaxx-handoff` writes a summary and starts a fresh chat when the current one has become too expensive to continue.
  - The "up to 80×" quota claim is the author's own and I haven't checked it, but the cache-expiry countdown is the useful part on its own.
- **[git-twig](https://github.com/leostera/git-twig)** (Rust, v0.5.0): creates copy-on-write git worktrees for agents, using up to 97% less disk, and ships a skill (`git twig skill`).
  - **Filesystems:** native CoW only works on APFS and Btrfs/XFS with reflink. On ext4 it falls back to plain `git worktree`.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **["Code is memory": Lauren Tan at AIE Code Summit](https://github.com/The-Focus-AI/ai-engineer-code-2026-nov/blob/main/talks/2026-11-11-all-code-is-slop-except-mine/story.md)** (Nov 11 talk, write-up marked draft, ~12 min):
  - Agents copy whatever is already in the codebase, so keep it clean.
  - Ban anything that needs nuance: `useEffect` is only allowed inside framework APIs, and lint rules block imports across layers.
  - Delete 99% of comments.
  - Review screenshots, videos, TLA+ models and property-based UI tests instead of reading diffs.
  - Her warning: "don't automate a bad loop."
  - Timestamps cite the transcript, which garbles some terms.
- **[pstack's principles and playbooks](https://github.com/cursor/plugins/tree/main/pstack)** (~10 min): the talk turned into 24 rules ("prove it works", "fix root causes") and routing logic. Worth reading for its structure even if you never install it.
- **[OpenAI on new ways of working with Codex](https://latent.space/p/codex-work/)** (Latent Space, summit write-up, ~8 min): Codex Cloud lets you publish an environment once and run many tasks in isolated copies of it, and voice is pitched as a way to delegate work. It's a vendor workshop, so read it for the patterns, not for claims of capability.

### 6b. General AI engineering reading

- **Daniel Stenberg on agents porting curl to Rust** (quoted by [Simon Willison](https://simonwillison.net/2026/Nov/18/daniel-stenberg/), Nov 18; [digest](https://dev.to/magnus_ferm/dev-news-digest-17-nov-2026-1800-2i13)):

## 8. 🎯 One thing to try today (≤30 min)

**Turn your last three agent corrections into deterministic checks with pstack.**

```bash
claude update && claude --version     # expect 2.1.328
# in an Angular/NgRx repo, inside Claude Code:
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
/pstack:create-verification-skill
```

1. **Pick three corrections:** go through recent sessions and note three things you corrected Claude on more than once, such as "no `subscribe` inside effects", "always use `takeUntilDestroyed`", or "no PrimeNG imports in `core/`".
2. **Ask for enforcement, not prose:** feed them to `/pstack:create-verification-skill` and ask for ESLint rules, a dependency-cruiser config or a test, with error messages that tell the agent the fix. Don't accept a CLAUDE.md rule.
3. **Delete the old rules:** remove the matching rules from CLAUDE.md.
4. **Compare the two reviewers:** run the new `/code-review` on a branch that breaks one rule, then `/simplify`, and note which one catches what.

**Keep it if** the lint errors alone get the agent to fix the code without you stepping in.
