## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[One Success Isn't Reliability: ThinkingBox](https://arxiv.org/abs/2608.19741)** (Microsoft, arXiv) — the methodology paper behind §1's bench: grade agents on committed state, run 20×, report pass^20 not pass@1. Makes the case that most agent "success" is survivorship bias. *~15 min.*
- **[Fast and Hard Code](https://lucumr.pocoo.org/2026/8/22/fast-hard-code/)** — Armin Ronacher on why, once an agent can rewrite a service in a language you don't know, people pick Rust/Zig for the *artifact* (small, fast binary) rather than for familiarity. Sharp on where human comprehension still has to live. *~8 min.*
- **[How Coding Agents Fail Their Users](https://arxiv.org/pdf/2605.29442)** — large-scale analysis of 20,574 real developer-agent sessions cataloguing concrete misalignment failure modes. First-hand-data grounding for anyone designing review gates. *~20 min.*
- **[Spec-Driven Development in 2026: how teams actually use it](https://dev.to/krlz/spec-driven-development-in-2026-what-it-is-the-tooling-and-how-teams-actually-use-it-2fk2)** — practical taxonomy across Spec Kit / Kiro / OpenSpec, with a usable heuristic: write the spec only if you'd be annoyed by a misinterpretation; skip it if a follow-up prompt would fix the output. *~10 min.*

### 6b. General AI engineering reading

- **[Anthropic — Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)** — the initializer-agent-plus-incremental-coding-agent pattern (set up the env once, leave clean artifacts for the next session). Good frame for multi-session migration jobs. *~12 min.*

## 8. 🎯 One thing to try today (≤30 min)

**Update Claude Code, then curate `/model` and read your loop costs.** Given how much I fan out, the new v2.1.243 knobs are worth wiring in now:

```bash
claude update   # land ≥ v2.1.246 (also picks up the telemetry API-key-leak fix)
```

Then in `~/.claude/settings.json`, curate the model list and set a subagent cache TTL:

```json
{
  "modelPicker": ["claude-opus-4-8", "claude-sonnet-5", "claude-haiku-4-5-20251001"],
  "subagentPromptCacheTtl": "1h"
}
```

Run `/usage` and open the new **Loops breakdown** to see tokens-per-run per loop — that's the number that tells you which fan-out is actually expensive. Five minutes to configure, and it turns "subagents feel pricey" into a measured line item.

## 9. 📣 Shareable angle

**Hook:** "Your agent passed the demo. Did it pass it 20 times?"

> Microsoft's new ThinkingBox benchmark grades agents on what they actually changed in the database, not what they claim — and the best model drops from 65% pass@1 to ~25% pass^20. If you're shipping agents into production workflows, single-run success is survivorship bias; reliability is a pass^k problem, and eval-driven gates are how you find out before your users do.
