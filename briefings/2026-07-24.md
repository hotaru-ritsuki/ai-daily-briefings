## 8. 🎯 One thing to try today (≤30 min)

**Generate agent-optimized docs for one legacy AngularJS module with OpenWiki** — give your coding agent real context about the code it's migrating *from*, instead of making it re-derive it every session.

```bash
npx @langchain/openwiki --path ./src/legacy/<one-module> --update
```

1. Point it at a single self-contained AngularJS feature (one module/service cluster), not the whole app.
2. Review the generated wiki — especially the Mermaid sequence/state diagrams — for whether it captured the real control flow and NgRx-relevant data lifecycles.
3. In a fresh Claude Code session, feed that wiki as context and ask for the Angular 18 migration of that module. Compare against a cold run with no wiki.

If the diagrams are accurate, this becomes a standing pre-migration step (and the docs double as review material for the Angular side). Payoff: reusable context, not a one-off. *(Confirm the exact package/flag from the [README](https://github.com/langchain-ai/openwiki) — CLI surface may differ.)*
