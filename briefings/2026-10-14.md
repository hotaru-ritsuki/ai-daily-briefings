### Claude Code — [2.1.299 (Oct 14)](https://code.claude.com/docs/en/changelog)
(Page showed no 2.1.297/2.1.298 entries; I could only read the first ~100K of a ~1M-char page.)
- 🆕 ⭐ **MCP protocol 2026-07-28 default for cloud/Remote Control connectors**; opt out with `MCP_PROTOCOL_NEGOTIATION=legacy`. Matters because the revision is stateless (no initialize handshake/session IDs) and breaking for some servers.
- 🔧 ⭐ **MCP allow rules now match only the named server** (`mcp__<server>__*`) — re-check your permission allowlists for over/under-matching.
- 🆕 ⭐ **Idle compaction** for >200K-token terminal sessions (`"idleCompaction": false` or `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` to tune) — cheaper resumes, but context shifts under you after a break.
- 🆕 `CLAUDE_CODE_DISABLE_FILE_MENTIONS`: `@file` passes paths instead of contents — useful for keeping context lean.
- 🔧 ⭐ **`UserPromptSubmit` hooks now run before skill/custom-command expansion** — may alter existing hook behavior.
- 🔧 Plugin hooks that can't answer an action are refused rather than allowed (fail-closed); plugin (mod) API gains `$.prompt.media`, `$.session.identity()`, extra `skill.prompt` hook fields.
- 🆕 `/effort` and `/fast` in agent view; `--disallow-tools` for `claude plugin eval`; `/usage` warns on max effort, workflows, always-on context and large tool results; `--shutdown-drain-sec` for self-hosted runner orchestrator.
- 🐛 ⭐ Fixed: macOS sandboxed commands reaching denied paths through symlinks; Windows hooks failing open without Git for Windows; MCP HTTP connections hanging 30s on never-ending notification replies; `/usage` showing >100%; scheduled tasks announced for the wrong minute.
- 🔧 Resume command at exit now prints session ID rather than name.

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **MCP goes stateless.** Write-ups agree on the shape of the [2026-07-28 revision](https://appwrite.io/blog/post/mcp-goes-stateless-in-the-2026-07-28-specification): no initialize handshake or `Mcp-Session-Id`, multi round-trip requests (MRTR) replace held-open streams for elicitation/sampling, `Mcp-Method`/`Mcp-Name` headers for gateway routing, cacheable list results, OAuth hardening, an extensions framework and a deprecation policy. The [official C# SDK v2.0](https://devblogs.microsoft.com/dotnet/announcing-v20-of-the-official-mcp-csharp-sdk/) already implements it; TS/Python/Go SDK updates reportedly shipped alongside (single-source claim — verify in each SDK's release notes). The spec is from July; the new development is Claude Code defaulting to it today.
- **Delegation MCPs:** the search surfaced unverified-date projects such as claude-opencode-mcp (Claude Code delegating tasks to OpenCode agents with a shared worktree, 7 tools) and Claude Octopus (multi-agent MCP over the Agent SDK). I couldn't confirm dates or quality; treat as leads, not recommendations.

## 8. 🎯 One thing to try today (≤30 min)

**Check your MCP servers against the stateless spec and your allowlists against 2.1.299.**
1. `claude update && claude --version` (expect 2.1.299).
2. Run one of your MCP-dependent workflows via a cloud/Remote Control session; if it breaks, retry with `MCP_PROTOCOL_NEGOTIATION=legacy` to confirm the cause is protocol negotiation.
3. In `.claude/settings.json`, grep for `mcp__` allow rules and confirm each matches only the intended server (`grep -rn "mcp__" .claude/ ~/.claude/settings.json`).
4. Add `"idleCompaction": false` temporarily if you prefer to compare behavior on a long session.
