## 4. 🛠️ Claude Code & MCP ecosystem (community)

**Pattern emerging: two-file migration harnesses (`goal.md` + `<DomainMigration>.md`) → checked-in `.claude/skills/`.** Leonhardt's post is the most legible public example. The split is the interesting bit: `goal.md` is *protocol* (how the loop runs, when to abort, how to branch); `SignalMigration.md` is *substrate knowledge* (validator mapping, import paths, verification commands the agent runs to claim "done"). The protocol file changes rarely; the substrate file is the team's accumulated migration tax-knowledge. With v2.1.157's `.claude/skills/` auto-load, that split now lives next to the code, not in someone's dotfiles. This is the missing piece between Anthropic's harness essays and the [HeroDevs "Slog is Real" reality check](https://www.herodevs.com/blog-posts/the-slog-is-real-possibilities-and-limitations-of-ai-assisted-angularjs-migrations) (covered 05-27): *checked-in protocol* is the leverage point both pieces gesture at without quite naming.

**Routine + dynamic workflow composition is starting to show up in community write-ups.** The cleanest framing so far is [Vikas Sah's "Claude Code Routines Aren't a Feature. They're a Deployment Target"](https://engineeratheart.medium.com/claude-code-routines-arent-a-feature-they-re-a-deployment-target-66a888f99945) — a Routine is the *trigger and the artifact*, the dynamic workflow is the *execution*. For the migration pipeline: a nightly Routine that fires a dynamic workflow against one `src/app/features/<X>/` directory and opens a PR is the lowest-friction way to test the Bun-style pattern without a heavyweight CI integration.

**Marketplace growth, soft signal:** [claudemarketplaces.com](https://claudemarketplaces.com/) directory updated May 30 (200K monthly visitors per their data); [travisvn/awesome-claude-skills](https://github.com/travisvn/awesome-claude-skills) and [ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills) both seeing weekly additions. The discovery surface for skills is now mature enough to be your first stop before authoring — but the per-stack work (Angular, Spring Boot, NgRx) still won't be there.

## 8. 🎯 One thing to try today

**Mirror Leonhardt's two-file harness into a `.claude/skills/angular-modernize/` and dry-run it against one migrated component.** Quiet release day = the right window for this.

```bash
# Confirm Claude Code at 2.1.158 (no upgrade needed if you ran the 05-30 step)
claude --version

# In the migration repo root:
claude plugin init angular-modernize
# This scaffolds .claude/skills/angular-modernize/SKILL.md (auto-loads thanks to v2.1.157)

# Edit SKILL.md so the `description:` is a list of trigger conditions
# (not a behavior summary) — per Anthropic's skill-creator finding (cf. 05-25).

# Add two more files alongside SKILL.md:
#   goal.md            — orchestration protocol: startup sequence, branch strategy,
#                        sub-agent loop shape, abort criteria.
#   AngularMigration.md — substrate: deprecated patterns → modern equivalents,
#                         import path mappings, verification commands
#                         (ng build, the Playwright suite, NgRx selectors check).

git add .claude/skills/angular-modernize
git commit -m "skill: angular-modernize (goal + substrate split)"
```

Then in a session: *"Using the angular-modernize skill, migrate `src/app/features/<smallest-one>/` to standalone signal-based components. Cap at 5 subagents. Abort if `ng build` fails three times for the same reason."* The point is not the migration — it's verifying that the **`goal.md` discipline actually constrains the run** before you stake a real sprint on it. The signal is whether the agent aborts when it should. ~25 min.

Reference template: read [Leonhardt's full piece](https://dev.to/lutz_leonhardt/i-used-ai-agents-to-migrate-44-angular-components-the-review-changed-my-mind-4pop) for the Signal Forms version of the substrate file before authoring yours.
