## 3. 📋 AI coding tool changelogs

Cutoff = last briefing (09-10: CC **v2.1.267**, Codex **0.154.0** stable). Both sources fetched directly and reachable.

**Claude Code** ([docs changelog](https://code.claude.com/docs/en/changelog)) — one very large release:

- **v2.1.268 (Sep 10)** — headline day-to-day changes:
  - ⚠️⭐ **Task-tracking tools removed by default on newer models.** `TodoWrite`/`TaskCreate/Get/Update/List` are offered only on Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6, Haiku 4.5; elsewhere set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. On your default (Opus 4.8 / Fable 5.1 / Opus 5) there's now no scratchpad todo tool unless you re-enable it — a real behavior shift for any subagent/skill that relied on one.
  - 🐛⭐ **HTTP 400 regression fixed** on third-party Anthropic-compatible endpoints (`ANTHROPIC_BASE_URL`) — every turn had failed since 2.1.265 due to a regex in the Artifact tool's schema those endpoints reject. Relevant if you route CC through a gateway/proxy.
  - 🐛⭐ **MCP secret hygiene:** `/mcp`, `/plugin`, `claude mcp list/get` and MCP login errors no longer print secrets from `${VAR}` placeholders; plugin/marketplace errors no longer leak a token embedded in a git source URL.
  - 🐛⭐ **Permission/sandbox hardening:** deny/ask rules on symlinked dirs (`/etc`, `/tmp`, `/var`, `/bin`) now apply via the real path; Read/Edit deny rules apply even with an `env -C`/`eval` command on the same line; a respawned in-process teammate no longer inherits tools/prompt from a same-named agent file in an untrusted folder.
  - 🔧⭐ **`/plugin` install/enable/disable takes effect on closing the menu** — no `/reload-plugins` needed.
  - 🔧 **WebFetch now fails after 300s** on a never-finishing server (`CLAUDE_CODE_WEBFETCH_DEADLINE_MS` to override); Bedrock/Vertex/Foundry keep the tool list byte-stable + deliver env details as attachments (cache-correctness theme); a CPU busy-loop in long idle sessions is fixed; [Code Review] resolving a finding's **thread** (not just replying) is what now stops later reviews counting it open.

## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **The to-do-tools removal is a design signal, not just a toggle.** Alongside the recent context-engineering guidance (let the model judge; strip the scaffolding), Anthropic is betting the newest models **self-track** across a long turn and that a dedicated todo tool now costs more context than it earns. For you: your subagent fan-outs get a slightly leaner tool block for free, but any skill/command whose prompt says "update your todo list" is now a no-op on Opus 4.8/Fable 5.1. Grep your `.claude/` for `todo`/`TodoWrite`, and either re-enable via `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` or move that state into a `task_plan.md` re-injected by a `UserPromptSubmit` hook — no built-in tool needed.
- **Secret hygiene moved into the tools themselves.** v2.1.268's redaction across `/mcp`, `/plugin`, `claude mcp list/get` (plus the git-URL-credential and symlink-permission fixes) means MCP configs pulling tokens from `${VAR}` no longer echo them into your terminal or error logs — the practical unlock for wiring authenticated MCP servers (JetBrains, GitHub, a DB server) into a session you might screen-share. The whole release reads as a security-hardening pass, not a feature drop.
- **Worth a read for MCP server authors:** the [new MCP roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/) formalizes the stateless direction (the 2026-07-28 spec removed the stateful handshake that made early servers hard to scale) — the shape of what clients will expect, relevant right after CC's v2.1.267 reconnect/cache fixes.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Agentic Engineering Patterns](https://simonw.substack.com/p/agentic-engineering-patterns)** — Simon Willison. His recurring finding across every workflow that actually ships: the agent needs **a validation mechanism it can run itself** (tests, a type-check, a self-graded eval) — the loop closes only when the model can check its own output without you. The single most transferable heuristic for wiring an agent into CI. *~9 min.* *(Flag: simonwillison.net and simonw.substack.com are egress-blocked this run; sourced from search summaries — read the primary yourself.)*
- **[The New MCP Roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)** — MCP steering group (primary). Where the protocol is heading after the 2026-07-28 spec dropped the stateful handshake: statelessness, scale, and what clients will expect from servers. Read it if you author or run an MCP server — it's the design constraint behind CC's recent reconnect/cache fixes. *~8 min.*
- **[Armin Ronacher on The Coming Loop, and why agent-driven code still needs human comprehension](https://www.developersdigest.tech/blog/armin-ronacher-coming-loop-agent-comprehension)** — Developers Digest interview. The comprehension-debt argument: the bottleneck is shifting from writing code to *understanding* code you didn't write, and why that caps how much you can safely delegate to an unattended loop. Good counterweight to the "3.1 agent-workdays" optimism from OpenAI's numbers (covered 09-10). *~10 min.*
- **[awesome-evals `PATTERNS.md`](https://github.com/benchflow-ai/awesome-evals)** — BenchFlow. Not an essay but reads like one: worked, runnable examples for LLM-as-judge, pass@k, trajectory grading, and CI gating. The concrete companion to Willison's "self-runnable validation" point above. *~15 min to skim.*

## 8. 🎯 One thing to try today (≤30 min)

**Lift one LLM-as-judge pattern from `awesome-evals` into a real eval for something you actually ship.** Start:

```bash
git clone https://github.com/benchflow-ai/awesome-evals
cd awesome-evals && $EDITOR PATTERNS.md      # jump to the LLM-as-judge + CI-gating sections
```

Pick one deterministic-output task from your stack — e.g. a **Handlebars→PDF** render or an **NgRx reducer migration diff** — and write a 20-line judge: a rubric prompt + a pass/fail assertion your CI can run. The point isn't a full eval suite; it's to feel the loop Willison describes (§6a) — give the agent a check it can run itself, then let a subagent iterate against it. **Housekeeping while you're at it:** after `claude update` to v2.1.268, if any of your skills/commands assume a todo list, either re-enable with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` or move that state into a `task_plan.md` (§4).
