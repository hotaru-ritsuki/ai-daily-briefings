## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Introducing FrontierCode](https://www.latent.space/p/ainews-frontiercode-benchmarking)** (Cognition, via Latent Space AINews) — a coding benchmark of 150 maintainer-built tasks (Main 100 / Diamond 50) graded on regression safety, cleanliness, scope, test correctness and maintainability; Opus 4.8 leads at ~34.3% Main but only 13.8% on Diamond. *~10 min. The clearest articulation yet of "passes tests ≠ mergeable," and a ready-made rubric for reviewing agent diffs.*
- **[Evals Skills for Coding Agents](https://hamel.dev/blog/posts/evals-skills/)** (Hamel Husain) — point your coding agent at *building the evals*: it instruments the app, runs experiments, analyses results. *~12 min. The most concrete "eval-driven dev in your own repo" recipe I've found; March but evergreen.*
- **[SlopCodeBench: How Coding Agents Degrade Over Long-Horizon Iterative Tasks](https://arxiv.org/html/2603.24755v1)** — measures the quality decay that shows up over many iterative edits, not single patches. *~20 min skim. Directly relevant to unattended multi-step migration runs where late edits quietly rot.*
- **[The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)** (Armin Ronacher) — the tension between letting agents loop autonomously and keeping the human comprehension that makes code maintainable. *~9 min. The sharpest framing of the review-vs-velocity tradeoff I feel on parallel agent work; June, but it keeps being the reference.*
- **[A Survey of Development Workflows in the Coding Agent Era](https://nyosegawa.com/en/posts/coding-agent-workflow-2026/)** (Sakasegawa) — a practitioner taxonomy of how people actually structure work around coding agents. *~11 min. A map to diff my own CC + IntelliJ ACP loop against.*

### 6b. General AI engineering reading

Then connect it to a local server, walk each tool's schema, fire a real call, and confirm nothing broke under the stateless spec. *Bonus (~10 min more):* copy FrontierCode's grading dimensions — regression safety, cleanliness, scope, maintainability — into a project `/code-review` prompt and run it against your last migration diff to see which ones your agent's output actually fails.

## 9. 📣 Shareable angle

**Hook:** "Your coding agent's PR passes CI. Would you actually merge it?"
**Draft:** Cognition's new FrontierCode benchmark stops rewarding code that merely passes tests and starts grading regression safety, scope, and maintainability — the stuff that decides whether a human hits approve. The lesson for anyone running coding agents: your acceptance gate should score *mergeability*, not correctness, because the models that top the old benchmarks routinely ship patches maintainers reject.
