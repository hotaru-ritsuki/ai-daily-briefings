## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[angular/skills](https://github.com/angular/skills)**: the official one, published from `skills/dev-skills/` in `angular/angular`.
  - `angular-developer` covers signals, `linkedSignal`, `resource`/`httpResource`, DI, forms, routing, SSR/hydration, a11y and testing. Its first rule is "analyze the project's Angular version first".
  - The README targets Gemini CLI and Antigravity, but these are plain `SKILL.md` folders. `npx skills add https://github.com/angular/skills` works, or copy `angular-developer/` into `.claude/skills/`.
  - It pairs with the CLI's built-in MCP server (`npx -y @angular/cli mcp`, with a read-only mode). The skill gives guidance; the MCP server builds and runs tests.
- **[skill-distill](https://github.com/sybil-solutions/skill-distill)**: the teacher (Claude Code/Codex) reads the session log and writes a skill. It then starts a student (omp, pi, Codex, Claude Code or opencode plus a model) on a fresh copy of the starting state with only the original prompt and that skill. It finds the first place the student went wrong and patches the skill there.
  - Rules worth copying even if I never use the tool: **three trials per version** ("one lucky run proves nothing"); **test the checks on the reference first**; the skill may not contain the finished output.
  - Raw session logs stay in a git-ignored `runs/` because they contain local paths. The README marks the omp adapter "tested"; the other adapters are less proven.
- **[fast-anything](https://github.com/EL4CTEO/fast-anything)** (MIT, 327 ★, Nov 21): a Claude Code plugin and MCP server that profiles an app and ranks functions by time and how easy they are to port. It has the agent port only the hot ones to Rust, then **replays up to 500 recorded real calls** plus generated edge cases (NaN, -0.0, non-ASCII, 16× inputs) before switching to the port. It supports `mvn exec:java` and Node/TS. The point for me is the verification method (record real calls, replay them, then switch), which carries over to any agent-written port.
- **[gridlines](https://github.com/pritamux/gridlines)** (MIT, 116 ★): an alignment-pass skill. A Playwright probe measures the edges of text and icons, draws guide lines and lists every element that misses one (e.g. `MISS y88 leading: 15px vs 12px`), then the agent fixes the padding. It's a measurable "done" check for sidebar/table layout work instead of "looks fine to me".

## 8. 🎯 One thing to try today (≤30 min)

**Run ui-diff on a real Angular UI branch and see whether its comment catches what you'd catch in review.**

```bash
git clone https://github.com/imuratalpay/ui-diff.git ~/src/ui-diff
~/src/ui-diff/install.sh --claude
alias ui-diff='node ~/src/ui-diff/skills/ui-diff/bin/ui-diff.mjs'
cd ~/src/<angular-app> && git checkout <branch-with-a-PrimeNG-or-SCSS-change>
ui-diff init
```

1. Edit `ui-diff.config.json`. Set `"startCommand": "npx ng serve --port {port}"`, raise `startTimeoutMs` (ng serve is slow), and map routes by hand, since Angular routing isn't auto-detected: `{ "path": "/orders", "files": ["src/app/orders/**"] }`. Put `src/styles/**` and your PrimeNG theme files in `globalFiles`.
2. Mask anything with live data or animation (`"capture": { "mask": [".p-toast", "[data-live]"] }`).
3. Run `ui-diff check`. Nothing gets posted. Open `.ui-diff/comment.local.md` and `.ui-diff/compare/`.
4. **Pass criteria:** it flags the change you know about, with no false diffs on untouched routes. If base and head differ on a page you didn't touch, the capture isn't deterministic yet. Fix that before letting an agent rely on it.
5. If it passes, add one line to the repo's `CLAUDE.md`: "For UI changes, run `ui-diff check` and attach the summary to the PR." Then try `ui-diff publish --pr <n>` on a throwaway PR.
