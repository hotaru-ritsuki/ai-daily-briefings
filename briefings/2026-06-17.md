## 4. 🛠️ Claude Code & MCP ecosystem (community side, deep dive)

On a quiet official-release day, the worthwhile signal is the **subagent-driven-development + git-worktrees pattern**, now the dominant shape in advanced Claude Code usage and a clean fit for v2.1.178's nested `.claude/skills` + v2.1.172's 5-level depth. The [`obra/superpowers`](https://github.com/obra/superpowers) skills `subagent-driven-development` and `using-git-worktrees` are designed to compose: the orchestrator decomposes a plan into discrete tasks, dispatches an **implementer subagent into its own git worktree on its own branch** (isolated context, no cross-contamination), runs a two-stage review on each result, then merges. The orchestrator keeps state in the live session while each leaf gets fresh context — exactly the "avoid context pollution without losing coordination" property a per-feature AngularJS→Angular 18 sweep needs. Write-ups worth the read: [Jonathan's "orchestrate multiple agents like a team"](https://jonathansblog.co.uk/the-subagent-driven-development-claude-code-skill-orchestrate-multiple-agents-like-a-team) and the [claudemarketplaces skill page](https://claudemarketplaces.com/skills/obra/superpowers/subagent-driven-development).

For my stack specifically, the **database-MCP** layer is the underused one: [`crystaldba/postgres-mcp`](https://github.com/crystaldba/postgres-mcp) (and the lighter PGMCP) lets an agent introspect a live Postgres schema via natural language instead of me hand-feeding DDL into context — relevant when a migrated Angular feature needs its Spring Boot/JPA contract verified end-to-end. Pair it with the worktree pattern above so schema introspection happens in an isolated implementer, not the orchestrator's context.

**JetBrains MCP** ([`JetBrains/mcp-jetbrains`](https://github.com/JetBrains/mcp-jetbrains)) — no movement since the v262.7132.31 build (Jun 5). The integrated IDE MCP server (IntelliJ 2025.2+) remains the path for IntelliJ ACP work; nothing new to install.

## 8. 🎯 One thing to try today (≤30 min)

**Run a single Angular feature-module migration through the subagent-driven-development + git-worktrees pattern** — the highest-leverage thing available on a bug-fix-only release day.

```bash
# 1. Land the fixes:
npm update -g @anthropic-ai/claude-code && claude --version   # expect 2.1.179

# 2. Install the skills (if not already):
#    in Claude Code:  /plugin   → install obra/superpowers
#    or clone for reference:
git clone https://github.com/obra/superpowers ~/src/superpowers

# 3. In your migration repo, start an orchestrator session and prompt:
#    "Use subagent-driven-development. Migrate src/app/features/portfolio/
#     from AngularJS to Angular 18 standalone + signals, OnPush. Dispatch
#     each component to an implementer subagent in its own git worktree;
#     run the existing Playwright spec as the review gate; never commit on red.
#     Report a per-component pass/fail table when done."

# 4. Watch it spawn worktrees (git worktree list) and confirm the 2.1.179
#    Ctrl+O subagent-transcript fix actually shows live leaf progress.
```

Why today: v2.1.179 fixed the two subagent-viewing papercuts (`Ctrl+O` transcript, focus return) that made this pattern annoying to supervise, so it's the first day the orchestration is genuinely watchable end-to-end. The per-component pass/fail table is also the artifact that makes the migration-velocity case to the platform team.
