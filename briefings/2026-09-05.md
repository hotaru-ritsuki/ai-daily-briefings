## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **"External memory" is landing inside the harness, not beside it.** Practitioner reports on Astra-in-Codex describe the model **keeping notes across context windows** rather than repeatedly compressing history into one summary ([Lenny's Newsletter](https://www.lennysnewsletter.com/p/gpt-6-astra-is-a-banger-heres-everything)). That's the same persist-decisions-outside-the-window idea as `loopx`/planning-with-files (covered), but as a *native model behavior* — worth watching whether it reduces the need for my file-based plan scaffolding, or just moves the failure mode.
- **Spec-driven dev is consolidating on one toolkit.** GitHub's **[spec-kit](https://github.com/github/spec-kit)** (~111k★, MIT) now supports **30+ agents including Claude Code and Codex CLI** via a `specify → plan → tasks → implement` flow and slash commands ([writeup](https://letsdatascience.com/news/github-open-sources-spec-kit-for-spec-driven-development-1d51a7f7)). It's the agent-agnostic version of the GSD/planning-with-files discipline — the PRD generates the implementation, not the reverse. Cross-harness matters if I'm bouncing the same task between CC (Fable) and Codex (Astra).
- **Skills-as-OS + hygiene tooling maturing together.** The community framing is now "skills are the agent operating system" ([Developers Digest](https://www.developersdigest.tech/blog/skills-are-the-new-agent-operating-system)); CC's new `/skill-doctor` (§3) is the counter-pressure — a bloated skill set is real context cost, and now it's measurable per-skill.

## 8. 🎯 One thing to try today (≤30 min)

**Run `/skill-doctor`, then run the same real task through Codex (Astra) and Claude Code (Fable 5.1) and compare cost-per-task.** The independent read (§6b) is that they tie on coding-agent work at very different price shapes — so measure it on *your* code, not the launch blog.

```bash
# 1. Prune first — in an existing Claude Code session:
/skill-doctor          # note which skills never fire and their context cost

# 2. Head-to-head on one real task (a migration diff or a Playwright spec build):
codex upgrade          # 0.153.4 makes Astra the default; confirm with /model
codex                  # run the task, note tokens + wall-clock

claude                 # /model → Fable 5.1, run the identical task, compare
```

If Astra genuinely matches Fable at lower per-task cost on your workload, it becomes a real second harness for cost-sensitive runs; if not, you've spent 20 minutes to keep your routing honest. *(Fallback: just do step 1 — pruning dead skills is a free context win.)*
