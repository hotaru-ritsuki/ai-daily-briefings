## 8. 🎯 One thing to try today (≤30 min)

**Reproduce the Ronacher tool-calling regression on *your* stack — and mitigate it — in three steps.**

```bash
git clone https://github.com/Piebald-AI/claude-code-system-prompts
```

1. Open the current-version `Edit`/`MultiEdit` tool descriptions in that repo — note the exact field names, which are optional, and how nesting is shaped. That's the schema Sonnet 5 has strong priors for.
2. In a **long** Claude Code session (read a few files, make edits, keep the history), point Sonnet 5 at one of your **custom MCP tools** with a non-trivial schema (JetBrains MCP or an internal one) and ask for a multi-step edit. Watch the tool-call args for **invented fields** that aren't in your schema — that's the regression.
3. If you see it: rename/restructure your tool's params to mirror Claude Code's built-ins, and add strict server-side arg validation that rejects unknown fields loudly (so a bad call fails fast instead of corrupting state).

Even a single reproduction tells you whether your custom-tool surface is exposed — and the schema-alignment fix is cheap insurance now that Sonnet 5 is the default.

### 🤖 Claude in Microsoft Foundry hit GA — but it's a data-residency trap for EU-regulated stacks

- **What shipped:** Claude models (Opus 4.8, Haiku 4.5, and now **Sonnet 5**) are **generally available in Microsoft Foundry on Azure** (platform GA Jun 29; Sonnet 5 followed days later). Governance is Azure-native: **Entra ID** auth, **Azure RBAC**, MACC drawdown billed as consolidated **Claude Consumption Units (CCU)** on the Azure bill, running on NVIDIA GB300 Blackwell Ultra ([Claude blog](https://claude.com/blog/claude-in-microsoft-foundry), [Azure blog](https://azure.microsoft.com/en-us/blog/claude-in-microsoft-foundry-is-now-generally-available/), [MS Community Hub](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/claude-sonnet-5-is-now-generally-available-in-microsoft-foundry/4530737)). None of main's briefings cover Foundry — they covered the AWS upstream and the self-hosted apps gateway, not this.
- ⚠️ **The catch that matters to me:** **there is no European data zone.** Inference is routed to **Anthropic's own (US) servers regardless of which Azure region you select**, Anthropic remains the data processor, and the **US CLOUD Act applies** — so the GDPR data-residency guarantees you *do* get via **AWS Bedrock or Google Vertex do not extend to Foundry today**. Anthropic's regional-compliance page lists EU Foundry as **"Coming 2026,"** and EU banking/healthcare practitioners report it **unapproved for production**; current deployments are East US2 + Sweden Central Global Standard only ([InfoQ](https://www.infoq.com/news/2026/07/claude-foundry-ga-europe/), [MS Learn: region support](https://learn.microsoft.com/en-us/azure/foundry/reference/region-support), [Claude Platform docs](https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry)). *Why me:* if our platform (or any EU tenant of it) has data-residency obligations, Foundry is a **non-starter for now** despite the clean Azure governance story — Bedrock/Vertex stay the residency-safe routes. If we're US-only, it's arguably the tidiest governed Claude-on-Azure procurement path yet.
