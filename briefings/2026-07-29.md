## 4. 🛠️ Claude Code & MCP ecosystem

**The MCP 2026-07-28 spec is real now — here's what actually changed** ([spec blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [Claude support post](https://claude.com/blog/bringing-mcp-2026-07-28-to-claude)). The countdown coverage was speculative; these are the concrete facts to build against:
- **Stateless core.** The `initialize`/`initialized` handshake and `Mcp-Session-Id` header are retired; every request carries its protocol version + client identity in `_meta`, so any request can route to any server instance behind a load balancer.
- **Header routing:** gateways read `Mcp-Method` and `Mcp-Name`. **Cacheable lists:** `tools/list`/`prompts/list`/`resources/list` responses now carry `ttlMs` and `cacheScope`.
- **Server→client calls** (sampling, elicitation) move to **Multi Round-Trip Requests** instead of bidirectional streams. **Roots, Sampling, Logging** are deprecated with a **12-month** sunset — nothing breaks immediately.
- **Auth hardening:** RFC 9207 issuer validation, and **Client ID Metadata Documents (CIMD)** replace Dynamic Client Registration.
- All four Tier-1 SDKs (TS, Python, Go, C#) plus the beta Rust SDK support it **at publication** ([release notes](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/)). For my Spring Boot servers this is a Java-SDK-tracks-C#/reference-impl question worth checking before I commit.

**Cross-tool interop is becoming the default.** Beyond Codex 0.146.0 reading Claude Code marketplaces (§3), there's now a community **Codex-in-Claude-Code plugin** — delegate a code review or a scoped task to Codex without leaving the CC session ([first-hand writeup](https://medium.com/@markchen69/when-rivals-collaborate-installing-openais-codex-plugin-in-claude-code-5d3e503ce493)). The "pick one agent and stick with it" era is closing.

**DeepEval 4.0** shipped a **local eval harness for coding agents (Claude Code + Codex)** — Pytest-style test cases, metrics, and CI gates for agent runs ([DeepEval](https://deepeval.com/blog/top-5-llm-evaluation-frameworks)). Directly relevant to my test-automation-+-LLM interest; see §8.

## 8. 🎯 One thing to try today (≤30 min)

**Turn a Claude Code / Codex session into a CI-gated test with DeepEval 4.0's local harness.** Pick one recurring agent task (e.g. "generate a PrimeNG table component from this interface") and write a single eval that asserts on the output.

```bash
pip install -U deepeval
```

Then define one `LLMTestCase` with a metric + threshold and run it like a pytest. If it's useful, promote it into your migration CI so agent-generated code is gated the same way handwritten code is. This is the cheapest way to make "does the agent still do X correctly" a regression test instead of a vibe check.
