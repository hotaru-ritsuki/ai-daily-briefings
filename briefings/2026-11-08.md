## 8. 🎯 One thing to try today (≤30 min)
**A/B a long refactor session: plain Claude Code against billion-context's self-compression.**
1. Make a scratch worktree so nothing touches your main checkout: `git worktree add ../ng-bili -b try/bili && cd ../ng-bili`.
2. Install the plugin inside Claude Code:
   ```
   /plugin marketplace add ranxianglei/billion-context
   /plugin install billion-context@billion-context
   /billion-context:bili-setup
   ```
   (Or `npm install -g billion-context --prefix=~/.local`, then `bili claude`.)
3. Give it a task that normally triggers auto-compaction, for example: *"Migrate every `@Input()` in `src/app/features/**` to signal `input()`, updating templates and specs, one feature folder at a time; run `npx ng test --watch=false` after each folder."*
4. Run the same prompt in a normal session in another worktree. Compare:
   - `/context` at the end of each session
   - whether the agent still remembers the first folder's decisions by the fifth folder
   - `/usage` for each session
5. Uninstall with `/plugin uninstall billion-context` when you're done. Remote Control is off while it's active.

**Success criteria:** you can say whether self-managed compression beat built-in compaction on *recall of earlier decisions*, not just on token count.
