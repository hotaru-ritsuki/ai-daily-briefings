## 4. 🛠️ Claude Code & MCP ecosystem (community side, deep dive)

**v2.1.169's `/cd` is the missing link in the worktree-per-subagent pattern that's now the dominant orchestration mode** (covered repeatedly since Jonathan's 05-02 [Subagent-Driven Development](https://jonathansblog.co.uk/the-subagent-driven-development-claude-code-skill-orchestrate-multiple-agents-like-a-team) post and Boris Cherny's 5-parallel-instances workflow). Pre-v2.1.169, hopping the *orchestrator* between worktrees required a fresh session — losing accumulated `goal.md` substrate, the v2.1.157 auto-load Skills index, and the prompt cache. Post-v2.1.169, `/cd ../wt-portfolio` is one line. For the AngularJS → Angular 18 migration the practical mapping is: orchestrator session lives in the root; `/cd` into each feature-module worktree as you sweep it; `/cd ..` back. Combined with v2.1.166's `fallbackModel` and v2.1.163's Stop/SubagentStop `additionalContext` return, the harness now does what the [VILA-Lab paper](https://arxiv.org/abs/2604.14228) (06-07) called *"deterministic infrastructure surrounding the model"* without requiring a custom Python wrapper.

Relevance for the financial-services stack: if any internal compliance tooling is on Salesforce Service Cloud (KYC workflows, case management), this is the same shape as Atlassian Rovo MCP GA (covered 06-06) — first-party hosted with SSO. Worth a sandbox bake-off if Service Cloud is in the migration's adjacent surface area.

## 8. 🎯 One thing to try today (≤30 min)

**Update Claude Code to v2.1.169 and adopt `/cd` as the worktree-hop primitive in your existing orchestrator session.** The cache-preserving directory change is the single biggest workflow upgrade since v2.1.157's auto-load skills.

```bash
npm update -g @anthropic-ai/claude-code && claude --version   # expect 2.1.169

# 1. From an existing orchestrator session (no restart), confirm /cd works:
claude
> /cd .                          # baseline, no-op
> /cd src/app/features/portfolio # hop into a feature worktree without losing context
> /cd -                          # bounce back to the previous directory
# Verify the prompt cache survived by asking a context-heavy follow-up.

# 2. Probe safe-mode against your real .claude/ config:
claude --safe-mode               # boots with NO CLAUDE.md, plugins, skills, hooks, MCP
# Useful triage: if a behaviour disappears in --safe-mode, it's a customisation,
# not the model. The single best diagnostic for "is it my skill or is it Claude?"

# 3. Hide bundled skills if a custom one is being shadowed:
#    .claude/settings.json:
#      { "disableBundledSkills": true }
# Then re-list to confirm only your own skills are visible:
claude /plugin list --enabled

# 4. Sweep for the enterprise-MCP-policy-reconnect class:
#    Pre-v2.1.169, managed MCP policies could fail to enforce on reconnect,
#    IDE configs, or initial startup. If your platform team runs a managed
#    .mcp.json, re-audit transcripts for any reconnect-window tool calls
#    against denied servers.
rg -i 'mcp.*reconnect|mcp.*startup' ~/.claude/transcripts/ 2>/dev/null
```

The `/cd` test is the one that pays back daily — every worktree hop you previously paid a fresh-session tax on is now free.
