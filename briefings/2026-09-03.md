## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **"External state for the agent loop" is hardening into a tooling category, not a discipline.** `loopx` ([repo](https://github.com/huangruiteng/loopx), 5.5k★) is the clearest example: it sits *beside* the harness as a control plane — durable goals, decision scopes, peer claims/leases, evidence writeback and **quota-aware auto-wake** so a run parks and resumes instead of dying when it hits a limit. It's the same "persist decisions outside the conversation" idea as planning-with-files (covered), but aimed at multi-day, multi-agent continuity rather than a single task's plan file. Worth an hour if my migration runs keep losing thread after `/clear`.
- **Context/token compression is now a product layer in front of the model.** `headroom` ([repo](https://github.com/headroomlabs-ai/headroom), 68k★) ships as a **library, proxy, *and* MCP server** that compresses tool outputs, logs and RAG chunks before they reach the LLM — claiming ~20% fewer tokens for coding agents and 60–95% for JSON, with *reversible* compression so the model can re-expand full data on demand. Route Claude Code through it as a proxy and the savings show in a dashboard (§8). This is the token-hygiene knob (Codex's per-tool output limits, covered) as an external, harness-agnostic layer.
- **Code-intelligence MCP is shifting from blind reads to knowledge graphs.** `codebase-memory-mcp` ([repo](https://github.com/DeusData/codebase-memory-mcp), 42k★) indexes a repo into a persistent graph (158 languages, sub-ms queries, single static binary) and claims ~99% fewer tokens vs. letting the agent grep its way around — the same pitch as `trace-mcp` (covered) but graph-backed, which fits my large Spring Boot/TS monorepos.
- **Official MCP governance is catching up:** CC v2.1.259's `managedMcpServers` (§3) is the org-level counterpart to these community servers — the mechanism to hand a vetted, centrally-managed MCP set to a whole team rather than trusting per-repo `.mcp.json`.
