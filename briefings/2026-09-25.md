## 3. 📋 AI coding tool changelogs

Both daily tools shipped since the last briefing (cutoff: 2026-09-24). Fetched the CC docs changelog + GitHub CHANGELOG.md and Codex GitHub Releases directly.

### Claude Code — v2.1.282 (Sep 24)
- **⭐ 🔧 Compaction now retries on a fallback model** when the summarization request is refused — previously a refused summary could fail the whole turn. *Matters:* fewer dead long sessions.
- **⭐ 🐛 Resume/`--continue` reasoning preservation.** Fixed multiple cases where continued/resumed sessions re-sent earlier messages in altered form (making the API drop Claude's reasoning), and where extended thinking was dropped when `/model`, `/rename`, `/artifacts` fired mid-turn or when relaunched with a changed `--tools` list. *Matters:* directly affects your resumed subagent workflows.
- **🐛** Fixed every request 400-ing when history holds web-search results the API can't decrypt (e.g. from a third-party gateway turn); fixed "Invalid `data` in `redacted_thinking` block" loops (now drops thinking blocks and retries once); fixed a failed turn after a safety-related model switch with thinking off.
- **🆕** `maxProseWidth` caps prose width in wide terminals while tables/code keep full width; startup + `/status` + `claude doctor` now flag telemetry env vars in project settings that were ignored or disabled.
- **🔧** `allowClaudeInChromeWithManagedMcp` lets `claude --chrome` run alongside an exclusive `managed-mcp.json`.

### OpenAI Codex — v0.157.0 (Sep 25)
- **⭐ 🆕 Conversation forking** — new `f` shortcut forks a conversation while preserving drafts and queued prompts. *Matters:* branch an exploration mid-run instead of restarting; this is the standout feature.
- **⭐ 🆕 GPT-6 Sol & Luna GA**, including Amazon Bedrock support and migration prompts off older models. *Matters:* if you route via Bedrock, Monday's cheap-tier models are now first-class there.
- **🔧** Fullscreen transcripts on by default; background server auto-starts for eligible sessions; shift-click text selection; better Unicode rendering (bullets, checkboxes, aligned equations).
- **🐛** Voice-conversation persistence across thread navigation, realtime proxy routing, and file-upload retries (5-min timeout).

## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

- **"Harness" has gone from concept to product category — in repo names.** A week after the harness-engineering essays, the trending list is full of *open coding-agent harnesses*: **[zai-org/ZCode](https://github.com/zai-org/ZCode)** ("Z.ai's coding agent harness", ~6.6k★) and **[unreallabsai/unreal-agent](https://github.com/unreallabsai/unreal-agent)** ("async-first agent harness", ~1.8k★) both surfaced Sep 24 ([trending](https://github.com/marc-ko/daily-trending-repo/issues/559)). Worth a skim to steal harness-loop ideas for your `.claude/` setup — the async-first framing maps onto long-running CI-style agent jobs.
- **Approval- and audit-first orchestration is a distinct sub-theme.** **[open-multi-agent](https://github.com/open-multi-agent/open-multi-agent)** is a self-hosted TypeScript agent runtime built around *durable approvals and verifiable run records* ("own it, approve it, audit it"). This is the community answer to the same requirement driving §7 — an immutable trail of every agent action — and it's in your stack (TS). If you're putting agent surfaces on a Spring Boot backend, the run-record model is the portable idea.
- **Browser-debugging MCP has matured.** **[ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp)** (official) lets an agent read console output, inspect network traffic, run Lighthouse, and walk the accessibility tree in a live Chrome — auto-connecting to authenticated sessions on Chrome 144+. For a heavy Playwright user this is the natural complement: Playwright drives the flow, DevTools MCP explains *why* it broke. See §8.
- **Evals knowledge is consolidating into curated hubs.** **[benchflow-ai/awesome-evals](https://github.com/benchflow-ai/awesome-evals)** collects papers/blogs/tools/benchmarks for building and evaluating agents — a decent single entry point before you stand up your own LLM-as-judge harness (§6a).

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns
- **[Spec-Driven Development: A Spec-First Approach to AI-Native Engineering](https://developer.microsoft.com/blog/spec-driven-development-ai-native-engineering/)** — Microsoft for Developers. The official MS take on making an executable spec the source of truth and treating code as a generated, verifiable artifact; useful counterweight to the vendor-agnostic SDD hype. *~9 min.*
- **[Context Engineering: A Practical Guide for AI Agents](https://sourcegraph.com/blog/context-engineering)** — Sourcegraph. Concrete on the subagent pattern you use: each subagent runs the same retrieve→act→report pipeline against a narrower scope and returns a distilled 1–2k-token summary. *~12 min.*
- **[AI Evals FAQ](https://hamel.dev/blog/posts/evals-faq/)** — Hamel Husain. Operational Q&A from someone who's shipped this: error analysis first, binary judgments, why 60–80% of the work is understanding failures, not writing automated checks. *~15 min.*
- **[A pragmatic guide to LLM evals for devs](https://newsletter.pragmaticengineer.com/p/evals)** — The Pragmatic Engineer. Engineer-facing walkthrough of building evals into a real workflow rather than treating them as a research artifact. *~12 min.*
- **[Evaluate AI Agents in Production: a 3-Level Framework](https://www.kunalganglani.com/blog/evaluate-ai-agents-production)** — adapts Husain's hierarchy into assertion-based unit tests → trace-based LLM-as-judge → online A/B, with the plumbing spelled out. *~10 min.*

### 6b. General AI engineering reading
- **[Interpreting Pangram](https://lucumr.pocoo.org/2026/9/14/interpreting-pangram/)** — Armin Ronacher digs into how an AI-text detector actually works and what it says about model fingerprints. Not about coding workflows, but a sharp, first-principles read on model interpretability. *~10 min.*

## 7. 💼 AI in fintech

- **Governance frameworks for agentic finance are now being written down.** A new survey, [*Governing Agentic AI in FinTech*](https://arxiv.org/pdf/2608.11344), catalogs the control requirements as banks move from predictive models to agents that *execute* coordinated workflows — the recurring non-negotiable is an immutable, requestable audit trail for every decision and action (the same requirement §4's `open-multi-agent` targets in code).
- **Payments regulators are engaging early:** the IMF's [*How Agentic AI Will Reshape Payments*](https://www.elibrary.imf.org/view/journals/068/2026/004/article-A001-en.xml) note frames agent-initiated commerce as a near-term supervisory question, not a speculative one. Worth a skim if any of your work touches payment flows.

## 8. 🎯 One thing to try today (≤30 min)

**Wire Chrome DevTools MCP into Claude Code and let it debug a failing Playwright test.** Instead of relaying console/network errors by hand, give the agent eyes on the live browser:

```
claude mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest
```

Then, in a session, run one of your flaky Playwright specs and ask Claude to "reproduce the failure in Chrome, read the console and network tab, and propose a fix." It reads real console output, inspects requests, and can run a Lighthouse pass — closing the loop between "the test failed" and "here's why." ([repo](https://github.com/ChromeDevTools/chrome-devtools-mcp))
