## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

**VILA-Lab's ["Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems"](https://arxiv.org/abs/2604.14228)** is the most concrete public reverse-engineering of Claude Code's harness I've found, and somehow this series has missed it. The team reverse-engineered Claude Code v2.1.88's ~1,900 TypeScript files / ~512K LOC and quantified the structural split: **1.6% of the codebase is AI decision logic, 98.4% is deterministic infrastructure** — permission gates, the five-layer compaction pipeline, tool routing, four extensibility mechanisms (MCP, plugins, skills, hooks), subagent delegation, and append-oriented session storage. Practical reading: the paper formalises the seven-mode permission system and ML-based classifier that you've been writing `allow`/`deny` against — useful before authoring your next managed-settings policy. **The thesis bites**: "as foundation models converge in baseline reasoning, the critical differentiator for autonomous system reliability becomes the deterministic engineering harness surrounding the model" — i.e. your `goal.md` discipline (05-31 Leonhardt) is doing more work than your model choice. Companion repo: [VILA-Lab/Dive-into-Claude-Code](https://github.com/VILA-Lab/Dive-into-Claude-Code) ships a [`build-your-own-agent.md`](https://github.com/VILA-Lab/Dive-into-Claude-Code/blob/main/docs/build-your-own-agent.md) with the architectural patterns extracted as a guide.

**Microsoft Conductor** ([repo](https://github.com/microsoft/conductor), [blog](https://opensource.microsoft.com/blog/2026/05/14/conductor-deterministic-orchestration-for-multi-agent-ai-workflows/)) is the Microsoft-side answer to GitHub Security Lab's `seclab-taskflow-agent` (covered 05-30) and the YAML-declarative counterpart to Claude Code's JS-generated dynamic workflows. **No LLM in the orchestration loop** — routing is Jinja2 expressions, first matching condition wins, deterministic. Per-agent model overrides; supports GitHub Copilot **and** Anthropic Claude as providers in one YAML. Same architectural shape as the seclab tool but Copilot-integrated; if the platform team's Codex-vs-Claude bake-off (covered 06-04) wants a single orchestration layer that can run both, this is the credible MIT-licensed option.

**GitHub MCP server adds `set_issue_fields` + MCP Apps UI moved to feature flag** ([releases](https://github.com/github/github-mcp-server/releases)). The granular Issues toolset now supports writing org-level custom field values on issues (flagged under `issues_granular`); MCP Apps UI support migrated out of insiders-only mode into a proper `remote_mcp_ui_apps` flag — the slow rollout of MCP-rendered server-side UIs is starting. Direct fit if your migration tracking lives in GitHub Issues with custom fields.

**Spring AI 1.0.8 / 1.1.7 / 2.0.0-M7 (May 23)** deprecates SSE transports; **Streamable HTTP is now the default** for MCP servers ([release notes](https://spring.io/blog/2026/05/23/spring-ai-1-0-8-1-1-7-2-0-0-M7-available-now/)). MCP annotations moved into Spring AI core from the community module. For the Spring Boot side of our stack this is the cleanest path to a production-grade MCP server with version negotiation and non-blocking execution; pairs with the 2026-07-28 MCP spec's stateless redesign.
