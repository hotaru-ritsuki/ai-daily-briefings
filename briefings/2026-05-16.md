### Claude Code — 2.1.143 (May 15) ([changelog](https://code.claude.com/docs/en/changelog))

- 🆕 ⭐ **Plugin dependency enforcement**: `claude plugin disable` refuses when another plugin depends on it, suggests the disable chain. `claude plugin enable` force-enables transitive deps. ⭐ *Prevents silently breaking plugin stacks during config changes.*
- 🆕 ⭐ **`worktree.bgIsolation: "none"`** — background sessions edit the working copy directly, skipping `EnterWorktree`. ⭐ *For repos where worktrees conflict with your build setup (monorepos with symlinks, certain Angular CLI configs).*
- 🆕 Projected context cost (per-turn + per-invocation token estimates) in `/plugin` marketplace browse pane.
- 🔧 ⭐ **`/bg` preserves `--mcp-config`, `--settings`, `--add-dir`, `--plugin-dir`, `--strict-mcp-config`, `--fallback-model`, and `--allow-dangerously-skip-permissions`** across respawn. ⭐ *The biggest `/bg` fix yet — backgrounded migration agents keep their full environment instead of silently losing MCP servers and settings.*
- 🔧 ⭐ Background sessions preserve model and effort level after waking from idle. ⭐ *No more overnight agents reverting to default effort.*
- 🔧 `claude agents` now accepts `--add-dir`, `--settings`, `--mcp-config`, `--plugin-dir`, `--permission-mode`, `--model`, `--effort` as defaults for dispatched sessions.
- 🔧 Background sessions honor `permissions.defaultMode` from settings.json (was previously overridden to auto).
- 🔧 PowerShell tool enabled by default on Windows for Bedrock/Vertex/Foundry; passes `-ExecutionPolicy Bypass`.
- 🐛 Fixed stop hooks that block repeatedly looping forever — capped at 8 consecutive blocks (override: `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`).
- 🐛 Fixed `/goal` evaluator firing while background shells or subagents are still running.
- 🐛 Fixed `/bg` without a prompt sending "continue" instead of waiting for input.
- 🐛 Fixed macOS `/bg` agents getting "Operation not permitted" on `~/Documents`, `~/Desktop`, `~/Downloads` even with Full Disk Access.
- 🐛 Fixed corrupt `.credentials.json` hanging CLI on startup.
- 🐛 Fixed `--agent <name>` not finding plugin-contributed agents without the `plugin:` prefix.
- 🐛 ~10 additional background-agent, Windows, and agent-view fixes.

## 4. 🛠️ Claude Code & MCP ecosystem

- **Full-fidelity `/bg` changes the migration workflow.** Before 2.1.143, backgrounding a session was lossy — MCP servers, custom settings, and fallback models could silently drop. Now `claude agents --mcp-config .mcp.json --model opus --effort high` dispatches a session that survives sleep, idle, and respawn with its full environment intact. This is the missing piece for "dispatch five migration agents overnight from Agent View and find them finished in the morning."
- **Anthropic published the 2026 Agentic Coding Trends Report** — 8 trends across foundation/capability/impact, case studies from Rakuten, CRED, TELUS, Zapier. Worth skimming for the multi-agent coordination patterns and the data on where agent-assisted coding is actually working vs. where it's failing ([PDF](https://resources.anthropic.com/hubfs/2026%20Agentic%20Coding%20Trends%20Report.pdf)).
- **`worktree.bgIsolation: "none"` solves a real pain point** — if your Angular CLI workspace uses symlinks or your monorepo's build config breaks in worktrees, background agents now have the option to edit the working copy directly. Trade-off: no isolation between concurrent sessions, so use with care on repos where only one agent runs at a time.

## 8. 🎯 One thing to try today (≤30 min)

**Upgrade to 2.1.143 and test the full-fidelity `/bg` workflow on a migration subtask.**

```bash
# 1. Upgrade
claude --upgrade  # confirm 2.1.143

# 2. Start a session with your migration MCP config:
claude --mcp-config .mcp.json

# 3. Pick a small migration task and start working on it interactively.
#    Once Claude is mid-task, background it:
#    Press ← ← (double left arrow) or type /bg

# 4. Open Agent View to verify the session kept its config:
claude agents
#    The session should show as Running with your MCP servers intact.

# 5. From Agent View, dispatch a second task with explicit config:
#    claude agents --model opus --effort high \
#      --mcp-config .mcp.json --settings .claude/settings.json \
#      "Migrate src/app/legacy/filters.directive.js to Angular 18
#       standalone component with signals.
#       /goal ng build succeeds and all tests pass."

# 6. Let both run. Check back in 15 min.
#    The key test: do both sessions still have their MCP servers?
#    Run /mcp in each to verify.

# 7. If your repo has worktree issues, try the new setting:
#    Add to .claude/settings.json:
#    "worktree": { "bgIsolation": "none" }
#    Warning: no isolation between concurrent agents with this setting.
```

The 50% weekly limit increase means you have more headroom to run these experiments without burning through your quota. The combination of full-fidelity `/bg` + Agent View dispatch flags + higher limits is the first time Claude Code's background agent story is genuinely production-ready for parallel migration work.
