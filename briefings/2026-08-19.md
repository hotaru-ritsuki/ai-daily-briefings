## 4. 🛠️ Claude Code & MCP ecosystem (community deep dive)

- **Cross-harness orchestration is the through-line this week.** Codex's async-hooks-call-MCP (§3) and Databricks' **[Omnigent](https://github.com/omnigent-ai/omnigent)** (Apache-2.0, [Databricks blog](https://www.databricks.com/blog/introducing-omnigent-meta-harness-combine-control-and-share-your-agents)) point the same direction: a **meta-harness** over Claude Code, Codex, Cursor, Pi and custom YAML agents, splitting a *server* (state, policies, skills) from a *runner* (laptop/sandbox) so sessions stay portable and **Python contextual policies** can enforce a cost budget by denying an agent mid-session. Open-sourced in June but resurfacing via Latent Space's AIE-Europe coverage — worth a look precisely because I straddle CC + Cursor + IntelliJ ACP + Codex and currently switch by hand.
- **The clearest decision framework I've seen for my own stack:** [Choosing between skills, subagents, and MCP servers in Claude Code](https://smithhorngroup.substack.com/p/choosing-between-skills-subagents) — skills = procedural know-how, subagents = orchestration/parallelism with isolated context, MCP = external connections; most production setups use all three. A cleaner mental model than the "install everything" catalogs (§6a).
- **OpenReview (§5) is also an ecosystem artifact, not just a repo:** it's a readable, ~agent-in-a-sandbox implementation — GitHub webhook → Vercel Workflow → sandbox clones the PR branch → a Claude agent runs project tooling → posts inline comments and can commit fixes. That "the reviewer can also *fix*" loop is the pattern to steal for a migration-review subagent.
- **Plugin-adoption, measured:** [quemsah/awesome-claude-plugins](https://github.com/quemsah/awesome-claude-plugins) scrapes real Claude Code plugin adoption metrics across GitHub (via n8n) instead of curating by vibes — a data-driven way to see which plugins teams actually keep.

## 8. 🎯 One thing to try today (≤30 min)

**Clone OpenReview and read its Vercel Workflow definition as a blueprint for a mergeability-graded review subagent.** No deploy needed — the value is the pipeline:

```
git clone https://github.com/vercel-labs/openreview && cd openreview
# open the workflow/handler that runs: sandbox → clone PR branch → agent analyzes diff → inline comments → optional commit
```

Trace how it (1) isolates the checkout in a sandbox, (2) lets the agent run *project tooling* before judging, and (3) posts inline suggestions vs. committing a fix — then map those three onto a project `/code-review` subagent scoped to Angular migration diffs, grading regression-safety and scope rather than just "tests pass." *Bonus (~3 min):* `claude update` to v2.1.235 and flip on the new `spellcheck` setting.

## 9. 📣 Shareable angle

**Hook:** "Your AI reviewer shouldn't just comment on the diff — it should be able to *fix* it."
**Draft:** Vercel just open-sourced OpenReview: a self-hosted, Claude-powered PR bot that spins up a sandbox, clones the branch, runs your project's own tooling, then posts inline suggestions — or commits the fix directly. The interesting shift isn't "AI reads the diff"; it's that the reviewer runs in an isolated environment with permission to act, which is exactly the boundary you want to design on purpose.
