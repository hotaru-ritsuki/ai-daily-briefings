## 3. 📋 AI coding tool changelogs

### Claude Code — v2.1.202 (Jul 6) · [changelog](https://code.claude.com/docs/en/changelog)
The 07-06 addendum's re-fetch confirmed 2.1.201 was still latest, so **2.1.202 is the full delta**.
- **⚠️⭐ `/review <pr>` reverted to a fast single-pass review; the multi-agent review is now `/code-review <level> <pr#>`.** *Why it matters:* a command-semantics change I'll hit on every PR — pick the effort level deliberately instead of inheriting the old multi-pass default. 🔧
- **⭐ Skill re-invocation no longer appends a duplicate copy of the skill's instructions to context.** *Why it matters:* context hygiene — repeated `/skill` calls in a long migration session were silently bloating the window. 🐛
- **⭐ Clearer MCP error when a server config has `url` but no `type`** — now suggests `"type": "http"` instead of the misleading "command: expected string". *Why it matters:* the exact papercut when hand-editing MCP configs. 🔧
- New `/config` **"Dynamic workflow size"** setting (small/medium/large agent counts — advisory, not an enforced cap), plus `workflow.run_id` / `workflow.name` OpenTelemetry attributes for reconstructing a workflow run from OTel. 🆕
- Fixes: Remote Control (mobile/web) commands failing with "Unknown command" and caption-less images being dropped; `/remote-control` showing the wrong permission mode; resuming a session by name being minutes-slow in repos with many git worktrees. 🐛

## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **Hashline / minimal-harness thread is the week's most useful community signal.** [`can1357/oh-my-pi`](https://github.com/can1357/oh-my-pi) (16.3k★, TypeScript) forks Mario Zechner + Armin Ronacher's [`badlogic/pi-mono`](https://github.com/badlogic/pi-mono) (44k★, the harness under OpenClaw) and adds **hashline** hash-anchored edits, LSP, a DAP debugger, `retain`/`recall` cross-session memory, and subagents. Both use **"lazy skills"** — a one-line description in context, full instructions loaded only on invocation — the same progressive-disclosure idea now landing in Claude Code's skill-duplicate fix (§3).

Worth cherry-picking the review/test skills for a financial-services repo where you want a small, auditable skill set.

If your agent's browser tests are token-heavy, the CLI path is now the recommended default.

## 8. 🎯 One thing to try today (≤30 min)

**Feel hashline edits on a throwaway repo to judge whether the pattern is worth pushing into your custom MCP tool schemas.** Ronacher's 07-06 finding said newer Claude models invent fields on non-Claude-Code tools; hashline sidesteps it by making the model cite a per-line hash instead of reproducing text.

```bash
git clone https://github.com/can1357/oh-my-pi && cd oh-my-pi
cat packages/coding-agent/DEVELOPMENT.md   # setup, then run it against a scratch git repo
```

Watch the `edit` tool calls: no whitespace reproduction, no ambiguous matches. If it holds up, the takeaway for my stack is to shape **custom MCP/JetBrains tool schemas the same way** — anchor-based, strict-validated — rather than free-text `oldText`/`newText`.
