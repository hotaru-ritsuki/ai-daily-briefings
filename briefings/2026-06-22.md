## 5. 📦 Useful repos (AI-first, ranked by relevance)

*Excludes repos already in the last 7 briefings (`angular/skills`, `agentgateway`, `awesome-harness-engineering`, `wshobson/agents`, `omnigent-ai/omnigent`, `pr-agent`, `Nikita-Filonov/ai-review`, etc.).*

1. **[Fission-AI/OpenSpec](https://github.com/Fission-AI/OpenSpec)** (~52k★) — spec-driven dev: a strict propose → apply → archive state machine *before* code, with first-class Claude Code support. *Why:* pairs with 06-21's `angular/skills` — the skill teaches the agent *how* to write Angular, OpenSpec forces it to agree on *what* before writing. Spec discipline is the cheapest counter to "agent drifted from intent" rework on the migration. (§8.)
2. **[confident-ai/deepeval](https://github.com/confident-ai/deepeval)** — Pytest-style LLM eval framework (G-Eval, hallucination, answer-relevancy, LLM-as-judge). *Why:* the missing "unit tests for prompts" layer once you've internalized 06-20's evals-as-CI argument from the Anthropic post. Self-hostable inside the perimeter.
3. **[strands-agents/evals](https://github.com/strands-agents/evals)** — agent eval framework with **trajectory analysis** (not just final output), tool-usage assessment, MLLM-as-judge. *Why:* evaluates *how* the agent got there — the right lens for subagent reliability, which a final-answer eval misses entirely. Complements deepeval (one for prompts, one for agent loops).
4. **[oguzc/playwright-wizard-mcp](https://github.com/oguzc/playwright-wizard-mcp)** — MCP server that drives Playwright test generation with best-practice prompts. *Why:* directly in my stack; locators come from real page state (accessibility tree), not DOM guessing. Different shape from the official `microsoft/playwright-mcp` (which exposes browser automation as raw tools) — this one is opinionated, generation-first.
5. **[OpenDCAI/One-Eval](https://github.com/OpenDCAI/One-Eval)** — agentic NL→eval orchestration on LangGraph; natural-language eval requirements → traceable runs + reports. *Why:* lower friction than hand-writing harnesses for ad-hoc checks ("does the agent ever drop a `@HostListener`?"). Newer, smaller — sandbox-grade, not production.
6. **[sunnamed434/awesome-mcp-registry](https://github.com/sunnamed434/awesome-mcp-registry)** — auto-updating, trust-scored MCP directory (also §4). *Why:* vet-before-install for the MCP supply chain.

## 9. 📣 Shareable angle

**Hook:** "Microsoft made its SRE agent 30 points more accurate not by adding tools — by deleting 100 of them."

**Draft:** Microsoft's Azure SRE Agent team lifted its "Intent Met" score from 45% to 75% on novel incidents by replacing 100+ bespoke tools with a plain filesystem the agent greps and reads — because frontier models were trained on exactly that workflow. The lesson for anyone wiring MCP servers onto a coding agent: every narrow tool you add is context you're spending and a path you're constraining; sometimes the highest-leverage move is to expose the codebase as files and get out of the way.
