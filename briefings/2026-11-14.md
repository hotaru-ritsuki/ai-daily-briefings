## 3. 📋 AI coding tool changelogs (since the 2026-11-13 briefing)

### Claude Code — 2.1.325 (Nov 13; there's no 2.1.324 entry)

- ⭐⚠️ **Sandbox auto-allow is now off by default.** Sandboxed Bash commands go through the normal permission prompts. Set `sandbox.autoAllowBashIfSandboxed: true` to get the old behavior. If you manage settings for a team, set it in the highest-ranking managed source.
- ⭐⚠️ **Unattended runs ask more often:**
  - **Skills:** scheduled tasks and `/loop` ask before running a skill that declares `allowed-tools` or hooks. Pre-approve it with `Skill(name)` in `permissions.allow`.
  - **"Always allow" (Desktop, IDE and SDK):** it only offers a bare rule when saving that rule would actually allow the command next time, so a scheduled task that relied on one may now wait for you.
  - **Read-only git:** read-only git commands in repos that aren't trusted now ask first. Pass the repo with `--add-dir`; the `additionalDirectories` setting doesn't count.
- ⭐🐛 **Subagent fixes:**
  - A subagent with its own model is no longer switched to the plan-mode model under `opusplan`.
  - A subagent that hits the output limit is asked for a shorter complete answer, instead of returning only the end of one.
  - A slash command's `allowed-tools` no longer carry over to background agents.
- ⭐🔧 **MCP tasks:**
  - Esc on a background task's question now means "answer later", and the question stays in `/tasks`.
  - Claude is told when a task is waiting on you.
  - Fixed: servers that got stuck in "needs auth" after a token refresh failed briefly, and tasks that stopped updating after a connection dropped.
- 🐛 **Permissions:**
  - Relative deny rules like `Read(./.env)` still apply after a `cd`.
  - Fixed: some compound Bash commands ran without asking.
  - Fixed: an allow rule could run a different program than the one it names.
  - The sandbox now fully protects worktree settings and hooks.
- 🔧 **Context size:** `CLAUDE_CODE_MAX_CONTEXT_TOKENS` now also sets the context window for unrecognized `claude-*` model IDs. This follows yesterday's change to assume 1M by default. Sessions on many third-party gateways and Foundry now compact instead of failing with a context-length error on every turn.
- 🚫/🔧 **Plugins:**
  - `pluginDigests` is deprecated and ignored.
  - Unsafe paths in a plugin's folder are skipped, and `claude plugin validate` reports them.
  - `.claude/skills` inside a `--plugin-dir` plugin no longer load when the session starts in a folder above it.
- 🆕 **VS Code:** prompt suggestions, accepted with Tab. Turn them off with `promptSuggestionEnabled: false`.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns
- **["Building always-on agents"](https://claude.com/resources/articles/building-always-on-agents)** (Anthropic, Nov 13, ~12 min).
  - Every trigger writes to a durable inbox, with one worker per inbox and events batched. Timers add events to the inbox and never start runs directly.
  - Memory stores pointers, not copies. Credentials sit behind a proxy.
  - A hook can defer a risky tool call, end the run, and resume when the user's answer arrives as a new event.
  - There's no code, but it's the clearest reference architecture for Routines-style agents.
- **["Elephant-Goldfish Design Review"](https://agentpatterns.ai/patterns/multi-agent/elephant-goldfish-design-review/)** (agentpatterns.ai, ~6 min). The pattern behind EGM: the drafter has full context and the reviewers have none. It explains why a reviewer with less context finds more problems in a spec.
- **[Armin Ronacher, "The Software Atelier"](https://ai.engineer/code/2026/talks/armin-ronacher)** (AI Engineer, write-up dated Nov 12). His agent got much better while its harness barely changed. He argues for workflows that can stop, suspend, restore and continue. I only saw a search summary.
- **["AI-First Workflows: Code as a Strategic Weapon"](https://adamtornhill.substack.com/p/ai-first-workflows-code-as-a-strategic)** (Adam Tornhill, ~8 min). Commit the test suite first so it guards against unwanted changes by the AI. I only saw a summary.

### 6b. General AI engineering reading
- **["Building strong safety evaluations"](https://www.anthropic.com/research/building-strong-safety-evaluations)** (Anthropic, Nov 13, ~18 min). The best guide to grader design I've seen this year, and it applies well beyond safety:
  - Use atomic yes/no criteria, swap the order in pairwise comparisons, and check the grader against human labels with Cohen's kappa.
  - Aim for at least 100 items for multi-turn evals.
  - Configuration matters: the same evals differed by up to 34 percentage points between the API and the consumer app.

## 8. 🎯 One thing to try today (≤30 min)

**Run one real feature spec through EGM's goldfish review before writing any code.**

1. **Install:**
   ```
   claude update            # need ≥ 2.1.325
   claude plugin marketplace add google/elephant-goldfish-model
   claude plugin install egm@egm
   ```
   Start a new session afterwards. EGM requires that agents can spawn subagents.
2. **Draft the spec.** In your Angular repo, run the EGM draft skill (type `/egm` to see the list) on a small, real change. For example: "add retry and an error banner to `<NgRx effect>` feeding `<PrimeNG table>`, with a Playwright check".
3. **Review it.** Run the review skill. Count how many of the goldfish's questions are things you knew and never wrote down. Each one is context a future agent run would have lacked.
4. **Judge it.** It's worth adopting if the review found at least one real gap, such as a missing empty state, a retry storm or an untested selector. If so, add `/egm-drift-report` to your PR checklist.

*Side task (5 min, do this before tonight's scheduled runs):* 2.1.325 changed the defaults that unattended runs depend on. Check whether anything you run headless uses a skill with `allowed-tools`:
```
grep -rl 'allowed-tools' ~/.claude/skills .claude/skills 2>/dev/null
```
Add `"Skill(<name>)"` to `permissions.allow` for each one, and add `"sandbox": {"autoAllowBashIfSandboxed": true}` if your routines rely on sandboxed Bash running without prompts.

## 9. 📣 Shareable angle

**Hook:** "The best reviewer for your AI's spec is the one that knows the least."
**Draft:** Google's open-source Elephant-Goldfish plugin has one agent that knows everything write the design doc, then reviewers with no context tear it apart before any code exists. The gaps a reviewer with no context finds are exactly the context your next agent run won't have. Review the plan, not the 2,000-line diff.
