## 3. 📋 AI coding tool changelogs

Cutoff = last briefing (08-26: CC **v2.1.246**, Codex **0.149.1** stable + 0.150.0-alpha train).

**Claude Code — v2.1.247 (Aug 26)** ([changelog](https://code.claude.com/docs/en/changelog)):

- ⭐ 🆕 **`/claude-api cost-optimize`** — profiles an existing project's Claude API spend and walks caching, token hygiene, batch, effort, and model-choice levers one measured change at a time. *Why it matters:* a first-party audit for exactly the fan-out cost I keep eyeballing.
- ⭐ 🐛 **Subagent first-call model 404 → fallback chain.** A subagent that 404s on its model now uses the session's fallback model chain, and the parent gets the error type/status/request-id/model instead of a dead agent. Removes a real unattended-run failure.
- ⭐ 🔧 **Sonnet 5 auto-compact now targets the full 1M window** (~967K vs ~934K) — more usable context before compaction on long sessions.
- 🆕 **`SendFeedback` tool** — Claude can draft a `/feedback` report when something breaks (off via `feedbackDrafts`); org-customizable `spinnerTipsOverride`; a Bash permission prompt now offers one-keystroke "Yes, and switch to auto mode."
- 🔧 On Bedrock/Vertex/Foundry (and telemetry-off sessions), Claude is now **told when an MCP server failed to connect** instead of silently concluding the tools don't exist; `/goal` caps idle background check-ins at three per goal; cross-session peer messages collapse to a one-line preview (Ctrl+O expands).
- 🐛 Long fixes list: fast arrow+Enter acting on the wrong row in pickers, megabyte hook output wedging a session on "Prompt is too long," `/compact` under `--agent` using the wrong system prompt, and the Bash sandbox deleting a dotfile-managed `~/.claude/settings.json` symlink.

**OpenAI Codex — 0.150.0 stable (Aug 26), 0.150.1 (Aug 27)** ([releases](https://github.com/openai/codex/releases/tag/rust-v0.150.0)):

- ⭐ 🆕 **Interrupt hooks** — run a command or MCP handler when an active top-level turn is interrupted. New automation surface (cleanup, checkpointing, notify) that CC-style hooks already had.
- ⭐ 🆕 **Task references via `@`** — reference other Codex tasks so an agent can read, create, or message them from the terminal; auto-titled tasks; `/rename` suggests titles.
- ⚠️/🔧 **Untrusted projects no longer supply project-level `AGENTS.md`**, managed deny-read rules persist across permission changes, and app-server diagnostics get stronger credential redaction. A sensible hardening — check any repo you rely on for its `AGENTS.md` to apply.
- 🔧 `/copy` picker (full response / code block / blockquote), clickable markdown links in supported terminals, permission-mode cycling keybindings, Vim dot-repeat; Bedrock compaction + multi-agent fixes. **0.150.1** = remote-compaction image-budget fix only.

## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **Codex is converging on Claude Code's orchestration surface.** With 0.150's **Interrupt hooks** and **cross-task `@`-references** now stable ([releases](https://github.com/openai/codex/releases/tag/rust-v0.150.0)), the two harnesses now share the same primitives — hooks that fire on lifecycle events, and tasks that address other tasks. For my plan-on-Claude / execute-on-Codex split, that means an interrupt on the Codex side can now trigger a handoff back without a polling wrapper.
- **Skill hygiene is becoming a tooling category, not a discipline.** [`khendzel/skills-janitor`](https://github.com/khendzel/skills-janitor) (~114★, zero-dependency, CC + Codex) frames it bluntly: swipe through your skills/subagents/MCP servers, see honest token costs, scan each for prompt injection, and it actually deletes what wastes context. This is the concrete answer to the skill-bloat problem the parts-bin marketplaces (wshobson/agents, alirezarezvani/claude-skills) create — install broadly, then prune with data (§8).
- **A directory layer over the marketplace sprawl.** [`davepoon/buildwithclaude`](https://github.com/davepoon/buildwithclaude) (~3.4k★, updated today) is a single searchable hub for Skills, Agents, Commands, Hooks, Plugins, and Marketplace collections across Claude Code, Desktop, and the Agent SDK — useful as a lookup index rather than yet another config to adopt.
- **The "no agent approves its own PR" pattern is being formalized.** [`nathanjohnpayne/mergepath`](https://github.com/nathanjohnpayne/mergepath) is a repo standard with 70+ fail-closed CI checks and **multi-identity review** — a different agent identity must review the PR an agent wrote — plus one-command propagation to downstream repos. Low stars, but the multi-identity gate is the right shape for the mergeability-graded review I keep sketching.

## 8. 🎯 One thing to try today (≤30 min)

**Garbage-collect your Claude Code skills with `skills-janitor`.** If you've installed from any of the big marketplaces, you're almost certainly carrying skills you never fire — each one eats startup context. Run:

```bash
git clone https://github.com/khendzel/skills-janitor && cd skills-janitor
# follow the README to point it at your ~/.claude (skills, subagents, MCP servers)
```

It shows the honest token cost of each skill/subagent/MCP server, flags any with prompt-injection risk, and deletes what you swipe away. Ten minutes to turn "my `/context` startup payload feels heavy" (the CC-08-24 hygiene point) into a measured cleanup. **Zero-install alternative:** run `/claude-api cost-optimize` on a real project (new in v2.1.247) and let Claude profile your actual spend levers.
