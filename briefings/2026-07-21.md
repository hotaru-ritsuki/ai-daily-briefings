## 4. 🛠️ Claude Code & MCP ecosystem (community)

The theme this week is **orchestration-layer tooling filling the gap v2.1.215 opened** by removing auto-`/verify` and auto-`/code-review`. Two shapes are converging:

- **TUI/tmux orchestrators** that run several agent CLIs side-by-side with git-worktree isolation — [`nutthouse/tutti`](https://github.com/nutthouse/tutti) (ops layer over Claude Code/Codex/Aider/API agents; roles, `tutti.toml` pipelines, audit trail, and a `:4040` dashboard with SSE updates) and [`Thurbeen/thurbox`](https://github.com/Thurbeen/thurbox) (persistent tmux sessions, remote SSH, inter-session messaging, native code-review view). Both make the "implement in one agent, review in another" pattern a config artifact rather than something you drive by hand.
- **Directories** to navigate the churn: [`andyrewlee/awesome-agent-orchestrators`](https://github.com/andyrewlee/awesome-agent-orchestrators) (~1.1k★, 140+ tools) and [`Picrew/awesome-agent-harness`](https://github.com/Picrew/awesome-agent-harness).

If you subscribe to the "let the agent judge" advice from §1, the missing half is a *deterministic* review gate you don't rely on the model to remember — which is exactly what `tutti.toml`-style pipelines encode.

## 8. 🎯 One thing to try today (≤30 min)

Now that v2.1.215 removed auto-`/code-review`, **make the review gate explicit and deterministic instead of hoping the model remembers.** Fastest path: clone `tutti` and encode a two-role implement→review pipeline for one migration file.

```
git clone https://github.com/nutthouse/tutti && cd tutti
# skim the README, then define roles in tutti.toml:
#   [agents.impl]   role = "implement", worktree = true
#   [agents.review] role = "review",    worktree = true, depends_on = "impl"
```

Run it against one AngularJS→Angular 18 component port and compare the review agent's findings to what you'd have caught by eye. Even if you don't adopt `tutti`, the exercise clarifies what your explicit review step *should* assert — which is the real deliverable.
