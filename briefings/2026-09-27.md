## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **[`Graphify-Labs/graphify`](https://github.com/Graphify-Labs/graphify)** is the standout. Instead of an embedding index, it builds a real graph you *traverse*: functions, imports, SQL schema references, config keys, even PDF/doc entities, parsed deterministically with tree-sitter so nothing leaves your machine and every edge is explained (`EXTRACTED` = read from source, `INFERRED` = resolved by graphify). It ships as a portable skill across CC/Cursor/Codex/Gemini CLI. This is the anti-RAG take on code intelligence — auditability over recall — and a good fit for regulated codebases where "why did the agent think these are connected" matters.
- **[`stablyai/orca`](https://github.com/stablyai/orca)** — an ADE (agent development environment) rather than an MCP server: worktree-isolated parallel agents, diff-line comments shipped back to the agent, `orca worktree` scripting, quick-open across worktrees/files/agents, and optional Computer Use for desktop-app steps. Bring-your-own-subscription for any CLI agent.
- **Production structure patterns worth stealing** ([DEV guide](https://dev.to/lizechengnet/how-to-structure-claude-code-for-production-mcp-servers-subagents-and-claudemd-2026-guide-4gjn)): *one MCP server per concern* (splitting GitHub issues / PRs / code-search into three servers measurably improved tool-selection accuracy vs one bundled server), and *give subagents a minimal fresh prompt, not the full parent context* — inheriting parent context makes a subagent drift the same way the parent already drifted.
- **[`xyTom/coding-tools-mcp`](https://github.com/xyTom/coding-tools-mcp)** — an MCP server that gives any agent (not just coding CLIs) the ability to write and run code; useful if you want code-exec inside a non-coding agent host.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns
- **[Agentic coding is straining CI: how we scaled test impact analysis at Anthropic](https://claude.com/blog/agentic-coding-is-straining-ci-heres-how-we-scaled-test-impact-analysis-at-anthropic)** — first-hand: when Claude writes ~80% of merged code, tests grew 10x and CI jobs 25x in six months; their fix is test-impact analysis (run only the tests a diff can affect). Directly relevant if your Playwright + Spring suites are the next bottleneck once agents accelerate PR authoring. ~10 min.
- **[Astra for Coding: Why Are We Doing This Again?](https://lucumr.pocoo.org/2026/9/7/astra-why/)** — Armin Ronacher ran an autonomous "software factory" for 35 hours: ~1B tokens, ~$1,200, 75k net LOC, 79 commits, and *nothing usable* — plus the failure mode where token-efficient codegolf style leaks from tool-calls into committed, unreadable code. The best available argument for keeping a human definition-of-done in the loop. ~12 min.
- **[Note, 24th Sep 2026](https://simonwillison.net/2026/Sep/24/harder/)** — Simon Willison: coding agents make software engineering *harder*, not easier — unlocking them "requires extraordinary discipline and knowledge." Short, and a useful antidote to autonomy hype; his Sep 20 write-up on getting API keys onto agent machines (via `llm keys get`) without pasting them into the app is the practical companion. ~3 min.

## 8. 🎯 One thing to try today (≤30 min)

**Graph one of your repos instead of grepping it.** Install the skill and build a knowledge graph over a single Angular or Spring module:

```
git clone https://github.com/Graphify-Labs/graphify
pip install graphifyy   # note: package is graphifyy (double-y); CLI stays `graphify`
```

Then invoke `/graphify` in Claude Code against a bounded directory (start small — one feature module) and ask it to trace, e.g., every caller of a service method or every config key a component reads. Because edges are tagged `EXTRACTED` vs `INFERRED`, you can immediately see what it *knows* vs what it *guessed* — a fast read on whether deterministic graphing beats semantic search for your codebase before you wire it into a heavier workflow.
