## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **Two design choices in [MCP Companion](https://github.com/SinLordEp/mcp-companion#tools) worth copying in any MCP server I write:**
  - **Each tool steps aside** when the IDE ships an official tool for the same job. `mc_status` reports which ones have.
  - **Every write has a `preview`** that lists conflicts and affected files, and `apply` runs only when there are none, as one undoable command. No tool ever opens a dialog.
  - Its ~50-line [agent guide](https://github.com/SinLordEp/mcp-companion/blob/HEAD/src/main/resources/agent/mcp-companion-guide.md) (also a ready-made skill) tells the agent how the tools fit together, which tool descriptions alone can't do.
  - **Limits:** IDE build 263+ only, `mc_spring_beans` needs IDEA Ultimate, single maintainer, no GitHub release yet.
- **Benchmark MCP tools against your own session logs.** [develar/search-bench](https://github.com/develar/search-bench) replays the real search calls from Claude Code session files against JetBrains MCP search and `accio`, then grades answer quality and speed. Take the queries from `~/.claude/projects/*.jsonl`, not from made-up prompts.
- **Merge policy as code is spreading beyond Claude Approvals.**
  - [Lonca](https://github.com/selimdizer/lonca) merges only the exact head commit, after review by a different model family, gated by a risk tier computed from the diff.
  - [Forgeline](https://github.com/Nabwinsaud/forgeline) uses hooks to stop agents from editing the gate or the policy.
  - Both follow the same rule: agents judge, deterministic code decides.
- **ACP between agents, not just between an IDE and an agent.** [antigravity-acp](https://github.com/lvdoushacc/antigravity-acp) runs Antigravity as a Claude Code subagent over a warm ACP connection, and [antigravity-codex-subagent](https://github.com/Kiraliang954321/antigravity-codex-subagent) does the same for Codex over `app-server` v2. Both are tiny projects.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[How Much Do Coding Agents Over-Edit, and Why?](https://arxiv.org/abs/2611.34875v1)** (Goel, Steenhoek, Hu, Microsoft Research; ~25 min).
  - **Method:** *Delta Residue Attribution* traces each patch block to the step that wrote it, reverts the block and reruns the tests to see whether it was needed.
  - **Findings:** agents are about as precise as human developers (0.887 vs 0.864 on SWE-bench Verified). The extra lines are mostly regression tests written before the fix.
  - **Recommendation:** report "code necessity" alongside resolve rate, and prune unneeded edits in the harness.
  - **Caveat:** secondary write-ups disagree on the size ratio (2.33× vs 1.09×), so check the PDF before quoting numbers. It's a preprint, not peer-reviewed.
- **[Quartet QE: "Record once, replay with no AI"](https://github.com/Callahan-ci/quartet-qe#record-once-replay-with-no-ai)** (README section, ~12 min). It's a practical rulebook for agent-written tests:
  - Only steps from a passing test are recorded.
  - A step that breaks goes back to the AI to be recorded again, which can change *how* it's done but never *what* it proves.
  - Recordings from failing tests are kept in `_unproven/`, so CI shows the real bug and not "no recording".
  - The framework adds W3C `traceparent` headers itself, so a test can prove that the service linked an order to its Kafka event.
- **[Lonca README](https://github.com/selimdizer/lonca#readme)** (~10 min). A first-hand design for multi-agent work with one person in charge: the lead plans but never writes code, lanes report `DONE:` or `QUESTION:`, and a watcher flags lanes that go quiet. Read it for the honest list of what its guard rails *don't* stop.

### 6b. General AI engineering reading

- **[Trained to betray: post-training supply chain attacks hijack coding agents](https://microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-how-post-training-supply-chain-attacks-hijack-coding-agents)** (Microsoft Security, Nov 12, not covered here before; ~15 min).
  - **Dataset poisoning:** about 1% poisoned fine-tuning examples (90 in ~9,000) made the model misuse command tools when it saw the trigger.
  - **Model poisoning:** a backdoored Qwen3.5 checkpoint succeeded 84–95% of the time on unseen repositories, including **91–97% when run inside Claude Code**. That reflects the backdoored checkpoint, not a flaw in Claude Code's defaults.
  - **Defences:** treat checkpoints like untrusted dependencies (hash, provenance), evaluate them in your real harness, limit tool authority, and alert on tool calls the user's request doesn't explain. Read it before pointing Claude Code at a fine-tuned open-weight model through a gateway.

## 8. 🎯 One thing to try today (≤30 min)

**Let Claude Code refactor a Spring service through IntelliJ instead of with text edits.**

1. In IntelliJ IDEA 2026.3, go to *Settings › Plugins › Marketplace*, search "MCP Companion" and install it (no restart needed). Make sure the bundled *MCP Server* plugin is enabled and connected to Claude Code (*Settings › Tools › MCP Server*).
2. Check it from the project root:
   ```bash
   claude mcp list    # the JetBrains server should be listed and connected
   claude "Call mc_status and list which mc_* toolsets are available vs yielded."
   ```
3. Add the agent guide as a skill:
   ```bash
   git clone --depth 1 https://github.com/SinLordEp/mcp-companion ~/src/mcp-companion
   cp -r ~/src/mcp-companion/skills/mcp-companion .claude/skills/
   ```
4. Give it a real task: *"Use mc_spring_beans `dependencies` on `InvoicePdfService`, then mc_change_signature **preview** to add a `Locale locale` parameter defaulting to `Locale.ENGLISH`. Show the conflicts and affected files, don't apply."* Then apply it, and run `mc_diagnostics` → `mc_build` → `mc_run start_at` on the test class.

**Pass criteria:** every call site in Java (and Kotlin, if any) is updated in one undoable command, and no file is edited by text in between. Count how many tool calls and tokens it took compared with asking Claude to do the same change with Edit and `mvn test`. If `mc_spring_beans` is missing, you're on Community edition. If it reports `no_spring_model`, indexing hasn't finished.
