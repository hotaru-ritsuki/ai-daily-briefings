## 3. 📋 AI coding tool changelogs (since the 2026-11-17 briefing)

**Claude Code 2.1.327** (Nov 17, on both the [docs changelog](https://code.claude.com/docs/en/changelog) and [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md); a long release, so only what matters is listed):

- ⭐ ⚠️ **Shell "head start":** start-up files can run before the first Bash command is approved, even if you refuse it. Disable with `CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1`.
  - **Why:** a speed win, but your shell rc now runs without a prompt.
- ⭐ 🆕 **`claude mcp add-json <name> -`** reads the server JSON from stdin. It doesn't work from inside a Claude Code session.
  - **Why:** you can register a Jira or Atlassian MCP server without its token landing in shell history.
- ⭐ 🐛 **`claude mcp add/remove --scope project` no longer deletes other top-level keys** in `.mcp.json`, such as `$schema` or other tools' `servers`.
  - **Why:** if you share `.mcp.json` with Cursor or IntelliJ, it was silently losing their keys.
- ⭐ 🔧 **Remote MCP servers reconnect after longer outages:** after a VPN drop they're retried in the background for about a day.
- ⭐ 🆕 **A health check in `/status`:** it lists broken agent, skill, command and output-style files, ignored permission settings, an unavailable sandbox and hook matchers that never match.
  - **Why:** one place to see why a `.claude/` config isn't taking effect.
- ⭐ 🐛 **Agent-team fixes:**
  - In-process teammates on a different model from the lead now compact at their own limit, on their own model.
  - `--agents` definitions are no longer lost when plugins reload.
  - A resumed subagent no longer picks up a sibling's model and effort.
- 🐛 **Remote Control in worktree mode:** stopping the server no longer deletes a running session's git-ignored files such as `.env`.
- 🐛 **Hooks:** failures in SubagentStop, SessionEnd, CwdChanged and FileChanged hooks are now shown, and `/hooks` now lists hooks from `--settings`.
- 🐛 **Headless runs:** `claude -p` no longer hangs when fetching a model's settings stalls behind a proxy; it continues after 10s. `/export` now asks before overwriting a file.
- 🔧 **Commits:** Claude is now told not to commit files that likely hold secrets.
- 🆕 **Renderer:** `/tui classic` is the new name for the non-fullscreen renderer.

**OpenAI Codex** ([Releases](https://github.com/openai/codex/releases)):

## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **External sandboxes, in detail** ([repo](https://github.com/prime-radiant-inc/external-sandbox), [Claude Code guide](https://github.com/prime-radiant-inc/external-sandbox/tree/main/claude-code), Apache-2.0):
  - **Backends:** one HTTP/WebSocket protocol with three servers: v86 (WebAssembly VM, Node, port 8686), Apple Container (8687) and Quicksand QEMU (8688). A conformance suite checks that each backend implements the protocol correctly.
  - **How Claude Code connects:** `CLAUDE_CODE_SHELL_PREFIX` points at a wrapper that sends the whole command unchanged to `/exec/ws`. The project is mounted read-write at the same absolute path inside the VM.
  - **Gotcha:** the README notes that the prefix also wraps hooks, status-line commands and stdio MCP server start-up. Your hooks and local MCP servers would then run inside the VM, which may lack Node. Native Read/Edit still act on host files.
  - **Network:** off by default. Optional egress goes through a host proxy that swaps in API keys, so the keys never enter the VM.
- **[SITREP](https://github.com/IluvatarLabs/sitrep)** (93 ★, MIT, Nov 12): a self-hosted dashboard for every Claude Code and Codex session across your machines. It shows context fill, cost and which sessions are blocked on a prompt, and you can answer prompts from it. It speaks plain HTTP, and the README warns that "anyone who can reach port 7487 can read every session". Keep it on localhost or a VPN.
- **[turbo-browser-mcp](https://github.com/Tthanh2k6/turbo-browser-mcp)** (131 ★, MIT, Nov 14): a Playwright MCP server built to cut tokens.
  - **Tools:** `smart_fill_form` fills a whole form in one call, `inspect_compact` can return only what changed since the last snapshot, and `batch_actions` chains steps. Submit buttons are blocked by default.
  - **Claims:** the author's single-run numbers show about 68% fewer tokens than a full ARIA snapshot on a 140-button page. The README itself calls these upper bounds.
- **Stale Codex config in skill READMEs:** [am-will/swarms](https://github.com/am-will/swarms) (250 ★) still tells Codex users to set `[features] multi_agents = true`, but Codex 0.168 moved this to `agents.enabled` (covered Nov 13). Check the config keys in any Codex skill README you copy.
- **Star-farmed clones in GitHub search:** a search for repos created since Nov 13 with 150+ stars returned about 20 near-identical "Gemini-Config-Checker-" repos at ~473 ★ each. It also returned copies of a "GitHub-Copilot-app" repo from accounts with random names. I didn't inspect them; don't install anything from that cluster.

## 5. 📦 Useful repos

1. **[prime-radiant-inc/external-sandbox](https://github.com/prime-radiant-inc/external-sandbox)** (28 ★, Apache-2.0). A shared sandbox protocol, clients and conformance tests for Claude Code, Codex and Pi.
   - **Why I'd care:** OS-level isolation for agent shell commands without Docker.
2. **[prime-radiant-inc/external-sandbox-v86](https://github.com/prime-radiant-inc/external-sandbox-v86)** (npm `external-sandbox-v86`). The zero-dependency backend: `npx` downloads a ~36 MB Alpine VM, with your project mounted live over 9p.
   - **Why I'd care:** this is the one to try in §8.
3. **[erkamyaman/rust-anything](https://github.com/erkamyaman/rust-anything)** (1.9k ★, MIT, Nov 16). Ports an app to Rust one unit at a time.
   - **How it works:** it records the original's behavior on generated edge cases plus your inputs. You or an agent write the Rust, and replaying the recordings gates every unit. It ships as a CLI, an MCP server and a skill, and supports TS and Java sources.
   - **Why I'd care:** the record → port → replay gate fits any migration, such as AngularJS to Angular or Spring Boot 2 to 3, even if you never touch Rust.
4. **[Tthanh2k6/turbo-browser-mcp](https://github.com/Tthanh2k6/turbo-browser-mcp)** (131 ★). Token-lean Playwright MCP (§4).
   - **Why I'd care:** a cheap A/B against Microsoft's playwright-mcp on your own E2E flows. Check that the npm package matches the source before you run it.
5. **[IluvatarLabs/sitrep](https://github.com/IluvatarLabs/sitrep)** (93 ★). A console for Claude Code and Codex sessions across machines (§4).
   - **Why I'd care:** shows which parallel worktree session is stuck waiting for you.
6. **[av/skills](https://github.com/av/skills)** (28 ★, MIT, updated Nov 11). 26 skills.
   - `workgraph` runs work as a graph of subagent nodes with gates and budgeted cycles.
   - `bughunt` finds, triages, fixes and audits bugs with parallel subagents.
   - `sandcastle` runs Claude Code, Codex and OpenCode inside sandboxes.
   - **Why I'd care:** `workgraph`'s gated nodes are a more structured alternative to a single long `/loop`.
7. **[am-will/swarms](https://github.com/am-will/swarms)** (250 ★). `/swarm-planner` writes a plan of tasks with dependencies, then `/parallel-task` runs them in waves of subagents, each of which commits but doesn't push.
   - **Why I'd care:** a simple wave scheduler for multi-module features. Fix the Codex config key first (§4).

## 8. 🎯 One thing to try today (≤30 min)

**Run Claude Code's Bash tool inside a throwaway v86 VM, and see what breaks.**

```bash
claude update && claude --version          # expect 2.1.327
# terminal 1, from a scratch clone of a real repo:
npx external-sandbox-v86 --port 8686 --preserve-paths --mount-rw "project=$PWD"
# terminal 2, same directory:
git clone --depth 1 https://github.com/prime-radiant-inc/external-sandbox /tmp/esb
mkdir -p .external-sandbox-claude-tmp
CLAUDE_CODE_SHELL=/bin/bash CLAUDE_CODE_TMPDIR="$PWD/.external-sandbox-claude-tmp" \
CLAUDE_CODE_SHELL_PREFIX=/tmp/esb/claude-code/claude-shell-prefix.sh \
EXTERNAL_SANDBOX_API_URL=http://127.0.0.1:8686 claude
```

1. **Confirm the commands run in the VM:** ask Claude to run `uname -m; whoami; curl -sI https://example.com`. You should see i686, a non-root user and a network failure.
2. **Try real work:** ask for a `git log`/`rg`-heavy task, such as "find every NgRx effect without error handling". The guest is 32-bit Alpine with Git, ripgrep and Python but no Node, so `ng test` fails here. That's a backend choice, not a dead end: on a Mac, Apple Container is the backend for running Node.
3. **Check the gotcha:** run `/mcp` and `/status`. The prefix also wraps stdio MCP server start-up and hooks, so note which ones now fail inside the VM.
4. **Keep it or drop it:** keep the setup only if the failures are limited to Node-dependent commands. Requires `uv` and Python 3.11+ on the host for the streaming client.
