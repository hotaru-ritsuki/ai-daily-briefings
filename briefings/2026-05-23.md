### Claude Code

**v2.1.150 — May 23, 2026** ([changelog](https://code.claude.com/docs/en/changelog))
- 🔧 Internal infrastructure only; no user-visible changes.

**v2.1.149 — May 22, 2026**
- 🆕 ⭐ **`/usage` now breaks down limit consumption by skills, subagents, plugins, and per-MCP-server cost.** First real visibility into which MCP server or skill is eating tokens in long sessions — useful for trimming an MCP config that's quietly inflating context.
- 🆕 **Scrollable `/diff` detail view** (arrows, `j/k`, `PgUp/PgDn`, Space, Home/End). Small QoL win when reviewing large generated diffs.
- 🆕 **GFM task-list checkboxes** (`- [ ]` / `- [x]`) render in markdown output instead of plain bullets — pairs with `/goal`-style task tracking.
- 🆕 Enterprise `allowAllClaudeAiMcps` managed setting loads claude.ai cloud MCP connectors alongside `managed-mcp.json`.
- 🐛 ⭐ ⚠️ **PowerShell permission bypass fix** — built-in `cd` functions (`cd..`, `cd\`, `cd~`, `X:`) changed the working directory undetected, letting later commands read outside the workspace. Windows-only but security-relevant.
- 🐛 ⭐ **Worktree sandbox-write allowlist fix** — was covering the entire main repo root instead of only the shared `.git` directory (with `hooks/` and `config` denied). Anyone running parallel migration agents in worktrees was effectively running them with write access to the main checkout.
- 🐛 PowerShell prefix/wildcard allow rules (e.g. `PowerShell(dotnet.exe build *)`) were not pre-approving native executables and scripts.
- 🐛 Parser was trusting stale variable-tracking values for `PWD`/`OLDPWD`/`DIRSTACK` across `cd`/`pushd`/`popd`.
- 🐛 `find` in the Bash tool exhausting the macOS system file/vnode table and crashing the host on large directory trees — relevant if you've ever run a recursive find on a node_modules-heavy Angular repo.
- 🐛 `otelHeadersHelper` failing silently when the script path contains spaces; failures now reported in `/doctor`.
- 🐛 `/ultraplan` and remote-session creation failing with "Could not capture uncommitted changes" on clean working trees.
- 🐛 Effort level shown in status bar now reflects skill/agent frontmatter `effort:` instead of the baseline `/effort` setting.
- 🐛 Several smaller fixes: thinking spinner staying amber, collapsed-Bash hidden-line count, argument-hint clipping, Ctrl+O transcript freeze, duplicate up-arrow history entries, `/insights` crash on missing cache fields, `/feedback` now bundling pre-compaction conversation.

## 4. 🛠️ Claude Code & MCP ecosystem

**MCP 2026-07-28 RC — the actual delta.** The stateless protocol core is the biggest practical change: no `initialize` handshake, no `Mcp-Session-Id` header, client metadata in `_meta` on every request. Servers can now sit behind a plain round-robin load balancer without sticky sessions or shared session stores. The other shoe is **MCP Apps**: servers can ship interactive HTML UIs rendered in sandboxed iframes that talk back over the same JSON-RPC channel as tool calls — closer to "rich tool result" than a generic chat surface. Tasks moves to an extension with `tasks/get/update/cancel`, and Extensions get formal governance (reverse-DNS IDs, Standards Track, independent versioning). Final spec lands July 28 with a 12+ month deprecation window for the old transport ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)).

**Chrome DevTools MCP — Microsoft now reachable from Claude Code via marketplace install.** Official server from the ChromeDevTools org gives a coding agent puppeteer-driven control of a live Chrome instance: trace recording, performance insights, network inspection, source-mapped console stack traces. Chrome 144's automatic connection is the path of least resistance for agents that need to share state with a manually-open browser; manual remote-debugging-port wiring is the fallback for sandboxed environments ([repo](https://github.com/ChromeDevTools/chrome-devtools-mcp), [Chrome blog](https://developer.chrome.com/blog/chrome-devtools-mcp)). For an Angular migration, this is the "agent inspects the rendered page after a component port" capability that Playwright MCP doesn't cleanly cover.

**Mercado Libre — 23,000 engineers, 90% autonomous coding target by Q3 2026.** Katelyn Lesse used the London keynote to walk through ML's Claude Code rollout: engineers own design, architecture, and code review; Claude Code writes the lines. Useful data point for the "is 90% autonomous realistic" conversation at scale, and a precedent worth name-dropping when pitching internal expansion ([MIT Tech Review](https://www.technologyreview.com/2026/05/21/1137735/anthropics-code-with-claude-showed-off-codings-future-whether-you-like-it-or-not/), [pravinkumar.co](https://www.pravinkumar.co/blog/code-with-claude-london-no-new-model-2026)).

## 8. 🎯 One thing to try today (≤30 min)

**Install Chrome DevTools MCP and use it to verify a migrated Angular component visually.** Closes the loop between "agent rewrites the component" and "agent confirms the rendered DOM still matches".

```bash
# 1. Upgrade Claude Code first (you want 2.1.149+ for the /usage breakdown
#    and the worktree write-allowlist fix before running parallel agents).
claude --update

# 2. Add Chrome DevTools MCP to .mcp.json in your Angular repo:
# {
#   "mcpServers": {
#     "chrome-devtools": {
#       "command": "npx",
#       "args": ["-y", "@chromedevtools/chrome-devtools-mcp"]
#     }
#   }
# }
# (Requires Chrome 144 for automatic connection; otherwise launch with
#  `chrome --remote-debugging-port=9222` and pass --port to the MCP.)

# 3. Pick a recently migrated standalone component. In Claude Code:
#    "Use the chrome-devtools tools to open http://localhost:4200/
#     /<route-for-migrated-component>, take a performance trace, and
#     compare the network requests + console errors against the legacy
#     AngularJS version at /legacy/<same-route>. Report any new errors,
#     deprecation warnings, or perf regressions. Then check /usage and
#     tell me how many tokens the chrome-devtools MCP server consumed
#     versus the rest of this session."

# 4. The /usage breakdown in 2.1.149 is the real test — you'll find out
#    whether Chrome DevTools MCP is worth keeping enabled by default or
#    only loading via /mcp connect for specific tasks. Decide based on
#    actual per-server cost, not vibes.
```

If you already use Playwright MCP, run the same migration check through both and compare token cost — Microsoft's own guidance is now "use Playwright CLI for agents" (covered 2026-05-22), so Chrome DevTools MCP filling the *interactive debugging* slot while Playwright drops to CLI for *headless validation* is the natural division of labour.
