## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

- **The `CLAUDE.md`-as-guardrail pattern has clearly won as a genre.** Chang's four-principle file (§1) is worth reading not for the celebrity name but because it's the most-copied concrete answer to "what do I actually put in project memory?" The four rules map to failure modes you'll recognize: *Think Before Coding* (plan-before-prompt), *Simplicity First* (against over-engineered diffs), *Surgical Changes* (minimal-diff discipline), *Goal-Driven Execution* (don't wander). Treat it as a **baseline to diff against**, not gospel — copy the framing, keep your repo-specific rules. Annotated walkthrough: [MCP.Directory](https://mcp.directory/blog/karpathy-claude-md-annotated-2026).
- **Serena is the community MCP most worth adding this week for large codebases.** It wires a language server into MCP so the agent does symbol-level `find_symbol`/`replace_symbol`/`find_referencing_symbols` instead of re-reading whole files into context — the retrieval discipline behind the file-based-plan patterns, but at the AST level ([oraios/serena](https://github.com/oraios/serena), [ClaudeLog guide](https://claudelog.com/claude-code-mcps/serena/)). Free, LSP-backed, works with CC/Codex/any MCP host. For an Angular+TS+Java monorepo this is the difference between "grep the file" and "jump to the definition."
- **Superpowers now carries the official-marketplace trust signal.** Jesse Vincent's [obra/superpowers](https://github.com/obra/superpowers/) (TDD RED-GREEN-REFACTOR enforcement, systematic-debugging + brainstorm skills, subagent-driven dev with built-in review) is in Anthropic's official plugin marketplace and past **~94k★** ([Claude plugin page](https://claude.com/plugins/superpowers)) — `/plugin install superpowers@claude-plugins-official`. ## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Working With Coding Agents: Principles for Reliable AI-Built Software](https://nishbhana.com/Working-With-Coding-Agents/)** — Nish Bhana (Jul 2026, not covered). Seven first-hand working principles distilled from shipping AI-built software: *give the agent a check it can run, plan before you prompt, keep context small and specific, hunt the unknowns your spec missed, review by risk, invest in fundamentals agents multiply, stay accountable for what ships.* The most compact "how to actually work with this" list I've seen. *~9 min.*
- **[The Code Agent Orchestra — what makes multi-agent coding work](https://addyosmani.com/blog/code-agent-orchestra/)** — Addy Osmani (Mar 2026). Names the three walls of single-agent work — context overload, no specialization, no coordination — and where subagents vs. agent-teams each help. Useful counterweight to the "one loop + skills beats subagents" argument from Anthropic's Commerce Agents piece (covered 09-03): decide per task, not per dogma. *~11 min.*

## 8. 🎯 One thing to try today (≤30 min)

**Install Serena and let an agent navigate one of your larger repos by symbol instead of by file.** On a monorepo this is where context bloat actually hurts, and Serena swaps whole-file reads for LSP-backed symbol lookups.

```bash
# Add Serena as an MCP server to Claude Code (uvx runs it without a global install):
claude mcp add serena -- uvx --from git+https://github.com/oraios/serena serena start-mcp-server --context ide-assistant

# then, in a real repo:
claude
#  → ask: "find the definition of <SomeService> and every place that references it,
#     then propose a surgical change to <method>" — watch it use symbol tools, not grep
```

Compare the context usage (`/cost`) against how the same task runs without Serena — the symbol-level path should read far fewer tokens on a large codebase. **5-minute fallback if you'd rather not add an MCP server:** drop [Chang's four-principle `CLAUDE.md`](https://github.com/forrestchang/andrej-karpathy-skills) next to your own and diff them — keep the framing, delete anything that contradicts your repo's rules.
