## 4. 🛠️ Claude Code & MCP ecosystem (community)

- **"Meta-harnesses" are the emerging community pattern — orchestrate multiple coding agents behind one policy/sandbox layer.** This is the community mirror of §1's official gateway. [`omnigent-ai/omnigent`](https://github.com/omnigent-ai/omnigent) (~5.9k★, created Jun 11) drives Claude Code, Codex, and Cursor interchangeably — "swap harnesses without rewriting, enforce policies and sandboxing." [`ruvnet/metaharness`](https://github.com/ruvnet/metaharness) (~349★) goes the other direction: scaffold *your own* branded agent harness with its own npx CLI, MCP server, memory, and a learning loop. For a regulated stack the interesting bit isn't the model-switching — it's the governance envelope (policy + sandbox) sitting above whichever agent you point at it, letting you standardize one audit story across the three tools you already bounce between.
- **`/dataviz` shipping as a first-party *skill* (§3) is a packaging signal worth copying.** Anthropic chose a skill — not an MCP server, not a subagent — for a bounded design task: it runs in your main thread so you steer each chart, with the validator as a deterministic gate. If your team hand-rolls Highcharts theming, a project-local skill encoding your own tokens + contrast rules is a half-day win and a cleaner pattern than a CLAUDE.md paragraph.
- **Background-agent auto-PR (§3) reshapes team etiquette, not just config.** Once agents open draft PRs unattended, the `Notification` hook plus a naming convention (`agent/…` branches, draft-only) is the difference between "useful" and "noise on a shared repo." Encode it in `.claude/settings.json` before enabling, not after.

## 8. 🎯 One thing to try today (≤30 min)

**Wire the new background-agent `Notification` hook and watch the auto-PR flow *before* it surprises you on a real branch.** After updating to v2.1.198:

1. In `.claude/settings.json`, add a `Notification` hook matching the new events:
   ```json
   { "hooks": { "Notification": [ { "matcher": "agent_completed", "hooks": [ { "type": "command", "command": "notify-send 'Claude agent opened a PR'" } ] } ] } }
   ```
2. Kick off a small, throwaway background agent on a scratch worktree: `claude agents` → give it a bounded task (e.g. "add a unit test for `X`").
3. Watch it commit, push, and open a **draft** PR on its own — then confirm the branch name and that nothing merged.

Decide your team convention (branch prefix, draft-only, required reviewer) *now*, on a scratch repo — so the shift from "agent asks" to "agent ships a draft PR" is a choice you made, not a default you discover mid-migration.
