- **"Loop engineering" has become a named discipline.** Osmani's framing (trigger → topology → **verifier** → stop-rules) is now the standard vocabulary for the outer loop that prompts, checks, and *stops* an agent — the verifier and stop-rule are what catch fail-plausible before it ships. It maps straight onto Claude Code primitives: subagent as executor, eval/verify skill as verifier, an explicit stop-rule instead of "until it looks done." Pair with v2.1.221's `prompt-audit` (§3) — auditing old-model cruft out of `.claude/` is the subtractive half of the same move.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Own the Outer Loop — Loop Engineering](https://addyosmani.com/blog/own-the-outer-loop/)** — *Addy Osmani* (Jun 7; the essay that named the discipline, still the best entry point). Stop prompting agents; design the trigger/topology/verifier/stop-rules that prompt them. *Takeaway:* the verifier and stop-rule are where correctness lives, not the prompt. ~12 min.
- **[When AI Loops Fail: The Production Incidents Behind Loop Engineering](https://theairuntime.com/p/when-ai-loops-fail-the-production)** — *The AI Runtime*. The longitudinal study that surfaced **fail-plausible** — the loop that reports believable progress while already wrong. *Takeaway:* instrument the loop to catch confident-but-wrong output; a crash is the *safe* failure. ~8 min.
- **[Why AI Agents Fail in Production: The Agent Failure Stack](https://www.sherlocks.ai/blog/why-ai-agents-fail-in-production)** — *Sherlocks*. 73 real production incidents distilled into seven failure classes (hallucinated actions, runaway cost, tool misuse, silent wrong answers, context loss, over-automation). *Takeaway:* failures are missing-controls problems, not weak-model problems — the fix is harness, not a bigger model. ~9 min.
- **[Loop Engineering: Why the Agent Era Needs a Runtime, Not a Longer Prompt](https://medium.com/jin-system-architect/loop-engineering-why-the-agent-era-needs-a-runtime-not-a-longer-prompt-b5aa34944fb4)** — *JIN* (Jul). The argument for treating the loop as a runtime with checkpoints and stop conditions rather than stuffing more into the prompt. *Takeaway:* a concrete counter to prompt-bloat — move logic into the loop, not the system prompt. ~7 min.
