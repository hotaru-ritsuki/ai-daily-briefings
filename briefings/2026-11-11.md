## 4. 🛠️ Claude Code & MCP ecosystem (community)
- **A good MCP design to copy, from Pangular Inspector's [MCP docs](https://github.com/pangular-inspector/devtools/blob/main/apps/docs/src/content/agents/mcp-server.md).** The ideas carry over to any internal Spring Boot or Angular MCP server:
  - **Two transports with different trust levels.** stdio (`pangular mcp`) only scans your source. HTTP (`/__devframes/__mcp` on the dev server) adds live-page tools, but only while the app is open in a browser.
  - **The two servers get different names on purpose.** The stdio one is `pangular` and the HTTP one is `pangular-live`. The docs explain why: Claude Code prefers a local server over a project server with the same name, so the HTTP server would otherwise never load.
  - **Tokens stay out of config files.** The bearer token is read from an environment variable, never printed into config. There's a `--read-only` flag, and you get a clear-text warning on non-loopback HTTP.
- **[agent-autoloop](https://github.com/KKKKhazix/agent-autoloop)** (MIT, Node 24+) shows an approval pattern that's easy to copy:
  - Each event runs one round with `claude` or `codex`, and the process exits afterwards.
  - To ask a question, the agent ends its reply with a structured `agent-autoloop` block. The hub turns it into a card, and `agent-autoloop answer` resumes the same session.
  - The rules live in `rules.json`, and it also has an append-only event log and SQLite state.
  - It talks to ACP agents too, which makes it relevant to the IntelliJ ACP setup.
  - The installer is `curl | sh`, so read `install.sh` first.
- **[Toolport](https://github.com/tsouth89/toolport)** (MIT core, 238★) is a local MCP gateway. You configure servers once and share them across Claude Code, Codex, Cursor and VS Code. Three features matter after this week's MCP OAuth-leak fixes:
  - It moves API keys from plain-text configs into the OS keychain.
  - It pins tool definitions and flags changed descriptions, including hidden instructions.
  - A "Strict" mode quarantines changed tools.

  I haven't verified these claims.
- **[cc-remote](https://github.com/AkaraChen/cc-remote)** (374★) runs the `claude` login, model and subagents on an ssh host, while Read, Edit, Bash and your local MCP servers run on your laptop. It's built on `claude-agent-acp`, so any ACP client can drive it.

## 8. 🎯 One thing to try today (≤30 min)
**Give Claude Code a source-level map of an Angular/NgRx app through Pangular's stdio MCP, read-only.**
1. In a scratch branch of your Angular repo:
   ```bash
   claude mcp add pangular -- npx -y @pangular-inspector/devtools mcp --root "$PWD" --read-only
   ```
   To see every option first, including the HTTP live-page variant, run `npx @pangular-inspector/devtools mcp --print-config`.
2. In `claude`, run `/mcp` and look at the tools it exposes. I haven't verified the tool list.
3. Ask: *"Using the pangular tools only, list every route, its lazy-loaded module/standalone component, and which NgRx feature selectors each routed component reads. Flag components that inject `Store` but use no selectors."*
4. Compare that with what Claude produces from plain Grep and Read on the same question: accuracy, tokens (`/usage`) and time.
5. If it wins, try the HTTP transport (`pangular-live`) with `ng serve` running, and ask why a specific reactive form is invalid.

**Success criteria:** decide whether a structural MCP beats grep for NgRx and route questions in your codebase. Remove it with `claude mcp remove pangular` if it doesn't. Pin a version before you share it in a team `.mcp.json`, because `npx` pulls unreviewed code.
