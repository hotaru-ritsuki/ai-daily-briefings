## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

**The Agent SDK credit pool reshapes how to architect daily Claude Code use.** Three concrete consequences before June 15:

- **Headless runs are now budgeted.** Anything via `claude -p` or the SDK draws from the same $100/$200 monthly bucket as the team's Claude Code GitHub Action. A Routine firing a dynamic workflow at midnight against `src/app/features/<X>/` (the Bun-style pattern from 05-30) is *exactly* the shape that lives here. The bucket is plenty for one or two of these a day; not plenty for "run this on every PR push." Right-size before June 15.
- **Interactive Claude Code is untouched** — keystrokes, slash commands, MCP tool calls in a live session stay on Max.
- **Third-party SDK wrappers are now a cost decision.** `claude-peers-mcp` (covered 05-30), Conductor, OpenClaw, and any custom `Anthropic SDK + agent` setup count as programmatic. The local migration-coordinator pattern still works, but the cost shifts pools.

**Playwright 1.56 ships official Test Agents (Planner/Generator/Healer) — overdue mention.** Planner explores the app and emits a Markdown plan, Generator turns plan → test files, Healer runs the suite and repairs failing tests against the live browser ([docs](https://playwright.dev/docs/test-agents), [TestDino guide](https://testdino.com/blog/playwright-test-agents)). For my stack: same fan-out shape as Anthropic's dynamic workflows but tied to the e2e suite, and Healer-against-live-browser is the missing piece for the Angular migration verification loop — port a component, run Healer to repair selectors against the new template, log diffs.
