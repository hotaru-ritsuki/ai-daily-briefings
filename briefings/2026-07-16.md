## 4. 🛠️ Claude Code & MCP ecosystem (deep dive)

**The MCP RC beta SDKs are the actionable story this week.** With the normative `2026-07-28` spec 12 days out, betas now exist for **Python v2, TypeScript v2, Go 1.7.0-pre.1, and C# 2.0.0-preview.1** ([announcement](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/)). Upgrading the SDK is deliberately decoupled from adopting the new revision, so the safe move is: pin the **exact** beta (unpinned installs stay on stable), point it at a real server, and check three things — (1) statelessness (no `initialize` handshake / session; you can round-robin load-balance now), (2) the **routable `Mcp-Method` / `Mcp-Name` headers** so a gateway routes without parsing the body, and (3) the **`-32602` vs `-32002`** error-code change for missing resources, which is the one likely to break existing client assumptions. New capability worth noting: **Multi-Round-Trip Requests (MRTR)** — a tool can now request user input mid-execution via `InputRequiredResult`, which changes how you'd design an interactive DB or migration tool. Existing servers keep working past Jul 28; this is a "test now, migrate deliberately" window, not a hard break.

On the community side, **browser + test-platform MCP servers are maturing past toys**: Apple shipped an official **Safari MCP server** (Jul 1, Safari Technology Preview 247 — 16 tools, the first from a major browser vendor) ([guide](https://www.developersdigest.tech/blog/safari-mcp-server-developer-guide-2026)), and **BrowserStack / Cypress / Maestro** now wire their actual grids into agents rather than exposing a generic browser ([TestGuild roundup](https://testguild.com/top-model-context-protocols-mcp/)) — relevant to pushing my Playwright E2E work into the agent loop.

## 8. 🎯 One thing to try today (≤30 min)

**Run one AngularJS→Angular component through a spec before the agent touches code.** Spec Kit turns "migrate this component" into an explicit, reviewable spec (intent, constraints, acceptance criteria) that the agent then implements — the antidote to a confident agent solving the wrong problem in a large migration.

```bash
uvx --from git+https://github.com/github/spec-kit.git specify init ng-migrate-spec --ai claude
cd ng-migrate-spec
claude    # then: /specify migrate the AngularJS <one component> to Angular 18 standalone + signals,
          # preserving public @Input/@Output contract and existing Playwright coverage
```

The point isn't the tool — it's noticing whether writing the spec surfaces contract/behavior questions you'd otherwise only catch in diff review. If it does, that's your signal to make spec-first the default for the migration. ([GitHub Blog](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/))
