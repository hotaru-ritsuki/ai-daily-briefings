### Claude Code ([changelog](https://code.claude.com/docs/en/changelog))

**v2.1.166 — June 6** (the substantive one of the week)
- 🆕 ⭐ **`fallbackModel` setting + `--fallback-model` for interactive sessions.** Configure up to three fallback models tried in order when the primary is overloaded or unavailable. Mid-session overload no longer kills a long-running migration run; you can pin a cheap fallback explicitly. ⭐ Direct fit for headless `claude -p` overnight migrations against the new Agent SDK credit pool (June 15) — set Opus 4.8 → Sonnet 4.6 → Haiku 4.5 and let cost degrade gracefully.
- 🆕 ⭐ **Glob patterns in deny-rule tool-name position** — `"*"` denies all tools; allow rules reject non-MCP globs; unknown tool names in deny rules now warn at startup. ⭐ First time you can write a default-deny policy as `{ "deny": ["*"], "allow": ["Read", "Grep", ...] }` instead of enumerating every tool name.
- 🆕 ⭐ **Cross-session `SendMessage` hardened — relayed messages no longer carry user authority.** Receivers refuse relayed permission requests; auto mode blocks them. ⭐ Real privilege-escalation class fix: pre-2.1.166 a child session could be talked into issuing a permission prompt that the orchestrator would silently auto-accept.
- 🆕 **`MAX_THINKING_TOKENS=0` and `--thinking disabled` actually disable thinking** on models that think by default via the Claude API (3P providers unchanged). Useful for cost ceilings on routine tasks.
- 🔧 ⭐ **Auto-retry on the configured fallback model** when the API returns an unexpected non-retryable error; auth, rate-limit, request-size, transport errors still surface immediately. Pairs with the fallback config above.
- 🔧 `claude update` announces the target version before downloading (no more silent updates).
- 🐛 Recurring "image could not be processed" error + extra token usage on unprocessable images — fixed.
- 🐛 Remote sessions getting permanently stuck on backend disruption during worker registration — fixed.
- 🐛 **JetBrains 2026.1+ terminal flickering** (IntelliJ, PyCharm, WebStorm) — fixed via synchronized output. ⭐ Direct fit since I'm on IntelliJ ACP.
- 🐛 Shift+non-ASCII (Shift+ä → Ä) dropped under Kitty keyboard protocol (WezTerm, Ghostty, kitty) — fixed.
- 🐛 PowerShell command validation occasionally hanging far past its time budget when a killed process's children held output pipes — fixed.
- 🐛 Orphaned `claude --bg-pty-host` spinning at 100% CPU after the macOS daemon dies — fixed.
- 🐛 Voice mode requiring `/login` to clear a stale auth check after `/voice` toggle — fixed.

## 4. 🛠️ Claude Code & MCP ecosystem (community, deep dive)

**v2.1.166's `SendMessage` hardening matters more than the changelog text suggests.** Pre-2.1.166, cross-session `SendMessage` was the mechanism that lets a Claude Code orchestrator talk to a `claude agents`-managed background session — and per the changelog, **relayed messages from other sessions were carrying the *receiving* user's authority**. In a worktree-per-subagent topology (Leonhardt-style two-file harness, covered 05-31), the orchestrator dispatching to N subagents is exactly the path that could let one compromised subagent issue a permission prompt the orchestrator silently auto-accepts. v2.1.166 closes that. If your orchestration setup uses `claude agents` heavily (as mine does for the migration), this fix is more important than the `fallbackModel` headline. Sweep audit pipeline: after upgrade, re-run an orchestrator dispatch in dry-run and confirm relayed permission requests now get refused rather than silently approved.

**Fallback-model config is also a cost-discipline tool, not just a reliability one.** With the June-15 Agent SDK credit pool live in 9 days, `fallbackModel: ["claude-opus-4-8", "claude-sonnet-4-6", "claude-haiku-4-5"]` becomes the cleanest way to put a soft ceiling on per-call cost without abandoning the high-tier model for cases that need it. The 06-02 `rightmodel` workshop pattern ([cwc-workshops](https://github.com/anthropics/cwc-workshops)) gives you the eval-sweep side; v2.1.166 gives you the runtime side. Pair them.

**Atlassian Rovo MCP Server is GA** ([Atlassian announcement](https://www.atlassian.com/blog/announcements/atlassian-rovo-mcp-ga), [Atlassian MCP](https://github.com/atlassian/atlassian-mcp-server)) — Atlassian-hosted MCP at `mcp.atlassian.com/v1/mcp/authv2` for Jira + Confluence + JSM, with semantic search and Confluence-page creation. **Important deprecation: the old `/v1/sse` endpoint stops working June 30, 2026** — update any existing `.mcp.json` that points at it. For our setup this is the cleanest single-source-of-truth for sprint context inside a Claude Code session, and the JSM tooling enables a real "agent reads the on-call alert, drafts the postmortem ticket" flow without leaving the editor. Bake-off candidate against the community [sooperset/mcp-atlassian](https://github.com/sooperset/mcp-atlassian) we'd nominally been using — Rovo's auth model and semantic-search tier should make it the default for the platform team.

**Anthropic Agent Skills (SKILL.md) is now formally an open standard inside the Agentic AI Foundation** ([New Stack background](https://thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards/), [Agensi explainer](https://www.agensi.io/learn/agent-skills-open-standard)) — Anthropic donated the spec; **146 AAIF member orgs as of Feb 2026**, including OpenAI, Microsoft, Block. ## 8. 🎯 One thing to try today (≤30 min)

**Wire up the new `fallbackModel` config and verify the `SendMessage` authority-boundary fix in one session.** Both are v2.1.166 changes; combined they pay back the most under the post-June-15 SDK credit-pool regime.

```bash
npm update -g @anthropic-ai/claude-code && claude --version   # expect 2.1.167

# 1. Configure tiered fallback in .claude/settings.json:
#    {
#      "fallbackModel": ["claude-opus-4-8", "claude-sonnet-4-6", "claude-haiku-4-5"]
#    }
#    Then verify it sticks:
claude config get fallbackModel

# 2. Confirm the SendMessage authority-boundary fix:
#    Start an orchestrator session that dispatches a subagent,
#    have the subagent issue a tool call that would require permission.
claude agents
# Then in another shell, simulate a relayed message; in pre-2.1.166 a
# permission prompt issued from the relayed message would inherit the
# *receiver's* approval. Post-2.1.166 it is refused.

# 3. Tighten one deny rule using the new glob support:
#    Add to .claude/settings.json "permissions.deny":
#      "*(Read(~/.ssh/**))"   # blocks all tools from reading SSH keys
#    Confirm it bites by asking Claude to read ~/.ssh/known_hosts.

# 4. Sanity-check the new managed-settings invalid-entry fix:
#    Drop a deliberately-invalid policy in .claude/managed-settings.json
#    and confirm the remaining valid policies still enforce.
```

If the deny rule didn't bite, the rule was previously silently disabled by an unrelated invalid entry (the v2.1.166 fix). If the `SendMessage` test surfaced a relayed permission auto-accept, you were previously running with the authority escalation. Either is a reason to upgrade today, not tomorrow.
