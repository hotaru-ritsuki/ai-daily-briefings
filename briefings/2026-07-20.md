## 4. 🛠️ Claude Code & MCP ecosystem (community)

**v2.1.215 quietly shifts the review burden back to you.** With `/code-review` and `/verify` no longer auto-firing, the deliberate move is to put an *explicit* review gate in the loop — which is exactly where two marketplace plugins earn their slot: **`code-simplifier`**, the cleanup-pass plugin Anthropic uses internally to strip duplication and clarify logic on modified code, and **`pr-review-toolkit`**, a bundle of specialized PR-review subagents ([plugin roundup](https://buildtolaunch.substack.com/p/best-claude-code-plugins-tested-review)). For a migration workflow: `code-simplifier` after an agent's first pass, `pr-review-toolkit` (or the MCP server in §5) as the adversarial gate before merge. This is the community-plumbing version of the Bun gate — the same "implementer, then reviewers whose only job is to find bugs" shape, wired into `.claude/`.

On the authoring side, **hub-and-spoke skill orchestration** — a coordinator skill that routes to specialist skills rather than one mega-prompt (see `simota/agent-skills`' "Nexus" model in §5) — is the config-layer answer to context bloat: each spoke gets fresh context, the hub keeps coordination state. It composes cleanly with the per-session subagent caps 07-17 covered: bounded fan-out, explicit routing, one review gate.

## 6. 📰 Articles & essays worth reading

### 6a. AI workflows & patterns

- **[Rewriting Bun in Rust](https://bun.com/blog/bun-in-rust)** — Jarred Sumner. The **primary-source** account behind 07-01's one-line mention: 535k lines of Zig ported in 11 days via ~50 dynamic Claude Code workflows (peak **64 concurrent agents**), with a **trial-on-3-files-then-fan-out** rollout and **two adversarial reviewer agents per implementer** whose only job was finding bugs, gated by a 1.38M-assertion suite. *The closest public analog to a large mechanical-but-risky migration — steal the gate design.* *~15 min.*
- **[The Pulse: What can we learn from Bun's rapid Rust rewrite with AI?](https://blog.pragmaticengineer.com/the-pulse-what-can-we-learn-from-buns-rapid-rust-rewrite-with-ai/)** — Gergely Orosz. The counterweight to the hype: what actually generalizes (a comprehensive test suite as the oracle, small trials before fan-out) versus what was Bun-specific. *Read alongside the primary source, not instead of it.* *~8 min.*
- **[A moratorium on AI-written change descriptions](https://simonwillison.net/2026/Jul/8/)** — Simon Willison. A sharp, small practice: he banned agent-written PR/commit messages because they described *what* the code does while omitting the *why* — the framing a human reviewer actually needs. *A one-line policy I could adopt this week.* *~3 min.*
- **[Claude Code Camp: The Workflows Turning One Engineer Into Ten](https://every.to/source-code/claude-code-camp)** — Every *(evergreen, not this week)*. The case for **subagents-as-roles**: each has its own context window, so the reviewer isn't biased by the executor's memory. *The conceptual backbone under the Bun gate and the `pr-review-toolkit` pattern (§4).* *~10 min.*

## 8. 🎯 One thing to try today (≤30 min)

**Build the Bun gate at micro-scale on one migration component — and make the review step explicit now that v2.1.215 won't run it for you.** Pick a single leaf AngularJS component on a scratch branch and give Claude Code this loop:

> "Migrate `<component>` to Angular 18. Implement it, then spawn two `/subtask` reviewer agents — one checking behavioral equivalence against the original, one checking adherence to our migration conventions — and a third subtask to apply only the fixes both reviewers agree on. Report disagreements to me."

That's the Bun playbook (implementer + 2 adversarial reviewers + fixer, §6a) compressed to one file. First command: `claude update && claude` on the branch, then paste the prompt.
